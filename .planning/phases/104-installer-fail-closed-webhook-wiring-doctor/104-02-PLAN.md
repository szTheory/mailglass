<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installer → adopter endpoint.ex (at install time) | The installer wires the webhook `body_reader`. An unmanaged `Plug.Parsers` ahead of the managed parser consumes the raw request body before Mailglass can verify webhook signatures — the production footgun this phase closes. |
| doctor → local source files (read-only) | The doctor performs a STATIC `File.read!` scan of `mix.exs` + `endpoint.ex`. No code execution, no `eval`, no `app.start` — no injection surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-104-03 | Spoofing | Webhook signature verification bypassed by a body-consuming unmanaged parser (silent prod 401 / unverified bodies) | mitigate | This IS the footgun the phase removes: `validate_preflight/1` now FAILS CLOSED (`Mix.raise`, non-zero exit) instead of warn-and-continue, so the adopter cannot ship the misconfiguration unknowingly. |
| T-104-04 | Tampering | `--force` becoming a silent bypass of the fail-closed gate | mitigate | `--force` is opt-in only and is explicitly documented in the fail-closed error message (D-03/D-06); the `--force` test asserts the managed block lands ABOVE the unmanaged parser (byte-index ordering), so even the escape hatch produces a correctly-wired result rather than a silent re-introduction of the 401 (Pitfall 4). |
| T-104-05 | Information disclosure / code execution | Doctor static scan reading or executing local source | accept | Read-only `File.read!` + `String.contains?` on local-project files the operator already owns; no eval, no network, no boot. No new disclosure surface beyond what the operator already has on disk. |
| T-104-SC | Tampering | npm/pip/cargo installs | accept | No package installs — pure stdlib + existing project modules (104-RESEARCH.md: no Package Legitimacy Audit needed). No `[ASSUMED]`/`[SUS]` packages. |

No HIGH-severity threats: this is an offline installer/mix-task phase with no network, DB, auth,
secrets, or untrusted-input surface. The net security effect is a REDUCTION in footgun risk.
</threat_model>
