    applies the GATE RULE below.

GATE RULE (the one rule; frontmatter, interfaces and behavior all point here):
  1. validate_verdict/2 every verdict. A reject whose only failures are evidence-quote substring misses is
     unverifiable and is DROPPED. Any other invalid verdict (schema, unknown key, a pass with a failed quote,
     a pass citing no rule, a non-reserved email) makes the gate red.
  2. After dropping, each scenario needs valid verdicts from >= 2 distinct judges; the first two in different
     A/B orders (after_only exempt). Fewer -> red (a replacement judge is spawned for a dropped reject).
  3. Zero valid rejects -> scenario passes. Exactly one valid reject -> passes only if a THIRD judge (not one of
     the first two) passed; otherwise the reject stands. Two or more valid rejects -> scenario rejected.
  4. Calibration: a known-bad with any valid pass -> red; the known-good must pass under rule 3.
  5. Zero scenarios -> red. The outcome does not depend on the order of the verdict list.
