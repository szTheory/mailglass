<objective>
Ship the `mix mailglass.upgrade.v2_schema` codemod (UPG-01) and its end-to-end proof against a 1.x `public` seed (UPG-04). The task is a plain `use Mix.Task` file-emitter that writes a Route B `MoveMailglassToSchema` migration into the adopter's `priv/repo/migrations/`. Purpose: adopters with mailglass tables already in `public` need a first-class, tested upgrade path to the 2.0 `mailglass` schema that leaves a moved DB indistinguishable from a fresh-installed one.
Output: the Mix task module + two `async: false` `:schema_isolation` tests (emitter unit test + migration-execution integration test).
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-136-01 | Tampering | generated trigger/function block drifts from fresh-install v01 DDL → moved DB silently differs from fresh DB | high | mitigate | Byte-parity transcription from v01.ex:136-159; test asserts exact `45A01` message + `SET search_path = ''` in the emitted body AND that 45A01 fires under the moved schema with no path pin |
| T-136-02 | Denial of Service | `ALTER TABLE … SET SCHEMA` takes ACCESS EXCLUSIVE; a long reader could stall the move indefinitely | medium | mitigate | Generated `up/0` opens with `SET LOCAL lock_timeout = '5s'` (fail-fast 55P03, retry); transactional wrapper kept (no `@disable_ddl_transaction` — else SET LOCAL no-ops, Pitfall 7); guide (Plan 02) documents the retry posture |

| T-136-04 | Elevation of Privilege | version-marker comment lost on move → `Mailglass.Migration.up` re-runs v01..v05 into the moved schema (data corruption) | high | mitigate | UPG-04 test asserts `obj_description` survives (read `current_version/0` dynamically); failure branch adds explicit `COMMENT ON TABLE` after the move |
| T-136-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package-manager installs in this plan (plain `Mix.Task`, no new deps — Decision 1 deliberately avoids Igniter) |
