<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Published Hex artifact -> consumer-install / journey | The jobs exercise the live published packages on a generated host; the guard asserts the install does not regress. |
| Job result -> milestone trust claim / issue #32 | The journey's green status is the evidence driving trust-claim acceptance; a false-green would mask a broken release. |
| Third-party action -> CI runner | Each `uses:` runs third-party code; `permissions: { contents: read, issues: write }` is the blast radius. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-07 | Repudiation/Tampering | False-green published journey (missing checkpoint) accepted as trust evidence | mitigate | `if-no-files-found: error` on the upload; full 5-stage journey required by the validator; `check_trust_runner_checkpoint.sh` enforces schema/stage-order/SHA (RESEARCH Pitfall 3, full-journey note). |
| T-60-08 | Tampering | hackney/finch silently reintroduced on a published install | mitigate | Three-signal guard after `mix mailglass.install` (config-false present, no uncommented Finch line, no hackney/finch in lock) — RESEARCH Pattern 3, Pitfall 4. |
| T-60-09 | Repudiation | Journey failure goes untracked | mitigate | `notify-on-failure` `needs:` extended to include `published-trust-journey` so its failure opens issue #32. |
| T-60-10 | Tampering | Compromised action tag runs in CI | mitigate | Reuse only existing SHA-pinned actions (RESEARCH Pitfall 5; CLAUDE.md). |
| T-60-11 | Information Disclosure | Secret leakage in new shell steps | mitigate | No secrets echoed; new steps read generated files only; `HEX_API_KEY` is not referenced (it lives in the hex-publish environment) — RESEARCH Security Domain. |
| T-60-SC | Tampering | npm/pip/cargo installs | n/a | No package-manager install in this plan; CI plumbing only. No `[ASSUMED]`/`[SUS]` packages. |
</threat_model>
