<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR/push event -> ci.yml job | Untrusted PR content triggers the lane; the lane runs first-party scripts only. |
| ci.yml job result -> gate-ci-green (publish gate) | A lane's conclusion gates publish; a false-green here would let a broken release ship. |
| Third-party action -> CI runner | Each `uses:` runs third-party code in CI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-03 | Repudiation/Tampering | False-green trust lane (skipped job) lets a broken release publish | mitigate | No `if:` and no `needs:` on the job (unconditional run); `gate-ci-green` ignores only `skipped`, so an always-run job blocks publish on red (RESEARCH Pitfall 1, Pattern 2). |
| T-60-04 | Tampering | Missing checkpoint silently passes the artifact upload | mitigate | `if-no-files-found: error` on the upload step (RESEARCH Pitfall 3). |
| T-60-05 | Tampering | Compromised action tag runs in CI | mitigate | Reuse only the existing SHA-pinned actions from `ci.yml`; add no tag-pinned action (RESEARCH Pitfall 5; CLAUDE.md SHA-pin rule). |
| T-60-06 | Tampering | Shell-meta injection via lock path in the Hex-first guard | mitigate | `check_clean_baseline_hex_only.sh` passes the lock path via env var; invoked with no untrusted interpolation into `run:` (RESEARCH Security Domain V5). |
| T-60-SC | Tampering | npm/pip/cargo installs | n/a | No package-manager install in this plan; CI plumbing only. No `[ASSUMED]`/`[SUS]` packages. |
</threat_model>
