# Phase 120 — UI Design Contract
## Deliveries surface redesign

> Visual and interaction contract for the Phase 120 Deliveries surface redesign
> (the v1.14 #2 biggest-impact surface; 119 → **120** → 121 → 122).
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> Source of truth for the design *system*: `brandbook/brand-book.md` and
> `mailglass_admin/assets/css/app.css`. This spec does NOT reinvent that system — it
> applies it precisely to the scoped Deliveries-branch changes (DELIV-01), inheriting the
> Phase 119 keystone contract (`119-UI-SPEC.md`) verbatim for tokens / typography / color /
> motion / a11y, and changing only **render conditions** of already-built primitives.
>
> **This is a surgical redesign of an existing surface, not a rebuild.** No-data vs no-match,
> `data_state`, responsive table↔card duality, null/long-value/masking/pagination are
> ALREADY implemented and tested in `deliveries_list.ex` — verify against the matrix, do
> not rebuild (D-09). The locked decisions D-01..D-13 in `120-CONTEXT.md` are binding
> constraints, not open questions.

## Interaction Contracts

The Deliveries branch resolves to exactly three top-level IA states. The discriminator is the
**existing** state, not a new flag (D-01):

- **genuine no-data** = `@deliveries == [] and not filters_active?(@filter_params)`
- **no-match-for-filters** = `@deliveries == [] and filters_active?(@filter_params)`
- **populated** = otherwise

`filters_active?/1` already exists (`operator_live.ex:684-687`); `deliveries_list.ex:68-99` already
branches on `@filters_active?` (emitting `operator-empty-truly` vs `operator-empty-filtered` +
reset). Phase 120 *gates rendering on this truth* — it invents no flag.

### DELIV-01a — Filters toolbar + "Open delivery" CTA gating (D-FILTERS-ON-EMPTY / D-02, D-03, D-04)

**Contract:**
1. Render the FILTERS card (`operator_live.ex:489-526`) and its `Open delivery` submit button
   (`:519`) **only in populated OR no-match** states.
2. **Withhold the entire FILTERS `<section data-testid="operator-filters">`** in genuine no-data —
   filters and an open-CTA can only ever act on an empty set; an enabled control over nothing is a
   least-surprise violation (STRESS-TEST C/E footgun: "disabled-looks-enabled" / "weird controls
   when nothing to act on").
3. In **no-match**, keep the toolbar so the operator retains the **`Clear filters`** escape
   (`:520-522`) AND the in-pane `operator-empty-reset` "Clear filters" button
   (`deliveries_list.ex:80-87`). Both reset affordances stay.
4. **Tenant-scope boundary (security-reviewer flag — DEFECT-REGISTER, D-04):** withholding the
   toolbar in no-data removes the only scope-widening vector. In no-match the prefilled
   single-tenant `tenant_id` stays scoped; `FiltersForm.fields` (`:510-516`) exposes only
   status / event / window — never a tenant-widening control. **Any change that lets the empty /
   no-data state widen tenant scope is a regression and MUST be rejected.**

**Gating seam:** introduce the no-data/no-match/populated discriminator at the
`operator_live.ex:488` else-branch (or a `case`/`cond` over `{@deliveries, filters_active?(...)}`)
that conditionally renders the FILTERS `<section>`. Do NOT push gating into `deliveries_list.ex`
(it already correctly renders the empty *pane*; the toolbar lives in `operator_live.ex`).

### DELIV-01b — Orientation strip becomes empty-pane-only (D-ORIENT-REDUNDANT / D-05, D-06, D-07, D-08)

**Contract:**
1. Render `<MailglassAdmin.Operator.Shell.orientation_strip surface={:deliveries} />` **ONLY in the
   genuine no-data pane** (alongside `operator-empty-truly`). This applies the Phase 119 D-07
   empty-pane-only pattern to Deliveries.
2. **Remove the strip from the detail column's `is_nil(@selected_delivery)` branch**
   (`operator_live.ex:581`), where it currently fires on every populated-but-unselected view (i.e.
   below a populated table — the D-ORIENT-REDUNDANT defect).
3. **Keep the "Select a delivery…" master-detail helper** (`operator-empty-detail`,
   `operator_live.ex:582-594`) for the populated-but-unselected case (D-06) — it is the correct
   column-fill affordance, NOT redundant orientation. Do not delete it.
4. **Orientation copy stays byte-frozen** (`shell.ex:405-414` `copy_for(:deliveries)` —
   heading "Deliveries" + the 3 symptom-first tips). Only its render *condition* changes (D-07,
   mirrors 119 D-10). Zero text edits.
5. **D-LABEL-TRIPLING resolves as a side-effect** (D-08): removing the strip from populated views
   drops the third "Deliveries" heading, leaving the **nav item + page `<h1>`** as the two
   canonical instances. No separate edit.

**Placement of the no-data strip (Claude's discretion — least-surprise, Apple-deliberate):**
- In genuine no-data, render a **single calm onboarding pane**: the `operator-empty-truly`
  `Components.data_state` (icon + "No deliveries" + "No deliveries have been recorded yet.")
  followed by the orientation strip as a quiet "what to do when sends start arriving" teach-block.
- One pane, one vertical rhythm. Do NOT stack filters + empty + helper + strip (the old info-dump).
- No new copy, no "what gets recorded here" hint block — the frozen empty-state body + the frozen
  3-tip strip already teach the next step (D-12). Reusing what ships is the least-surprise choice
  and keeps the mobile (375/320) scroll short.

### DELIV-01c — Matrix states route through existing capabilities (D-09)

**Contract — verify, do not rebuild:**
- **error / permission-denied / stale** route through the existing `deliveries_list.ex` `data_state`
  capability (`:37-67`, kinds `:empty | :error | :permission_denied | :stale`) and the existing
  detail-column `@detail_error` branch (`operator_live.ex:568-579`). Building net-new error /
  permission-denied UI would duplicate a tested primitive and diverge from the locked `data_state`
  voice tests.
- **responsive** (table ≥768 / cards <768, 320→wide), **long-ID/UUID/module-name/non-ASCII
  truncation** (`truncate`+`title`, `mono`), **null handling** (`format_datetime(nil) → "Pending"`),
  **high-count**, **recipient masking** (`mask_recipient`), **pagination** (de-emphasized when
  `total_pages <= 1`) are all already implemented in `deliveries_list.ex`. **Verify against the
  matrix, do not rebuild.**
- The full state matrix (happy / empty / no-match / loading / error / permission-denied / boundary /
  disconnected-reconnect) and viewport×theme matrix (320/375/768/1024/1440/wide ×
  light/dark/system) is a **verification + re-shoot** exercise, not new UI.

### Master-detail column order at breakpoints (Claude's discretion — inherit 119, least-surprise)

- **Populated-unselected:** single column (`grid-cols-1`); the list card fills width; the detail
  column renders the "Select a delivery…" helper (`md:block`, hidden on mobile via existing
  `hidden … md:block`). The detail column carries `is_nil(@selected_delivery) && "order-first
  md:order-none"` (existing) — on mobile nothing detail-side shows, so order is moot; preserve as-is.
- **Populated-selected:** two-column `md:grid-cols-[40%_60%]` → `min-[1440px]:!grid-cols-[33%_67%]`
  (existing). On mobile the list hides (`max-md:hidden`) and the detail takes over with a
  `Back to deliveries` control (existing). Preserve verbatim — least-surprise, already correct.
- **Resolution:** inherit the 119 master-detail patterns; make NO structural change to the grid
  template — the redesign is the empty-state gating + strip relocation, not a layout rewrite.

## Motion Contract

**Principle:** Reuse existing motion tokens ONLY. No new keyframes. No new motion CSS (D-11 / 119
D-11 / v1.13 MOTION locks). Transform/opacity only; instant under reduced-motion.

| Element | Motion | Token/class |
|---------|--------|-------------|
| Delivery row selection (hover/active) | Color transition | `transition-colors` (existing row classes) |
| Selected detail panel (mount) | Reveal | `.motion-reveal` (opacity + translateY, existing on `#delivery-detail-*`, `operator_live.ex:599`) |
| Selected detail panel (remove) | Fade/slide out | existing `phx-remove` `JS.hide(... ease-out duration-150 ...)` (`:600-605`) |
| Filter selects / buttons | Color/border transition | `transition-colors ease-out duration-(--duration-fast)` (existing) |
| Empty / no-data pane appearance | none required | `data_state` panes are token-clean; the orientation strip is "born token-clean" (no motion). |

**Reduced-motion:** `@media (prefers-reduced-motion: reduce)` already neutralizes all `.motion-*`
classes to instant. This phase adds NO motion CSS, so compliance is inherited.

**Forbidden in this phase:** new `@keyframes`; `height`/`width`/`padding` transitions; `ease-in`;
`scale(0)`; JS animation hooks; any bespoke motion CSS (protects v1.13 MOTION + TokenParity locks).
