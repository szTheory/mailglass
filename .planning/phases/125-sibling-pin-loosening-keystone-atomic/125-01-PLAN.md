<objective>
Replace both sibling `{:mailglass, "== X.Y.Z"}` exact pins with pessimistic `~>` constraints and relax
every gate that enforced exact equality — as ONE indivisible change. After this phase a core **patch**
release no longer drags a paired sibling release (the exact-pin dance the 1.10.2 ceremony hit). This is
the milestone keystone: it unblocks every future release.

Purpose: Kill the exact-pin release dance (PIN-01..05). The `==` pin forced the inbound re-pin to land
direct-to-main as a transient-RED SHA every core bump, because `stability_contract_test` required
pin == core@version while core only bumps inside the release PR. Loosening to `~>` and relaxing the
gates to "admits core @version, rejects ==" makes a bare main SHA GREEN with an unchanged core @version.

Output: Two loosened pins, relaxed contract-test + publish.check gates, the two `== X.Y.Z` sed rewrites
deleted from release-please.yml (with all three dead sed-anchor gates retired), CHANGELOG entries in all
three packages, and a documented `mix hex.retire` rollback lever.

**Atomicity is load-bearing (LD-3).** Every task below lands in ONE wave and is committed as ONE coherent
change. Splitting any part reds main or miscuts the next release — e.g. after the sed deletion the
sed-anchor exit-1 guard would match zero `==` lines, and the old `==`-asserting contract/config tests
would fail against the new `~>` pin. Do NOT partial-commit.
</objective>
