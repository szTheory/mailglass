## Deviations from Plan

### Auto-flagged Deviations (Rule 4 — surfaced for user awareness, no architectural change made)

**1. [Rule 4 candidate] `mix mailglass.publish.check --package mailglass_inbound` exits 1 by structural design after Commit A**

- **Found during:** Task 3 validation
- **What:** The plan's Task 3 acceptance criterion expects `mix mailglass.publish.check --package mailglass_inbound` to exit 0. In practice, the task's `verify_metadata` step strictly requires `manifest_version == mix.exs @version`, and its `verify_linked_constraint` step strictly requires `mailglass dep "== X" where X == root_version`.
- **Why it conflicts:** Task 1 mandates the bootstrap state — manifest at `"0.0.0"`, `@version` at `"0.1.0"`, root `mix.exs` still at `"0.3.2"` — exactly the state these checks reject. The mismatch is the *defining property* of the bootstrap edit: the manifest holds a sentinel value that release-please consumes to compute the next version. There is no plausible Commit-A state where both checks pass simultaneously without first running release-please end-to-end.
- **Where the check IS expected to pass:** On the **release-please PR head ref** during workflow-dispatch dry-run (D-44.5-04 step 3), where the manifest reads `{".": "1.0.0", "mailglass_admin": "1.0.0", "mailglass_inbound": "0.1.0"}` and root `@version` reads `"1.0.0"` — that is the post-PR-open state, not the post-Commit-A state.
- **Action taken:** **No code change to publish.check** (would be a Rule 4 architectural change — adding a `--bootstrap` mode is non-trivial and out of Plan 044.5-01 scope). The proposed Conventional Commit message is surfaced as-is. The user should be aware that running `mix mailglass.publish.check --package mailglass_inbound` locally between Commit A landing and the release-please PR opening will report `[conflict] check mix metadata`. This is intentional per D-44.5-01.
- **Recommended for the user:** Either (a) accept the local-only `[conflict]` as a documented bootstrap-period quirk, or (b) consider adding a `--bootstrap` flag to `mix mailglass.publish.check` in a follow-up plan that allows `manifest_version == "0.0.0"` to bypass the equality assertion for first-publish packages. Option (b) is appropriate scope for Phase 51 (closeout) or a small follow-up after Plan 04.

**2. [Pre-existing — out of scope] `mix mailglass.docs.check` exits 1 due to inbound docs drift**

- **Found during:** Task 3 validation
- **Stale tokens:** 5 issues in `mailglass_inbound/README.md`, `mailglass_inbound/docs/api_stability.md`, `mailglass_inbound/docs/sendgrid_ingress.md` — none of which are in this plan's `<files>` list.
- **Confirmed pre-existing:** Reproduced at parent commit `b5b39d7c` (the phase plan creation commit, before any of this plan's edits). Failure is unrelated to the 5 files this plan modifies.
- **Action taken:** None. Per executor scope-boundary rules, pre-existing failures in unrelated files are out of scope. Logged for Plan 03 (which curates inbound docs as part of Commit C) and for the deferred-items log.
- **Cascading effect:** `mix verify.stability_contract` exits 2 because its alias chain hits `mailglass.docs.check` and chain-fails before reaching the final `compile --no-optional-deps --warnings-as-errors` step. The first three steps of the chain pass (core support contract, admin support contract, inbound docs contract test).
