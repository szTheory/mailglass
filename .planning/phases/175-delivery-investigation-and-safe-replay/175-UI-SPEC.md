## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Delivery: “Review webhook replay”; Inbound: “Review inbound replay”; confirm: “Confirm replay” |
| Delivery empty — filters active | Heading: “No deliveries”; body: “No deliveries match the current filters.”; action: “Clear filters” |
| Delivery empty — no history | Heading: “No deliveries in this time window”; body: “No deliveries have been recorded for this Account during the selected time window.”; action: none |
| Delivery empty — requested page | Heading: “No deliveries on this page”; body: “Move to an available page to inspect the current results.”; action: use available pagination |
| Suppression empty | “No current Mailglass suppression matches this delivery.” Keep the existing Refresh action. |
| Error state | Refresh: “Couldn’t refresh suppression evidence. Try again.” Stale review: “Eligibility changed. Review the current request again.” Command failure: “Replay couldn’t be completed. Review current eligibility before trying again.” Denial: “Replay isn’t allowed for your account. Ask an Account administrator to review access.” |
| Destructive confirmation | None. Suppression stays read-only; replay has an explicit confirmation dialog. |

Keep copy short, direct, and actionable. A missing expiry is “Expiry date not recorded.” Never say “Never expires.” Explain removal policy in plain language: “Mailglass allows removal of [reason] suppressions” or “Mailglass does not allow removal of [reason] suppressions.” Do not add a removal button.

## Interaction and visual contract

- Delivery status and primary facts are the screen’s visual anchor. Keep technical evidence, suppression, and replay as secondary, clearly grouped sections. Show grouped technical evidence open by default below primary facts in full Delivery and full Inbound detail. Keep labels and values distinct; technical identifiers use the mono face and wrap without clipping.
- Keep suppression evidence in its existing stable Delivery card. Refresh stays next to the evidence state/action. Show ready match, ready empty, stale retained match, and unavailable with no prior fact as distinct states. On a failed refresh, label retained data stale and identify that the read failed; do not present it as current or as an empty-ready result. Keep Account scope explicit.
- Offer replay review from either quick view and full detail for the exact selected record. Preserve Account, filters, selection, and route context on close and return. An unavailable outbound replay shows its reason in place and has no enabled replay CTA. A reviewable ambiguous target may open review to select among that exact target set.
- Use one concise, responsive dialog shell for Delivery and Inbound. Keep stored webhook identity distinct from the recorded Mailbox identity. State the consequence plainly: outbound reprocesses the stored webhook request and does not resend mail; Inbound uses the recorded Mailbox and does not redeliver through the provider or reevaluate current router rules. Display only existing bounded projections; do not expose raw payloads, provider bodies, exception details, or new sensitive fields.
- The visible X close control has accessible name “Close.” Escape closes. Keep keyboard focus inside the open dialog and return it to the exact originating quick-view or full-detail trigger. Every action target is at least 44px; retain a visible focus ring and role=dialog/aria-modal semantics.
- Keep stale, denied, and failed replay feedback visible inside the open dialog in a live region. Keep the dialog mounted to avoid flash/flicker. After command failure, offer “Review again” to load fresh eligibility before another confirmation; retain the existing action-time check. Provide an explicit fresh-review path for stale state and explain that denied operators can re-review after access changes. Never leave an unexplained disabled confirm action or a dead end.
- On permitted success, close the dialog and announce an accessible toast. Outbound copy reports the actual result: new Events recorded or no change. Inbound copy names the recorded Mailbox run outcome; do not claim a new provider delivery or invent an Event. Refresh visible evidence from the command result.
- Keep existing restrained overlay/toast motion (opacity/settle only, at most 300ms, ease-out); exits are faster than entries. Respect the existing reduced-motion rule and never animate layout dimensions.
