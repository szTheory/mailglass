# Phase 110 - UI Design Contract

> Visual and interaction contract for Phase 110: Primitives. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - in-house Phoenix.Component + Tailwind v4 standalone + daisyUI 5 token system |
| Preset | not applicable |
| Component library | Phoenix.Component function components; daisyUI semantic utilities; no Radix/Base UI/shadcn |
| Icon library | Vendored Heroicons via `mailglass_admin/assets/vendor/heroicons-inline.js` and `<Components.icon name="hero-*">` |
| Font | Inter for UI/body, Inter Tight for headings/display, IBM Plex Mono for code/IDs |

Source notes: `components.json` is absent, this is not a React/Next/Vite stack, and Phase 110 must not initialize shadcn. Existing tokens live in `mailglass_admin/assets/css/app.css`; color remains in the daisyUI theme blocks only. Registry safety is therefore not applicable.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, segmented-control internal gaps, compact icon/text pairs |
| sm | 8px | Nav item gaps, chip padding, button/icon gaps |
| md | 16px | Default component padding, gallery cell padding, stat-card padding floor |
| lg | 24px | Component group spacing inside gallery sections |
| xl | 32px | Major primitive specimen groups |
| 2xl | 48px | Large section breaks only |
| 3xl | 64px | Page-level gallery spacing only |

Exceptions: no visual-spacing exceptions. Control-size tokens are allowed because they are multiples of 4 and already exist: `--size-control-sm: 36px`, `--size-control-md: 44px`, `--size-control-lg: 52px`. Normal interactive primitives default to the 44x44 comfort floor through `min-h-11` plus a width floor where the control can collapse. WCAG 2.2 AA 24x24 dense-control exceptions are allowed only if explicitly GAP-recorded with the applicable SC 2.5.8 exception; Phase 110 should plan for zero dense exceptions.

Phase 110 contract: primitive extraction must preserve the existing token scale. No arbitrary spacing such as `p-[14px]`, `gap-1.5`, raw pixel style attributes, or dynamic class construction is allowed for these primitives.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 700 | 1.5 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.2 |

Only weights 400 and 700 are permitted. `font-medium` and `font-semibold` remain banned because the loaded font files do not provide 500/600. Primitives must use `text-label`, `text-body`, `text-heading`, or `text-display`; raw Tailwind type utilities are violations.

Primitive typography rules:

| Primitive | Type Contract |
|-----------|---------------|
| `nav_link` | `text-body`; active state uses `font-bold`, inactive state uses default weight |
| `nav_pill` | `text-body`; active state uses `font-bold`, inactive state uses default weight |
| `tenant_chip` | `text-label`; tenant value uses `font-bold` and mono treatment for IDs |
| `theme_picker` | `text-label` or `text-body` consistently across all three options; selected state may use `font-bold` |
| `stat_card` | label `text-label`; value `text-display` for large cards or `text-heading` for compact cards; severity label `text-label` |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light: Paper `#F8FBFD` via `--color-base-100`; Dark/System-dark: Ink `#0D1B2A` via `--color-base-100` | Page background and primitive specimen backgrounds |
| Secondary (30%) | Light: White `#FFFFFF` / Mist-edge `#C7DCE5` via `--color-base-200/300`; Dark: Ink-raised `#152538` / Ink-edge `#315069` via `--color-base-200/300` | Cards, sidebar/nav surfaces, chip borders, stat-card containers |
| Accent (10%) | Light: Glass `#277B96`; Dark/System-dark: Ice `#A6EAF2` via `--color-primary` / `--color-accent` | Current nav/picker state, primary CTA only if one is required, visible focus ring |
| Destructive | Light: Crimson `#B42318`; Dark: Crimson-bright `#E29089` via `--color-error` | Destructive actions and error severity only |

Accent reserved for: `aria-current="page"` indicators, checked theme-picker segment, selected/active primitive state, `.btn-primary` when a real primary action exists, and `:focus-visible`. Accent is not a general hover color, decorative card border, empty-state illustration color, or default icon color.

Status/severity color contract: `success`, `warning`, `error`, and `info` are semantic status colors only. `stat_card` severity must use icon + label + color together; color alone is never sufficient. Meaningful status icons must reach non-text contrast requirements when they are needed to understand the state.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Set theme` if an explicit submit/action is required; otherwise the `Theme` radio group applies `System`, `Light`, or `Dark` directly with no separate CTA |
| Empty state heading | `No data yet` for empty `stat_card`; `No tenant selected` remains the `tenant_chip` no-tenant label until Phase 112 replaces the shell flow |
| Empty state body | `This value will appear after Mailglass records events for the selected tenant.` Use only where the primitive has room for body copy; compact stat cards may omit body copy but must not render bare `-`, `--`, or `___` after data has resolved |
| Error state | `Metric unavailable: check the source data and try again.` For component-contract failures, use test/gate output that names the primitive and missing assign/icon |
| Destructive confirmation | none - Phase 110 introduces no destructive action and must not add a new destructive confirmation pattern |

Copy restrictions: "Oops", "Whoops", "Uh oh", and "Something went wrong" remain banned. Labels must be domain-specific and direct: `System`, `Light`, `Dark`, `Deliveries`, `Inbound`, `Tenant currently in view`, `All clear`, `Unavailable`, `No data yet`.

## Primitive Contracts

| Primitive | Required Shape | States To Render | A11y Contract |
|-----------|----------------|------------------|---------------|
| `nav_link` | Link with icon + visible label, left border active cue, token spacing, `min-h-11` | active/current, inactive, hover-ready, focus-visible, disabled/not-available if applicable, long label | `aria-current="page"` only when current; icon decorative because label carries meaning; disabled link must remove navigation and expose `aria-disabled="true"` |
| `nav_pill` | Compact link with visible label and non-color selected cue | active/current, inactive, hover-ready, focus-visible, disabled/not-available if applicable, long label | `aria-current="page"` only when current; selected state cannot rely on color alone |
| `tenant_chip` | Read-only inline status chip with building icon + tenant text | with tenant, no tenant, long tenant ID, non-ASCII tenant, null tenant | Not a selector in Phase 110; icon decorative; chip label remains visible text; long values truncate with `title`/tooltip and never overflow |
| `theme_picker` | Three-option radio group styled as segmented control: `System`, `Light`, `Dark` | system selected, light selected, dark selected, disabled option/group if applicable, focus-visible, long localized labels if added later | Prefer native radios inside `fieldset`/`legend`; custom markup must use `role="radiogroup"`, child `role="radio"`, and `aria-checked`; do not use three independent `aria-pressed` buttons |
| `stat_card` | Bordered flat card with label, no-wrap tabular value, severity icon + label + color | neutral, info, success, warning, error, empty/no-data, unavailable/error, long label, long value | Label truncates with tooltip/title; value uses `tabular-nums` and `whitespace-nowrap`; severity icon is decorative only when adjacent label exists |

Component names and attrs may be chosen by the planner, but the public API must be explicit enough for tests to render every state directly with `render_component/2`.

## Theme Picker Contract

The picker is one selection among exactly three choices:

| Choice | Label | Value Contract | Visual Contract |
|--------|-------|----------------|-----------------|
| System | `System` | selected value `:system`; emits no explicit theme value downstream | selected segment has accent cue + non-color cue |
| Light | `Light` | selected value `:light`; may map to explicit light path/event value | selected segment has accent cue + non-color cue |
| Dark | `Dark` | selected value `:dark`; may map to explicit dark path/event value | selected segment has accent cue + non-color cue |

Interaction contract:

- Each option has a visible label. Icons are optional and never the only label.
- Each option has a 44x44 minimum target in the compiled bundle. If an icon-only compact treatment is used, it must also have `min-w-11` and an accessible name.
- Native radio behavior is preferred. If custom roles are used, keyboard behavior must match the WAI-ARIA APG radio group pattern: `Tab` enters/leaves, `Space` checks, arrow keys move and check within the group.
- The selected option is exposed programmatically (`checked`, `aria-checked`, or equivalent), not only through CSS.
- The primitive does not own host-scoped persistence, cookies, local storage, root theme resolution, or no-FOUC first paint.

## Stat Card Contract

Required shape:

| Element | Contract |
|---------|----------|
| Container | `rounded-box border border-base-300 bg-base-200` or equivalent semantic token surface; no heavy shadow; no nested card inside card |
| Label | `text-label font-bold text-secondary`; single line; truncate with `title` containing the full label |
| Value | `font-mono` or tabular numeric treatment; `tabular-nums whitespace-nowrap`; must not wrap at 320px |
| Severity | Closed semantic set: `:neutral`, `:info`, `:success`, `:warning`, `:error`; each state renders icon + visible label + semantic color |
| Placeholder | Use meaningful words such as `No data yet`, `All clear`, or `Unavailable`; no bare dash placeholders after runtime data has resolved |
| Long content | Long labels truncate with tooltip/title; long values use compact formatting, truncation+title, or horizontal containment without page overflow |

Stat-card consumers in Phase 110: operator overview and inbound overview must migrate to `Components.stat_card/1`; page-local `defp stat/1` copies and ad hoc overview stat card markup must be removed or fail the STATCARD gate.

## Icon Contract

| Rule | Contract |
|------|----------|
| Inventory | Every `hero-*` name referenced in admin `lib/**/*.ex` must exist in `mailglass_admin/assets/vendor/heroicons-inline.js` before the bundle is considered valid |
| Meaning | Icons are decorative (`aria-hidden="true"`) when adjacent text carries meaning; icon-only controls require `aria-label` and 44x44 target proof |
| Color | Meaningful icons use semantic token colors and must not be the only carrier of severity or status |
| Size | Decorative inline icons default to 16px or 20px on the 4px grid; icon-only controls use the control target size, not icon size, for pointer target proof |

The icon-exists guard should be deterministic and repo-local. A Node parser or ExUnit parser is acceptable; it must compare all used `hero-*` names against the vendored icon map and fail with the missing names.

## State And Gallery Contract

The dev gallery must certify the real public components, not copies.

| Requirement | Contract |
|-------------|----------|
| Real component rendering | `GalleryLive` renders `Components.nav_link`, `Components.nav_pill`, `Components.tenant_chip`, `Components.theme_picker`, and `Components.stat_card` directly. |
| Stable test IDs | Preserve `data-testid="gallery-{component}-{state}"`; add states rather than renaming existing anchors unless tests are updated in the same plan. |
| Theme coverage | Each named primitive state renders in light, dark, and system. System specimens must omit explicit `data-theme`; do not fake system with `data-theme="system"`. |
| Viewport coverage | Structural tests cover 320px through wide widths for the named primitives, with special proof for stat-card overflow/no-wrap and segmented picker target size. |
| Interaction states | At minimum: hover-ready class, focus-visible ring, active/current/checked, disabled, loading where applicable, selected, error/unavailable, empty/no-data, and long-content. |
| Disabled distinction | Disabled controls must be programmatically disabled (`disabled` or `aria-disabled` with removed action) and visually distinct without looking like an enabled hover/active state. |

## Accessibility Contract

| Area | Contract |
|------|----------|
| Target size | Normal controls are >=44x44 in the compiled bundle. WCAG 2.2 AA minimum is >=24x24 only for explicitly documented dense exceptions; none are expected in Phase 110. |
| Focus | Use the shared `mg-focus-ring`/`mg-focus-ring-inset` contract from Phase 109: 2px outline, token accent color, visible in light/dark/system, not obscured. |
| Non-text contrast | Required state indicators, borders that identify controls, focus indicators, meaningful icons, and selected cues meet 3:1 non-text contrast against adjacent colors. |
| Text contrast | Primitive text meets WCAG AA against the surfaces it appears on. Disabled controls remain visibly disabled; inactive disabled controls are not treated as active contrast obligations. |
| Keyboard | All interactive primitives are reachable and operable by keyboard. The radio group follows native radio/APG keyboard behavior. |
| Semantics | Use real links for navigation, buttons/radios for controls, and read-only text/chip semantics for `tenant_chip`. Do not model non-actions as buttons. |

External standards verified on 2026-06-18: W3C WAI-ARIA APG Radio Group Pattern; WCAG 2.2 Understanding SC 2.5.8 Target Size Minimum; WCAG 2.2 Understanding SC 2.4.13 Focus Appearance; WCAG 2.2 Understanding SC 1.4.11 Non-text Contrast.

## Gate Contracts

Phase 110 gates are additive and must prove green before the phase is complete.

| Gate | Required Delta |
|------|----------------|
| PRIMITIVE-DRIFT-GATE | Fail on private/inlined definitions or gallery copies for `nav_link`, `nav_pill`, `tenant_chip`, `theme_toggle`/`theme_picker`, and page-local `stat` helpers after public extraction. Allow exactly one implementation in `MailglassAdmin.Components`. |
| STATCARD-GATE | Fail when operator/inbound overview stat/KPI markup bypasses `Components.stat_card/1` or when bare dash placeholders remain for resolved stat values. Pair grep with component/structural assertions. |
| ICON-EXISTS-GATE | Fail if any `hero-*` name used in admin `lib/**/*.ex` is absent from `heroicons-inline.js`. |
| TARGET-SIZE proof | Extend Playwright structural tests to assert target dimensions for `nav_link`, `nav_pill`, `theme_picker` options, icon-only controls, and disabled controls in the compiled bundle. |
| GALLERY real-component proof | Assert gallery primitive cells render public component output across light/dark/system and that the old copied HEEx paths do not remain. |
| STATCARD overflow proof | At 320px, labels truncate with tooltip/title, values remain no-wrap/tabular, and the card does not cause page overflow. |

Verification commands should reuse existing lanes: `bash mailglass_admin/scripts/check-conformance.sh`, focused `mix test` for component/shell contracts, and `cd mailglass_admin && npm run test:operator-browser` for rendered structural proof.
