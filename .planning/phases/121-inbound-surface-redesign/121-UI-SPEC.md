# Phase 121 — UI Design Contract
## Inbound surface redesign

> Visual and interaction contract for the Phase 121 Inbound surface redesign
> (the v1.14 #3 biggest-impact surface; 119 → 120 → **121** → 122).
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> Source of truth for the design *system*: `brandbook/brand-book.md`,
> `brandbook/copy/microcopy.md`, and `mailglass_admin/assets/css/app.css`. This spec does NOT
> reinvent that system — it applies it precisely to the scoped Inbound-branch changes (INB-01),
> **mirroring the shipped Phase 120 Deliveries contract (`120-UI-SPEC.md`) verbatim** for tokens /
> typography / color / motion / a11y, and changing only **render conditions** of already-built
> primitives — PLUS three justified in-scope a11y/correctness fixes (dormant `data_state` wiring,
> reveal-disclosure ARIA + re-redact, replay-modal Tab-trap + double-submit lock on BOTH surfaces).
>
> **This is a surgical redesign of an existing surface, not a rebuild.** No-data vs no-match,
> `data_state`, responsive table↔card duality, null/long-value/masking/pagination are ALREADY
> implemented and tested in `inbound/records_list.ex` — verify against the matrix, do not rebuild
> (D-09). The reveal three-state machine and the replay modal are already correct; this phase adds
> bounded a11y semantics, not new behavior. The locked decisions D-01..D-18 in `121-CONTEXT.md` are
> binding constraints, not open questions. **Preserve the PII/raw-payload-default-hidden boundary
> and the replay safety contract — these are hard guardrails, not negotiable design surface.**

## Interaction Contracts

The Inbound branch resolves to exactly three top-level IA states. The discriminator is the
**existing** `empty_state_for/2` truth, not a new flag (D-01):

- **genuine no-data** = `@records == [] and not filters_active?(@filter_params) and @filter_errors == %{}`
  (the `empty_state_for/2` `:truly_empty` case, `inbound_live.ex:659-670`)
- **no-match-for-filters** = `@records == []` AND (`filters_active?` true OR
  `tenant_has_inbound_history?` true) → the `:filtered` case
- **populated** = otherwise

Keep the `@filter_errors == %{}` guard so an in-flight invalid filter is NOT misclassified as
no-data (the 120 trap at `operator_live.ex:490`). Wrap the `else` branch (`inbound_live.ex:382-533`)
in a top-level `cond`, mirroring the shipped Deliveries shape (`operator_live.ex:489-522`). Phase
121 *gates rendering on this truth* — it invents no flag.

### INB-01a — Filters toolbar + "Open record" CTA + health-strip gating (D-02, D-03, D-05)

**Contract:**
1. Render the FILTERS card (`inbound_live.ex:383-419`), its `Open record` submit
   (`:412`), AND the **health strip** (`Inbound.Overview.overview`, `:421-426`) **only in populated
   OR no-match** states.
2. **Withhold the entire FILTERS `data-testid="inbound-filters"` section, the `Open record` CTA, the
   health strip, AND the entire master-detail grid** (incl. the "Select an InboundMessage…" helper
   and the replay-modal seam) in genuine no-data. Filters and an open-CTA can only act on an empty
   set; a wall of zero stat-cards over an empty surface is the canonical info-dump the
   STRESS-TEST-PROMPT bans.
3. In **no-match**, keep the toolbar so the operator retains the **`Clear filters`** escape (`:413`,
   the `inbound-empty-reset` path) AND the in-pane `inbound-empty-filtered` reset. Keep the health
   strip and the master-detail grid.
4. **Tenant-scope boundary (security-reviewer flag — D-05, mirror of 120 D-04):** withholding the
   FILTERS card in genuine no-data removes the only scope-widening vector; `FiltersForm.fields`
   exposes only outcome / window — never a tenant-widening control; `:no_tenant`
   (`inbound-empty-no-tenant`) is handled entirely upstream by the `tenant_selector`
   (`inbound_live.ex:376-381`). **Any change that lets the empty / no-data state widen tenant scope
   is a regression and MUST be rejected.**

**Gating seam:** introduce the no-data/no-match/populated `cond` at the `inbound_live.ex:382`
else-branch. Do NOT push gating into `records_list.ex` (it already correctly renders the empty
*pane*; the toolbar/health-strip/grid live in `inbound_live.ex`). Note: `tenant_has_inbound_history?`
(`:687-702`) runs an extra full-window list query ONLY when `@records == []` — acceptable; ensure
the no-data port does NOT trigger it on populated views.

### INB-01b — Orientation strip becomes empty-pane-only (D-04, D-06, D-08)

**Contract:**
1. Render `<Shell.orientation_strip surface={:inbound} />` (testid `inbound-orientation`) **ONLY in
   the genuine no-data pane** (alongside `inbound-empty-truly`). This applies the Phase 119 / 120
   empty-pane-only pattern to Inbound.
2. **Remove the strip from the detail column's `is_nil(@detail)` branch** (`inbound_live.ex:483`),
   where it currently fires on every populated-but-unselected view (below a populated table — the
   same redundant-orientation / label-tripling defect 120 fixed).
3. **Keep the "Select an InboundMessage to inspect its Mailbox routing…" master-detail helper**
   (`inbound-empty-detail`, `inbound_live.ex:484-491`) for the populated-but-unselected case (D-04)
   — it is the correct column-fill affordance, NOT redundant orientation. Do not delete it.
4. **Orientation copy stays byte-frozen** (`shell.ex:416-425` `:inbound` copy) — only its render
   *condition* changes (D-08, mirrors 119 D-10 / 120 D-07). Zero text edits.
5. **D-LABEL-TRIPLING resolves as a side-effect:** removing the strip from populated views drops the
   third "Inbound" heading, leaving the **nav item + page `<h1>`** as the two canonical instances.

**Placement of the no-data strip (Claude's discretion — least-surprise, structural parity with
Deliveries):**
- In genuine no-data, render a **single calm pane**: the `inbound-empty-truly` `records_list`
  empty pane ("No InboundMessages" + "No InboundMessages have been recorded yet." — D-07 copy fix)
  followed by the orientation strip as a quiet teach-block.
- One pane, one vertical rhythm. Do NOT stack filters + health strip + empty + helper + strip (the
  old info-dump — Inbound is literally the as-built "before" picture).
- The no-data body MAY adopt the brandbook InboundMessage empty-state next-step line ("point your
  provider's inbound webhook here") delivered via **existing microcopy as copy, NOT new structure**
  (D-specifics). Default to least-surprise / structural parity with Deliveries. No new copy block,
  no new component.

### INB-01c — Matrix states route through existing capabilities + wire the dormant `data_state` (D-09)

**Contract — wire the dead code, then verify, do not rebuild:**
- **Wire the dormant `data_state` (latent bug-fix):** `records_list.ex` supports `data_state`
  (`records_list.ex:43-73`: error / permission_denied / stale / empty) but `inbound_live.ex` **never
  passes it** — the four states are dead code on this surface. Pass it (mirror 120 D-09) so
  **error / permission-denied / stale / disconnected** route through the existing primitive + the
  existing `inbound-detail-error` branch (`inbound_live.ex:470-481`). Building net-new error /
  permission-denied UI would duplicate a tested primitive and diverge from the locked `data_state`
  voice tests.
- **responsive** (table ≥768 `inbound-records-table` / cards <768 `inbound-records-cards`, 320→wide),
  **long-ID/UUID/module-name/non-ASCII truncation** (`truncate`+`title`, `mono`), **null handling**
  (`format_datetime(nil) → "Pending"`), **high-count**, **recipient masking** (`mask_recipient`),
  **pagination** (`inbound-pagination`, de-emphasized when `total_pages <= 1`) are all already
  implemented in `records_list.ex`. **Verify against the matrix, do not rebuild.**
- The full state matrix (happy / empty / no-match / loading / error / permission-denied / boundary /
  disconnected-reconnect) and viewport×theme matrix (320/375/768/1024/1440/wide ×
  light/dark/system) is a **verification + re-shoot** exercise, not new UI.

### INB-01d — Detail-column forensic density is legitimate, NOT info-dump (D-06)

Once an InboundMessage is selected, DetailHeader → Timeline → RoutingTrace (`:no_match` only) →
EvidenceCard → replay render at full density. This is **selection-gated, progressively-disclosed
forensic detail** (the inbound JTBD: "why did this InboundMessage route the way it did?"), and the
streamlined gate governs ONLY the empty/no-data state. Keep RoutingTrace gated to `:no_match` so it
is signal, not noise. Do NOT thin or restructure the selected-detail subtree.

### INB-01e — PII / raw-payload reveal: preserve invariants + bounded disclosure a11y (D-10, D-11, D-12)

**Hard guardrails (D-10 — do NOT weaken):**
- `reveal_state` defaults `:redacted` (`inbound_live.ex:100`) and re-sets to `:redacted` on every
  selection and clear (`:565`/`:584`) — non-sticky across views; whole-payload only;
  capability-gated via `authorize_reveal/1` over `Auth.authorize(adapter, :reveal_raw, …)`
  (`:944-951`), fail-closed on nil/non-atom adapter. No new auth surface, no new reveal *trigger*,
  no default-on. The IA refactor MUST NOT hoist evidence rendering outside the per-selection reset.
- The locked boundary test (`structural.spec.js:1176-1177`: `inbound-evidence-redacted` visible +
  `inbound-evidence-raw` count 0 on first selection) must **NOT** be weakened.

**Bounded reveal-UX a11y polish (within the locked `:reveal_raw` contract — D-11):**
- Make the reveal control (`evidence_card.ex:42-49`, testid `inbound-evidence-reveal`) a true ARIA
  **disclosure button**: `aria-expanded` false→true on grant, `aria-controls="inbound-evidence-raw"`,
  `mg-focus-ring`, `min-h-11` (already present). Keep `type="button"`.
- Announce the state change via a NEW `aria-live="polite"` `role="status"` region (planner's call
  on exact placement within `evidence_card.ex` — D-discretion) — **never the warning border color
  alone** (WCAG 1.4.1).
- Add a **"Re-redact raw source"** collapse control in the `:revealed` state, routing back to
  `:redacted` via **one new `handle_event` — NO fourth state atom** — and returning focus to the
  reveal button. `min-h-11`, `mg-focus-ring`, `type="button"`.
- Reveal button copy: **"Reveal raw source"** (unchanged) + secondary **"Contains unredacted PII."**
  Keep the exemplary denied copy verbatim.

**PII-free reveal audit (telemetry, not storage — D-12):**
- Emit `[:mailglass_admin, :inbound, :reveal_raw, :stop]` with metadata `tenant_id` / `record_id` /
  `:outcome ∈ :granted | :denied` ONLY — **never payload / body / headers / recipient** (CLAUDE.md
  telemetry PII rule). Durable persisted reveal-audit is deferred (Phase 123+).

### INB-01f — Replay (consequential action): keep modal weight + close two APG gaps on BOTH surfaces (D-13, D-14)

**Keep the full-modal confirmation weight — do NOT downgrade (D-13):** replay is
consequential-but-non-destructive (appends an immutable replay run to the append-only ledger; "Undo"
would be a lie). The modal that names the recipient + states the ledger consequence delivers the
"boring instead of terrifying" calm. Preserve the gate order **TENANT → CAPABILITY
(`:replay_inbound`) → REPLAY** (`inbound_live.ex:274-322`), the `:no_match`-can-never-replay rule,
and the struct-matched error copy (CLAUDE.md rule 7) — all unchanged.

**Close two genuine APG gaps, applied IDENTICALLY to BOTH replay modals (D-14)** —
`inbound/replay_modal.ex` + `operator/replay_modal.ex`, for cross-surface coherence:
1. **Tab / Shift+Tab focus-trap** (wrap last→first / first→last) via LiveView.JS focus sentinels or
   a scoped Tab keydown handler. `JS.focus_first` already sets initial focus but does NOT contain
   Tab — this is the one APG line item currently unmet.
2. **Double-submit pending-lock** on Confirm (`inbound-replay-confirm`, `replay_modal.ex:63-69`):
   `phx-disable-with` / `JS.set_attribute(disabled)` + a calm pending label **"Replaying…"** —
   prevents the render→click double-fire.

Everything else the modal already does right (`role="dialog"`, `aria-modal`, `aria-labelledby`,
Escape via `phx-key`, initial focus, focus-restore to trigger, scrim/overscroll, reduced-motion
neutralizer) is **already APG-conformant and e2e-asserted — do NOT regress.** Background-content
`inert`/`aria-hidden` modality and the `btn-error`-vs-consequential-color question are **deferred**
(Phase 123+).

**Focus-trap implementation (Claude's discretion):** LiveView.JS focus-sentinel spans vs. a scoped
Tab keydown handler — pick the least-surprise, smallest-correct-JS option; both are pure
Phoenix/LiveView.JS, no new npm deps. **Keep both surfaces' modals in lockstep.**

### Master-detail column order at breakpoints (inherit 120, least-surprise)

- **Populated-unselected:** single column; list card fills width; detail column renders the "Select
  an InboundMessage…" helper (`md:block`, hidden on mobile). Preserve the existing grid template.
- **Populated-selected:** two-column `md:grid-cols-[40%_60%]` → `min-[1440px]:!grid-cols-[33%_67%]`.
  On mobile the list hides and the detail takes over with a `Back to inbound` control
  (`inbound-detail-back`). Preserve verbatim — least-surprise, already correct.
- **Resolution:** make NO structural change to the grid template — the redesign is the empty-state
  gating + strip relocation + a11y polish, not a layout rewrite.

## Motion Contract

**Principle:** Reuse existing motion tokens ONLY. No new keyframes. No new motion CSS (D-18 / 120
