**Mailgun guide source of truth:**
  mailglass_inbound/lib/mailglass_inbound/ingress/providers/mailgun.ex
    - verify!/2 signs HMAC-SHA256 over `timestamp <> token` (flat form fields, NOT nested JSON)
    - Signature triple: params["timestamp"], params["token"], params["signature"]
    - Default tolerance: 300 seconds; default future_skew: 60 seconds
    - replay_cache_ttl_seconds: 28_800 (8 hours)
    - MailgunReplayCache.check_and_put: {:replay} returns 200 no-op (not 401)
    - Two normalize modes: body-mime field present → raw-MIME, absent → parsed

  mailglass_inbound/lib/mailglass_inbound/ingress/plug.ex (lines 464-471)
    - Config keys: `config :mailglass_inbound, :mailgun, signing_key: "..."`
    - Optional: timestamp_tolerance_seconds, future_skew_seconds, replay_cache_ttl_seconds

  mailglass_inbound/docs/postmark_ingress.md (style reference for provider guides)
    - Mount path, Plug.Parsers wiring, config section, persistence semantics sections

**SES guide source of truth:**
  mailglass_inbound/lib/mailglass_inbound/ingress/providers/ses.ex
    - verify!: SNS X.509 via core Mailglass.Webhook.Providers.SES.verify_envelope!/2
    - Three message types: Notification (persists), SubscriptionConfirmation (auto-confirms),
      UnsubscribeConfirmation (handled)
    - confirm_control_plane!/1: validates SubscribeURL via TrustPolicy then follows it
    - S3 fetch: MailglassInbound.S3Fetcher.ExAwsS3 (real) or S3Fetcher.Fake (test default)
    - S3 retry: 3 attempts, [250, 1000, 2000]ms backoff (default)
    - KMS caveat: client-side KMS NOT decrypted; use bucket-level SSE

  mailglass_inbound/lib/mailglass_inbound/ingress/plug.ex (lines 476-493)
    - SES config keys: s3_fetcher, cert_cache_ttl_seconds, s3_retry_opts
    - Default s3_fetcher is nil → resolves to Fake (test-only!)

  lib/mailglass/webhook/providers/ses/trust_policy.ex
    - valid_cert_url?: pattern ^sns\.[a-zA-Z0-9\-]{3,}\.amazonaws\.com(\.cn)?$
    - valid_subscribe_url?: same pattern
    - TrustPolicy is HARDCODED — no adopter-configurable allowlist

  mailglass_inbound/lib/mailglass_inbound/s3_fetcher.ex (behaviour interface)
  mailglass_inbound/lib/mailglass_inbound/s3_fetcher/ex_aws_s3.ex (real implementation)
  mailglass_inbound/lib/mailglass_inbound/optional_deps.ex (OptionalDeps.ExAwsS3 gateway)

    - CachingBodyReader wiring is required (reference install guide)

    **Section: Mailgun Route Setup**
    - In the Mailgun dashboard: Receiving → Routes → Create Route

    - Action: Forward to `https://your-app.example.com/inbound/:tenant_id/mailgun`

    - Optional knobs: timestamp_tolerance_seconds, future_skew_seconds, replay_cache_ttl_seconds

    **Section: Signing Key Rotation**
    - Update `signing_key` in config, redeploy — no downtime during rotation
    - Mailgun's 5-minute tolerance window means the old key continues to verify requests
      that were in-flight during rotation

    **Section: Verification**
    - HMAC-SHA256 over `timestamp <> token` (flat form fields, not nested JSON)
    - 5-minute (300s) timestamp tolerance window (configurable)
    - Replay protection: same token is rejected as a 200 no-op (not a 401 — providers retry on non-200)

    **Section: Two Payload Modes**
    - When Mailgun sends raw MIME (`body-mime` field present): parsed by MailglassInbound.MIME
    - When Mailgun sends parsed fields (default): normalized from body-plain/body-html/stripped-*
    - No adopter action required — the plug detects the mode automatically

    **Section: Persistence Semantics**
    - Same as Postmark/SendGrid: one canonical InboundRecord + one InboundEvidence row
    - Replay returns a 200 no-op (no second InboundRecord created)

  <behavior>
    The SES guide is the longest and highest-stakes doc in Phase 50. Covers:

    **Section: Overview**
    - SES Inbound (via SNS + S3) vs. SES sending-events webhooks (different service)
    - The flow: SES Receipt Rules → SNS topic → HTTPS subscription → mailglass endpoint + S3 body fetch

    **Section: Mount Path**
    - `forward "/inbound/:tenant_id/ses", MailglassInbound.Ingress.Plug, provider: :ses, router: MyApp.MailglassInboundRouter`
    - CachingBodyReader wiring is required (reference install guide)

    **Section: SNS Topic Setup**
    - Create an SNS topic (type: Standard, NOT FIFO)
    - Create an HTTPS subscription to `https://your-app.example.com/inbound/:tenant_id/ses`
    - SubscriptionConfirmation: mailglass auto-confirms it (no adopter action needed) when the
      SubscribeURL is from `sns.*.amazonaws.com` (validated by the hardcoded TrustPolicy)

    **Section: IAM Policy**
    - The SES receipt rule needs an IAM role that allows `s3:GetObject` on the bucket
    - Provide a complete, copy-pasteable IAM policy JSON:
      ```json
      {
        "Version": "2012-10-17",
        "Statement": [
          {
            "Effect": "Allow",
            "Action": ["s3:GetObject"],
            "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"
          }
        ]
      }
      ```
    - This must be attached to the IAM role used by the SES receipt rule action

    **Section: SES Receipt Rule Setup**
    - SES Console → Email Receiving → Rule Sets → Create Rule
    - Condition: recipient address pattern(s)
    - Action 1: S3 — store in YOUR-BUCKET-NAME with a key prefix (e.g. `inbound/`)
    - Action 2: SNS — publish notification to your SNS topic ARN
    - The SNS notification contains the S3 object key for mailglass to fetch

    **Section: Optional Deps Install**
    - Add to mix.exs deps:
      ```elixir
      {:ex_aws, "~> 2.7"},
      {:ex_aws_s3, "~> 2.5"},
      {:sweet_xml, "~> 0.7"},
      {:hackney, "~> 1.20"}  # or {:req, "~> 0.5"} / {:finch, "~> 0.19"} — any ex_aws-compatible HTTP client
      ```
    - Set up AWS credentials (environment variables or instance role — ex_aws standard)

    **Section: Configuration**
    - Required in production: `config :mailglass_inbound, :ses, s3_fetcher: MailglassInbound.S3Fetcher.ExAwsS3`
    - The default s3_fetcher is nil which resolves to the Fake (test-only!) — MUST be set in production
    - Optional: cert_cache_ttl_seconds, s3_retry_opts

    **Section: SubscribeURL Trust Policy**
    - SubscribeURL is validated against a hardcoded pattern: `sns.*.amazonaws.com`
    - No adopter-configurable allowlist needed
    - Forged SubscribeURLs that don't match this pattern are rejected without following the URL

    **Section: S3 Consistency**
    - SNS can deliver before S3 is read-after-write consistent
    - mailglass retries up to 3 times (250ms, 1000ms, 2000ms) before returning a structured error
    - Configurable via s3_retry_opts if needed

    **Section: KMS Limitation**
    - Client-side KMS-encrypted S3 objects are NOT decrypted by mailglass
    - Use bucket-level SSE (Server-Side Encryption) instead — SSE-S3 or SSE-KMS with bucket policy
    - Client-side KMS ciphertext parses as a degraded record (never a crash), but the body will be unusable

    **Section: Testing in Development**
    - In test/dev, the default `S3Fetcher.Fake` is used — no real S3 calls
    - Use `MailglassInbound.Fixtures.build_ses_sns_payload/1` to build test payloads
