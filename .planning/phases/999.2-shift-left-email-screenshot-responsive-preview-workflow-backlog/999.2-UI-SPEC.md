## Screen And Interaction Notes

- Workflow entry points are maintainer-facing only: `mix` task output and LiveView preview tooling surface; no new public runtime API in `mailglass` core.
- Primary visual focal point is the `Capture preview screenshots` action paired with the active matrix row state so maintainers can immediately identify "what will run next."
- Visual hierarchy is fixed: `1.` capture trigger + active matrix selection, `2.` capture progress/manifests panel, `3.` artifact list and metadata details.
- Capture matrix dimensions are fixed in v1: scenario (`preview_props/0`) x width (`375`, `768`, `1024`) x theme (`light`, `dark`).
- Render truth source is the existing `/dev/mail` preview path (`PreviewLive`); no alternate renderer is introduced.
- Artifact output contract is deterministic: stable filename ordering, stable manifest ordering, and explicit metadata for scenario/width/theme.
- Claim boundary copy is mandatory in UI/help text: "Chromium preview-pipeline confidence only; does not claim cross-client parity."
- CI visualization remains advisory in this phase; UI language must avoid implying required branch-protection gating.

## Accessibility Notes

- All matrix controls and capture actions are keyboard reachable with visible focus styles on both light and dark themes.
- Interactive controls meet 44px minimum target size and 4.5:1 contrast for text on actionable surfaces.
- Capture progress and failure states expose text equivalents (not color-only signaling).
- Error and empty states provide explicit next action text, not generic failure language.
