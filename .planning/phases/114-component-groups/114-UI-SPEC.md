# Phase 114 — UI Design Contract

> Visual and interaction contract for the Component Groups phase.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> This phase is a **fractal design-system uplift** of three composed component groups in
> `mailglass_admin` — not new product capability. All design decisions inherit from the locked
> dossiers established in Phases 109-113. Requirements: GROUP-01 (coherent spacing/hierarchy,
> next action obvious), GROUP-02 (nesting depth ≤2, breathing room), GROUP-03 (x/y grid
> alignment at narrow and wide widths).

## Spacing Scale

The 4px-grid semantic token scale is already defined in `app.css` `@theme` (lines 110-116) and
aliased as Tailwind utilities (`p-xs`, `p-sm`, `p-md`, `p-lg`, `p-xl`, `p-2xl`, `p-3xl`).
Phase 114 **enforces** this scale across the 8 group surfaces via a new SPACE-GATE grep gate —
banning raw numeric spacing literals (`p-6`, `mt-1`, `space-y-1`, `gap-2`, etc.) in those files.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`--spacing-xs`) | Icon gaps, inline margins |
| sm | 8px (`--spacing-sm`) | Tight element separation (e.g. label-to-value gap) |
| md | 16px (`--spacing-md`) | Default element padding, inter-section gap |
| lg | 24px (`--spacing-lg`) | Card outer padding (the `p-lg` shell variant) |
| xl | 32px (`--spacing-xl`) | Layout-level gaps where applicable |
| 2xl | 48px (`--spacing-2xl`) | Major section breaks (not expected in group surfaces) |
| 3xl | 64px (`--spacing-3xl`) | Page-level spacing (not used in group surfaces) |

**Inter-card rhythm:** The `space-y-4` (16px) vertical rhythm between group cards in the
detail column is owned by `operator_live.ex` / `inbound_live.ex` and is NOT swept by
the SPACE-GATE (it is a live-view composition knob, not a group-module literal).

**Exceptions:** The `<.card>` shell primitive exposes exactly two padding variants: `:md`
(16px) for compact group cards and `:lg` (24px) for primary group cards. No other
padding values are permitted inside the shell primitive itself.

## Typography

All type sizes, weights, and line-heights are defined in `app.css` `@theme` (lines 118-126)
and as `:root` font-family variables (lines 193-195). **Only 2 weights are loaded (400/700)**;
weights 500 and 600 are deliberately not loaded (app.css line 104 comment).

| Role | Size | Weight | Line Height | Font | Usage in this phase |
|------|------|--------|-------------|------|---------------------|
| Label | 12px (`--text-label`) | 400 (regular) | 1.5 | Inter | Status labels, tier-2 row labels, metadata |
| Body | 14px (`--text-body`) | 400 (regular) | 1.5 | Inter | Card body copy, detail text, timeline descriptions |
| Heading | 20px (`--text-heading`) | 700 (bold) | 1.2 | Inter | Card section headings (GROUP-01 visual hierarchy) |
| Display | 28px (`--text-display`) | 700 (bold) | 1.2 | Inter Tight | `support_cards.ex` Tier-1 status-colored count — the F-pattern anchor that makes "next action obvious" (D-06) |

**Weight rule:** `text-display font-bold` is the emphasis carrier in `support_cards.ex` Tier-1
insets (D-06) — the status-colored count (e.g. "3 failures") must use display size at weight 700.
All other group surface text uses body/label at weight 400, or heading at weight 700 for
section titles. **No weight 500 or 600 anywhere.**

**Mono:** IBM Plex Mono (400) is used for UUIDs, message IDs, and routing keys in
`evidence_card.ex` / `routing_trace.ex`. Not a new decision — already present.

## Color

The color system uses DaisyUI semantic tokens resolving to the mailglass brand palette
(defined in `brandbook/tokens.css`, aliased via `--mg-color-*` custom properties). No
raw hex literals appear in HEEx templates or CSS — TOKEN-01 rule.

### Surface Hierarchy (the single Phase 114 elevation rule — D-04)

| Surface | Token | Light value | Dark value | Usage |
|---------|-------|-------------|------------|-------|
| Page ground (sunken) | `bg-base-100` | `#F8FBFD` (Paper) | `#0D1B2A` (Ink) | Page background; NOT used inside group cards |
| Raised card (outer group) | `bg-base-200` | `#FFFFFF` (White) | `#152538` (Ink-raised) | Every group card's outermost shell (`<.card>`) |
| Sunken inset (inner content) | `bg-base-100` | `#F8FBFD` (Paper) | `#0D1B2A` (Ink) | Nested content inside a card (Tier-1 insets in `support_cards`, timeline event cards, routing wells) |
| Border | `border-base-300` | `#C7DCE5` (Mist-edge) | `#315069` (Ink-edge) | Outer card border; never on inner insets (borderless) |

**The box-prison fix (D-05):** `support_cards.ex` inner `<article>` cards at lines 38, 84,
130 currently use `bg-base-200 border border-base-300 rounded-box` — same tone as the outer
card (box prison). They MUST be demoted to borderless `bg-base-100` sunken insets. The outer
`<section>` gains `shadow-raised`.

**Elevation:**

| Token | Value | Usage |
|-------|-------|-------|
| `shadow-flat` | `none` | Default surface (no decoration) |
| `shadow-raised` | `0 1px 2px 0 rgb(13 27 42 / 0.06)` | Outer composed group only (the one place that needs lift) |
| `shadow-overlay` | `0 8px 24px -8px rgb(13 27 42 / 0.18)` | Modals/popovers — NOT used in this phase |

### Semantic Color Roles (60 / 30 / 10 split)

| Role | % | Tokens | Usage |
|------|----|--------|-------|
| Dominant (60%) | 60% | `bg-base-100` (page), `bg-base-200` (card surface) | Background + card surfaces — the vast majority of the group UI |
| Secondary (30%) | 30% | `bg-base-100` insets, `border-base-300`, `text-secondary` (`#5C6B7A` Slate / `#B8CAD4` Mist-soft) | Inner insets, borders, muted metadata labels |
| Accent (10%) | 10% | `text-primary` (`Glass #277B96` light / `Ice #A6EAF2` dark), `btn-primary` | Reserved exclusively for: primary CTA buttons (`btn btn-primary`), focus rings, the status-colored count in Tier-1 insets |

**Accent reserved for (explicit list):**
- `btn btn-primary` — the one primary action button per Tier-1 `support_cards` inset (D-06)
- `ring-primary` — focus ring on interactive elements (inherited from Phase 109 token)
- Status-colored count text in `support_cards.ex` Tier-1 insets where the status IS the primary action anchor

### Semantic (status) colors — second semantic set (used in status encoding)

These are NOT accent — they carry severity meaning for GROUP-01 "next action obvious."
Status is ALWAYS encoded as icon + label + color (never color alone — WCAG 1.4.1).

| Status | Token | Light | Dark |
|--------|-------|-------|------|
| Error / failure | `text-error` / `border-error` | `#B42318` (Crimson) | `#E29089` (Crimson-bright) |
| Warning | `text-warning` / `border-warning` | `#A95F10` (Amber) | `#E0A955` (Amber-bright) |
| Success | `text-success` | `#166534` (Pine) | `#8BB77F` (Pine-bright) |
| Info | `text-info` | `#1D637A` (Glass-deep) | `#A6EAF2` (Ice) |

**Optional status left-rule (D-06 discretion):** A `border-l-4 border-error` or
`border-l-4 border-warning` left-edge rule may be applied to the failure/orphan Tier-1
insets in `support_cards.ex` — always paired with the status-colored count text and label
text. If added, the left-rule adds severity scanability but is never the sole status carrier.
Decision at execution time: add it if visual hierarchy holds at 320px; skip it if it creates
crowding at narrow width.

## Copywriting Contract

Phase 114 is a structural/spacing/elevation uplift — it does not introduce new surfaces,
flows, or user-visible text. The copywriting contract below covers the interactive elements
and states within the three composed groups that are being restructured.

**Inherited copy from Phase 113 data-state contract** (do not change these):

| Surface | Element | Copy |
|---------|---------|------|
| `support_cards` — no failures | Tier-1 count | "0" with label e.g. "Delivery failures" |
| `support_cards` — failures exist | Tier-1 count | The numeric count (e.g. "3") + label + `btn btn-primary` CTA |
| `support_cards` primary CTA | Button label | Use the existing domain verb + noun: e.g. "View deliveries", "Manage suppressions" — keep whatever the current labels are; this phase does not change copy |
| `routing_trace` | No match state | "No match" (already in STATUS-BADGE pattern, locked Phase 113) |
| `evidence_card` — redacted | Card heading | "Redacted" (locked evidence state from Phase 99) |
| `evidence_card` — denied | Card heading | "Denied" (locked evidence state from Phase 99) |
| All detail headers | Error state heading | "[Noun] not found" or existing error heading — do not change |
| Timeline | Empty state | "No events recorded" (or existing copy — do not change) |

**Phase 114 specific copy rules:**

| Element | Copy | Rule |
|---------|------|------|
| Status-colored count (Tier-1 inset anchor) | Numeric value only (e.g. "3") — the label beside it carries the semantic ("Delivery failures") | Count is the F-pattern anchor; label is the descriptor. Neither alone; always together. |
| Tier-2 borderless divider row label | Existing labels — do not change | Phase 114 changes elevation/spacing, not text |
| `data-region` / `data-group-card` attributes | `data-region` on detail-column wrapper; `data-group-card` on each group's outermost shell | These are testid-style attributes, not visible copy |

**"Oops" ban:** Inherited from COPY-LD-01/Phase 96. Any error copy in the group surfaces
must follow the pattern "[Noun] [past-tense verb]: [specific cause]" — never "Oops",
never vague messages. Enforced by the existing `voice_test.exs` banned-words gate.

**No new destructive actions in this phase.** The existing replay confirmation modal
(operator `support_cards`) is already locked from Phases 99/111. No new confirmation
dialogs are introduced.

## Interaction Contract

### Touch Targets

All interactive elements inherit the Phase 110 target-size contract:
- Primary buttons (`btn btn-primary`): `min-h-11` (44px floor) — inherited, do not reduce
- Secondary / ghost buttons: `min-h-11` minimum — inherited
- No new interactive controls are introduced by this phase

### Focus Rings

`ring-primary` (Glass #277B96 light / Ice #A6EAF2 dark) on all interactive elements —
inherited from Phase 109 `--mg-color-focus-ring` token. No changes in this phase.

### Motion

No new motion is introduced. Existing `motion-reveal` class on the detail-column wrapper
(`operator_live.ex:564` / `inbound_live.ex:476`) is preserved unchanged. Phase 114 does
not add, remove, or modify any animation or transition rule.

### Data Attributes (proof substrate)

| Attribute | Element | Purpose |
|-----------|---------|---------|
| `data-region` | Detail-column wrapper div (in live views + gallery specimens) | Scopes the Floki ancestor-depth ExUnit assertion |
| `data-group-card` | Each group module's outermost shell element | Scopes the Playwright sibling-x equality assertion to direct siblings only |

These attributes are structural test instrumentation, not user-visible. They are added
at call sites (via `@rest` on `<.card>`) rather than baked into the primitive.
