<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| release event/tag → protected workflow | Untrusted or duplicate event data must pass tag, package, and release-SHA CI predicates before publication. |
| protected workflow → Hex | `HEX_API_KEY` crosses only inside the `hex-publish` environment and actual publish steps. |
| Hex packages → clean consumer | Registry metadata and dependency constraints must resolve the exact released package set. |

## ASVS L1 Release Gate

ASVS L1 applies at these primary boundaries: V4 Access Control is covered by protected refs, the `hex-publish` environment, and step-local credentials; V5 Input Validation is covered by tag/package predicates and contract-tested event conditions. Every critical/high threat is dispositioned `mitigate`. High-severity findings are blocking: any unresolved high-severity finding stops this plan and all release progression.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-148-01 | Tampering | publish-inbound release eligibility | high | mitigate | Contract-test that release events cannot select inbound and that admin has no inbound prerequisite (D-01, D-02). |
| T-148-02 | Information Disclosure / Elevation | publish job secret scope | high | mitigate | Preserve protected refs, `hex-publish`, successful prerequisite checks, and step-local `HEX_API_KEY` (D-03). |
| T-148-03 | Denial of Service / Tampering | linked tag concurrency | high | mitigate | Preserve the static group and `cancel-in-progress: false`; retain package idempotency guards. |
| T-148-04 | Denial of Service | release SHA with no ci.yml run | high | mitigate | Preserve gate-ci-green self-dispatch/recovery and assert the gate remains a publish prerequisite. |
| T-148-05 | Spoofing | local proof presented as published proof | medium | mitigate | Keep separate pending path-mode and Hex-mode evidence in the ledger (D-07). |
</threat_model>
