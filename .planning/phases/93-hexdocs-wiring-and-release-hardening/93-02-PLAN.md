<objective>
Harden the release pipeline so it can never again cut a release from commits touching only
brand/planning paths. Adopt BOTH mechanisms from research (VERDICT: belt-and-suspenders):
(a) the PRIMARY enforced CI commit-type lint as a new dedicated required workflow, and
(b) exclude-paths on the root . package as silent defense-in-depth.

Purpose: the 1.6.x accidental-release train fired twice (a brandbook feat: bumped core 1.6.0;
a fix(inbound): bumped core 1.6.2) because the root . package claims commits in EVERY path.
RELH-01 closes that gap. The lint fails loudly at PR time; exclude-paths skips the bump
silently at parse time. Neither alone is trusted.

Output: exclude-paths added to the root . config; a new guard-release-trigger.yml workflow;
an offline fixture test proving the five edge cases. Implements RELH-01.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author to release pipeline | A PR title + changed-file set crosses into release-please's bump decision on squash-merge. The guard sits at this boundary. |
| GITHUB_TOKEN to workflow | The guard reads PR title + files; it needs no write and no secrets. pull_request (not pull_request_target) keeps fork PRs in the low-privilege context. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-93-04 | Tampering | A bump-triggering PR slips a version bump past the guard via a non-conventional title (defers to pr-title.yml) | mitigate | pr-title.yml (pull_request_target, always fires) blocks non-conventional titles, so the only way to merge is a conventional title, which the guard then classifies. The two checks compose: title-validity (pr-title) + bump-vs-paths (guard). Edge-case 5 in the fixture test asserts the guard correctly defers rather than double-failing. |
| T-93-05 | Tampering | Path-prefix evasion (e.g., brandbook-evil/ matching brandbook/ prefix loosely, or a guarded path nested under a non-guarded one) | mitigate | The subset test uses the trailing-slash forms ("brandbook/" etc.) so prefix matching is anchored to the directory boundary; the FAIL only triggers when ALL files are guarded, so any single real-code file makes it PASS (a real release is intended). The fixture test's mixed case (case 1) proves a single lib/ file flips to PASS. |
| T-93-06 | Elevation of Privilege | Workflow token over-scoped, exposing secrets to fork PRs | mitigate | Plain pull_request trigger (not pull_request_target) with permissions pull-requests: read + contents: read only; no secrets used beyond the default GITHUB_TOKEN read scope. Acceptance criteria assert the trigger and least-privilege permissions. |
| T-93-07 | Repudiation | exclude-paths silently misbehaves (action-version regression) and no release is cut when one was intended | accept | exclude-paths is SECONDARY and only ever suppresses bumps for commits confined to unowned paths (no legitimate release lost). The loud required CI lint is primary; together they are belt-and-suspenders (research A1: low risk). |
| T-93-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this plan; only a JSON config edit, a YAML workflow using preinstalled gh + SHA-pinned actions/checkout, and a bash fixture test. No new dependency introduced. |
</threat_model>
