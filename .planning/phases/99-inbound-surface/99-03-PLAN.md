<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Routing trace data -&gt; rendered HTML | Matcher reflection contains route facts and message actuals that may include PII. |
| Evidence model -&gt; rendered HTML | Stored raw provider payload and headers are sensitive and must remain redacted by default. |
| Operator click -&gt; reveal state | Reveal request crosses the existing authorization seam in InboundLive. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-99-11 | Information Disclosure | `RoutingTrace.decorate/2` | mitigate | Preserve `Components.mask_recipient(actual)` for recipient actuals and add tests refuting raw recipient output. |
| T-99-12 | Tampering | `RoutingTrace` verdict rendering | mitigate | Keep pass/fail and matcher semantics sourced from upstream verdict tuples; do not add view-side matcher evaluation. |
| T-99-13 | Information Disclosure | `EvidenceCard` default render | mitigate | Keep raw payload absent unless `reveal_state == :revealed`; add redacted/denied/revealed tests with a unique secret. |
| T-99-14 | Elevation of Privilege | reveal affordance | mitigate | Reuse existing `phx-click="reveal_raw"` and InboundLive authorization; no new auth action or raw-source API. |
| T-99-15 | Denial of Service | raw payload display | mitigate | Preserve bounded `max-h-80 overflow-auto` read-only `<pre>` for revealed payloads. |
| T-99-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install or new dependency is planned. |
</threat_model>
