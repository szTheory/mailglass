# Phase 99 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Phoenix LiveView HEEx with Tailwind v4 standalone binary and vendored daisyUI |
| Preset | not applicable - this is not a React/shadcn project |
| Component library | Project Phoenix components plus daisyUI utility classes |
| Icon library | Vendored Heroicons inline plugin via `MailglassAdmin.Components.icon/1` |
| Font | Inter for UI, Inter Tight for headings, IBM Plex Mono for code/chips |

Contract:

- Use existing semantic utilities from `mailglass_admin/assets/css/app.css`: `text-label`, `text-body`, `text-heading`, `text-display`, `gap-sm/md/lg`, `rounded-box`, `bg-base-*`, `text-*`, `border-*`, `btn`, `badge`, and `motion-*`.
- Do not add shadcn, external component registries, Node tooling, raw hex colors in HEEx, custom client JS hooks, glassmorphism, bevels, or new product routes.
- Keep all inbound data access behind `MailglassAdmin.OptionalDeps.MailglassInbound`; the UI must still compile and render an empty-safe surface when the optional inbound package is absent.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tight inline chips, badge icon spacing |
| sm | 8px | Compact field gaps, chip groups, row metadata gaps |
| md | 16px | Default card internals, form blocks, list row content gaps |
| lg | 24px | Section spacing, master/detail group gaps, card padding at desktop |
| xl | 32px | Large page group separation when needed |
| 2xl | 48px | Major page breaks only |
| 3xl | 64px | Page-level breathing room only |

Exceptions:

- `min-h-11` is required for interactive controls and rows to satisfy the 44px touch target floor.
- `max-h-80` is allowed only for bounded read-only overflow regions such as the revealed raw payload `<pre>`.
- Percentage grid tracks (`md:grid-cols-[40%_60%]`, `min-[1440px]:!grid-cols-[33%_67%]`) are layout structure, not spacing values.

## Typography

Use exactly these four sizes and two weights on the inbound surface.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 700 | 1.5 |
| Body | 14px | 400 | 1.5 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.2 |

Contract:

- Filter labels and small section labels use `text-label uppercase font-bold text-secondary`.
- Remove all inbound `tracking-[0.08em]` classes; letter spacing is token-owned.
- Replace raw `text-lg`, `text-xl`, `text-2xl`, and larger type utilities with `text-heading` or `text-display`.
- Use `.mono` with `text-label` for IDs, matcher values, actual values, raw payload snippets, and verification fact chips.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-base-100` / `--mg-color-background` (`#F8FBFD` light, `#0D1B2A` dark) | Page background, right-column orientation area, sunken read-only chips inside raised cards |
| Secondary (30%) | `bg-base-200` / `--mg-color-surface-raised` (`#FFFFFF` light, `#152538` dark) | Filter card, overview tier, list card, detail cards, routing trace, evidence card |
| Accent (10%) | `text-primary`, `border-primary`, `btn-primary`, `focus-visible:ring-primary` / `--mg-color-accent` (`#277B96` light, `#A6EAF2` dark) | Primary CTA, active nav, selected list row left border, focus rings |
| Destructive | `text-error`, `border-error`, `badge-error`, `alert-error` / `--mg-color-error-*` | First failing route clause, route-level no-match badge, blocked/error feedback only |

Accent reserved for: primary action button, focus rings, active navigation indicator, selected inbound row border, and no other default structural borders or card fills.

Semantic status colors:

- `text-success` / `badge-success` for accepting and passing states.
- `text-warning`, `border-warning`, `bg-warning/10` only for denied reveal or warning states.
- `text-error`, `border-error`, and `badge-outline badge-error` only for failing route clauses, no-match route verdicts, and error states.

## Visual Hierarchy And Interactions

Primary focal point:

- At 390px, the inbound overview renders before the record list and becomes the first scannable answer to "what is happening in this tenant/window?"
- At `>=768px`, the overview renders above the list column inside the master/detail context.
- When an InboundMessage is selected, the detail pane becomes the focal point and the mobile list hides in favor of a full-width detail view.

Layout contract:

- Add a mobile-only filter disclosure using `Phoenix.LiveView.JS.toggle`, `data-testid="inbound-filters-toggle"`, and an inline `hidden md:block` filter panel. Filters stay visible at `>=768px`.
- Master/detail uses `md:grid-cols-[40%_60%]` and `min-[1440px]:!grid-cols-[33%_67%]`.
- At 390px, selected detail replaces the list in place. Provide `data-testid="inbound-detail-back"` with label `Back to inbound records`; it patches the existing URL state with `inbound_id` removed.
- Preserve `orientation_strip surface={:inbound}` when no record is selected; place it according to IA-LD-01.

Component contracts:

- `inbound-overview`: flat `bg-base-200 border border-base-300 rounded-box` tier. Show total InboundMessages, no-match count, accepted count, no-match rate, and secondary chips for reject, bounce, failed, and ignore when present. Values use `.mono`.
- `inbound-routing-trace`: read-only, rendered only for `:no_match`, with route cards and clause rows. Clause rows align `Dimension`, `Expected`, and `Actual` at wider widths and stack cleanly at 390px. Expected/actual values are mono chips on `bg-base-100`. The first failing clause keeps `border-l-4 border-error`; route-level no-match keeps `badge-outline badge-error`.
- `inbound-evidence-card`: owns the locked/info reveal affordance. Default state never renders raw payload bytes. Verification facts, provider, payload size, and header count render as mono key/value chips on `bg-base-100`. Revealed raw payload remains read-only in a bounded `<pre>`.
- No icon-only controls are introduced. Icons inside status rows and route verdicts are decorative with text labels or adjacent labels carrying the meaning.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Open InboundMessage` |
| Secondary CTA | `Clear filters` |
| Mobile filter toggle | `Filters` |
| Mobile detail back | `Back to inbound records` |
| Raw evidence reveal | `Reveal raw source` |
| Filter label | `Time window` |
| Empty state heading | `No tenant selected`; `No InboundMessages yet`; `No InboundMessages match these filters` |
| Empty state body | No tenant: `Enter a tenant ID to inspect inbound routing for one workspace.` Truly empty: `InboundMessages appear here once this tenant receives its first message.` Filtered empty: `Adjust the filters or wait for the next inbound message.` |
| Detail select prompt | `Select an InboundMessage to inspect its Mailbox routing, execution timeline, and raw evidence.` |
| Loading state | `Loading InboundMessages...` if explicit async loading UI is introduced |
| Error state | `InboundMessage not loaded: selected record is outside the current tenant or active filters. Refresh the page or adjust the filters, then try again.` |
| Destructive confirmation | No new destructive action in Phase 99. Existing replay confirmation keeps the `Re-runs Mailbox routing against the stored InboundMessage... Confirm to replay.` pattern from COPY-LD-13. |

Copy rules:

- Do not use `Oops`, `Whoops`, `Uh oh`, `Something went wrong`, generic `No data found`, or standalone `Email`.
- Use domain nouns: InboundMessage, Mailbox, Delivery, Suppression, Event, Message, Mailable.
- Overview label copy is allowed to be concise: `InboundMessages`, `No match`, `Accepted`, `No-match rate`, `Rejected`, `Bounced`, `Failed`, `Ignored`.

## Accessibility And Responsive Contract

| Area | Contract |
|------|----------|
| Heading hierarchy | Keep exactly one page `h1` from the operator shell. Inbound cards use `h2`/`h3` with token classes only. |
| Focus | Interactive controls use visible semantic focus rings via `focus-visible:ring-2 focus-visible:ring-primary` or daisyUI equivalent. |
| Touch targets | Buttons, inputs, selects, list rows, reveal controls, and mobile back/filter controls must be at least 44px tall (`min-h-11`). |
| ARIA/state | Active nav keeps `aria-current="page"`; selected inbound rows keep `aria-current`/`aria-selected`; reveal states remain explicit in DOM test hooks. |
| Viewports | Validate 390, 768, and 1440 widths in both themes. At 390, records list is full width until selection, then detail is full width with back affordance. |
| Contrast | Text and non-text boundaries meet WCAG AA in light and dark using existing `--mg-*` and daisyUI semantic tokens. |
| PII | Recipient actuals remain masked with `Components.mask_recipient/1`; overview stats never expose addresses, subjects, headers, raw payload bytes, or cross-tenant counts. |
