<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| durable receive truth -> async execution trigger | Once canonical/evidence truth is committed, execution may happen later and in a different process without changing the receive contract. |
| optional dependency gateway -> Oban runtime | Direct third-party job-system details must remain internal so the stable package surface does not grow accidentally. |
| bounded fallback -> operator expectations | Users must not mistake Task-based fallback for durable background execution with retries. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-01 | Tampering | ingress execution dispatch | mitigate | Keep persist-first ordering and move all async dispatch to post-commit logic only. |
| T-42-02 | Repudiation | execution lineage across multiple trigger modes | mitigate | Reuse one shared runner so fresh/replay/Oban/fallback outcomes all append to the same lineage model. |
| T-42-03 | Misrepresentation | non-Oban fallback semantics | mitigate | Emit explicit warning posture and keep docs/tests strict that fallback has no durability or automatic retries. |
</threat_model>
