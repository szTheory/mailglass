### Conflict Resolution Decisions (frozen)

**Conflict 1 — Phantom `:suppressed` atom (deliveries_list.ex:83):**
`:suppressed` maps to Amber/warning but has no row in the canonical Anymail taxonomy. The canonical delivery-level signal for a suppressed recipient is that the delivery never reaches the provider — the status remains `:failed` or is never dispatched. The unified `status_badge/1` must NOT include `:suppressed` as a recognized atom. If the value appears at runtime, it falls through to the neutral/unknown fallback (`bg-base-200 text-secondary`, `badge-outline`). The phantom atom is eliminated.

**Conflict 2 — Singular inbound atoms (records_list.ex:97-99):**
`records_list.ex` uses `:accept`, `:reject`, `:bounce` (singular, present tense). The canonical Anymail inbound taxonomy uses past tense: `:accepted`, `:rejected`, `:bounced`. The unified `status_badge/1` uses canonical past-tense atoms. The call site in `records_list.ex` must normalize the outcome value to canonical past-tense before passing it to `status_badge`. Resolution: the call site adapter function `record_outcome/1` (already present at records_list.ex:55) is updated to map singular → past-tense atoms before the badge render.

**Conflict 3 — Full string vs modifier-only (timeline.ex:130-135):**
`timeline.ex` returns the full `"badge badge-outline badge-error"` string (including the base `badge` class). `deliveries_list.ex` and `records_list.ex` return only the modifier (`"badge-success"`) and let the call site prepend `"badge badge-sm"`. The unified `status_badge/1` component renders a `<span>` with the full class list internally. The component ALWAYS includes the base `badge` class. All call sites use `<Components.status_badge status={...} />` with no manual class prepending. The call site in `timeline.ex:52` retains its `:if={event_badge(event.type)}` guard but drops the manual `class={badge_class(event.type)}` wrapper.

**Conflict 4 — Replay semantics (timeline.ex:131-133):**
All three replay event types (requested, succeeded, failed) currently map to `badge-error`. This is semantically incorrect: `:webhook_replay_succeeded` should be success (Pine), `:webhook_replay_requested` should be in-flight (Glass), and only `:webhook_replay_failed` should be error (Crimson). The unified taxonomy corrects this.

**Conflict 5 — `:dispatched` mapped to success:**
`deliveries_list.ex:80` groups `:dispatched` with `:delivered` and `:sent` under `badge-success`. Dispatched means handed to the provider — outcome unknown; it is in-flight, not terminal success. The unified taxonomy maps `:dispatched`, `:queued`, and `:sent` to the in-flight signal (Glass/primary tint). Only `:delivered` maps to success.

## Empty / Error / Loading State Inventory

Source: FEATURES.md §4, requirements AUDIT-02 (pre-populated). Phase 78 seed expansion makes every state reachable.

### State Taxonomy

| State | Trigger | Component pattern |
|-------|---------|------------------|
| Loading | Data fetch in-flight | Skeleton placeholder rows/cards (no spinner unless > 200ms) |
| Blank slate | Fresh context, zero data ever created | Icon (outline, `text-secondary`) + `text-heading font-bold` title + `text-body` description + one primary CTA |
| No results | Filter returns zero matches | Icon + quote the filter value + "No [noun] match [filter]." + "Clear filters" CTA |
| Error | Data fetch failed | `hero-exclamation-triangle` icon + specific error description + Retry CTA. Never blame user. |
| Cleared | All actionable items processed | Pine/success tint confirmation. Brief, not celebratory. |

### Empty State Copy Rules (Vercel Geist + brand book)

1. Title: "No [noun] yet" or "[Noun] not found." Title Case. State the condition. Never repeat the navigation label.
2. Description: Sentence case. One sentence. Explain why or what to do next. New information, not a repeat of the title.
3. CTA: Title Case, Verb + Noun. One primary action max. "View Documentation", "Send Test Email", "Clear Filters". Never "Get Started", "Continue", or "Learn More" (too generic).
4. Icon: Domain-relevant Heroicon, outline style, `text-secondary` color. No illustrations, no SVG art.

## Motion Assignment Matrix

Source: FEATURES.md §5, design-system.md motion vocabulary (pre-populated). Phase 77 implements this matrix. Phase 76 must land structural changes before Phase 77 begins.

| Motion | CSS class | Duration | WHERE to apply | WHERE NOT to apply |
|--------|-----------|----------|---------------|-------------------|
| `reveal` | `motion-reveal` (opacity + translateY 6px) | 220ms | Detail pane opening (delivery-keyed id), flash toasts, card appearance | Filter changes, pagination, periodic data updates, list row selection without navigation |
| `timeline-in` | `motion-timeline > *` (staggered 40ms, cap 8) | 220ms + stagger | Event timeline items on initial mount of detail pane | On every timeline patch/LiveView update |
| `tab-swap` | `motion-tab-swap` (crossfade 150ms, id-keyed) | 150ms | Preview tab switch | Full LiveView navigation, modal close |
| `overlay` | `motion-overlay` (scale 0.98→1 + opacity) | 220ms | Modal/dialog open | Modal close (instant or 100ms reverse) |
| `row-state` | `transition-colors duration-(--duration-fast)` | 100ms | Row hover, row selected state, active nav item | Row removal (instant), filter input changes |
| `flash` | `motion-reveal` on toast region | 220ms entry / 100ms exit | Success/error flash after action | Informational banners (static) |

### Motion Rules (non-negotiable)

- Ease-out only (`ease-out`). Never `ease-in`, `ease-in-out`, or `ease-linear`.
- Exits faster than entrances. Leaving ≤ 100ms. Arriving ≤ 220ms.
- Animate transform + opacity ONLY. Never `height`, `width`, `max-height`, `padding`, `margin`.
- Entrance fires on element mount (`phx-mounted` or `:if`-toggle re-insert), not on every LiveView patch.
- Never animate keyboard-repeatable actions (row navigation, filter typing).
- All six named motions are covered by the existing global `@media (prefers-reduced-motion: reduce)` block in `app.css`. No per-component `motion-reduce:` variants needed.
- No motion on orientation strip (always visible, not triggered by action).
- No animated height/width on support card state changes.

### Motion-Reveal Re-Fire Fix (Phase 77 specification)

Current bug: `operator_live.ex:332` — the `motion-reveal` div has no `id`. LiveView patches it in place on delivery selection change; animation does not re-fire. Fix: add delivery-keyed `id={"delivery-detail-#{@selected_delivery.id}"}`. Pattern reference: `preview/tabs.ex` id-keyed `motion-tab-swap`. This fix is Phase 77, not Phase 76.

## Gap Register Dimension Reference

The gap register (separate artifact: `74-GAP-REGISTER.md`) uses the six conformance pillars from `mailglass_admin/docs/design-system.md:104-121`:

1. **Spacing/size** — token utilities on the 4px grid; touch targets ≥ `min-h-11`
2. **Radius** — `rounded-box` / `rounded-field` only
3. **Color** — semantic tokens + opacity tints; no hex; accent ≤ 10%
4. **Type** — `text-label/body/heading/display`; `font-bold` or default only
5. **Elevation/stacking** — border + `shadow-flat`; `shadow-overlay` for modals only; z-index from named tiers
6. **Motion + A11y** — named motion vocabulary; `prefers-reduced-motion` inherited; semantic roles; visible focus rings

Severity scale (from D-04/D-05):
- **5** — Blocks correct usage or accessibility; blocks Phase 79 closeout
- **4** — Visible quality regression; blocks Phase 79 closeout
- **3** — Meaningful inconsistency; minimum severity required to cite in a build-phase task
- **2** — Minor drift; tracked but does not block closeout
- **1** — Cosmetic; noted only

Anti-churn contract: every build task in Phases 75-78 MUST cite a Phase 74 gap-register row at severity ≥ 3. No citation = no merge.
