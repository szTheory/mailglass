# Plan 54-01: PR/Branch Triage + Green Main Proof

## Objective

Execute the final v1.3 repo-truth closeout after the hygiene automation implementation: push the hygiene branch, dispose the open PR backlog, document or prune stale branches, verify CI and branch-protection truth, and capture final hygiene JSON evidence.

## Task 0: Baseline and push v1.3 branch

1. Confirm the local baseline:
   - `git status --short --branch`
   - `git log --oneline -3`
   - `git diff --stat origin/main..HEAD`
2. Ensure the only uncommitted changes are Phase 54 planning artifacts. Commit those before remote PR/branch mutation.
3. Push `work/v1.3-release-discipline` to origin.
4. Open or update the v1.3 PR with the release-discipline implementation summary and verification evidence from commit `fab1384`.

## Task 1: Triage dependency PRs

Compare each dependency PR against the current v1.3 lock refresh. If v1.3 already carries an equal or newer dependency version, comment and close the PR as superseded after the v1.3 PR exists. If not superseded, refresh and merge only after policy and CI pass.

Expected dispositions from planning-time evidence:

- #39 `postgrex-0.22.1`: likely superseded by the v1.3 `mix.lock` refresh.
- #38 `phoenix-1.8.7`: likely included by the v1.3 `mix.lock` refresh.
- #29 `sigra-1.20.0`: likely included by the v1.3 `mix.lock` refresh.
- #28 `oban-2.22.1`: likely included by the v1.3 `mix.lock` refresh.
- #27 `swoosh-1.25.1`: likely superseded by the v1.3 `mix.lock` refresh.

Record the exact action for each PR in `54-TRIAGE-RECORD.md`.

## Task 2: Triage workflow PR #37

1. Inspect #37's diff and current workflow usage of `actions/setup-node`.
2. If the upgrade is still relevant, refresh the branch and merge only after actionlint and CI pass.
3. If the change is no longer applicable or is covered elsewhere, close with a clear superseded reason.
4. Record the outcome in `54-TRIAGE-RECORD.md`.

## Task 3: Triage stale human PRs #17 and #30

1. Diff-audit #17 against the v1.2 SES inbound/provider work. Close it as superseded unless unique required work remains.
2. Diff-audit #30. Close the stale draft unless unique release-engineering work remains.
3. If either PR is deferred instead of closed, record the owner, reason, and exact next action.
4. Record all outcomes in `54-TRIAGE-RECORD.md`.

## Task 4: Document and prune branches

1. List local and remote branches with tracking status.
2. Document `preserve/*` branches as intentional archives.
3. Delete only branches proven merged or unnecessary:
   - old worktree-agent branches with no unique work
   - old release trigger branches if merged or obsolete
   - stale feature branches only after corresponding PR closure
4. Record branch decisions in `54-TRIAGE-RECORD.md`.

## Task 5: Capture green-main and hygiene evidence

1. Wait for CI on the pushed v1.3 PR/SHA and record run URL, SHA, status, and conclusion.
2. Run local verification:
   - `mix compile --warnings-as-errors`
   - `mix test test/mix/tasks/mailglass.repo.hygiene_test.exs test/mailglass/stability_contract_test.exs --warnings-as-errors`
   - `actionlint .github/workflows/release-please.yml .github/workflows/publish-hex.yml .github/workflows/post-publish-smoke.yml .github/workflows/repo-hygiene.yml`
   - `git diff --check`
3. Verify branch protection when credentials allow:
   - `GH_TOKEN="$(gh auth token)" scripts/verify-branch-protection.sh main`
4. Run and capture:
   - `mix mailglass.repo.hygiene --check --format json`
5. Write results to `54-GREEN-MAIN-EVIDENCE.md`.

## Task 6: Update planning truth

1. Update `.planning/ROADMAP.md` with Phase 54 completion status when all success criteria are satisfied.
2. Update `.planning/STATE.md` with current position and evidence pointers.
3. Check whether `.planning/REQUIREMENTS.md` has v1.3 acceptance checkboxes that should be marked complete.
4. Commit Phase 54 execution artifacts.

## Acceptance Criteria

- PRs #17, #27, #28, #29, #30, #37, #38, and #39 are each merged, closed, or explicitly deferred with reason.
- Local stale branches are pruned when safe or documented as preserved exceptions.
- The v1.3 hygiene branch is pushed and CI status for the relevant SHA is recorded.
- Branch protection is verified, or the credential limitation is documented without pretending success.
- Final `mix mailglass.repo.hygiene --check --format json` output is captured and its remaining blockers are either zero or explicitly accepted.
