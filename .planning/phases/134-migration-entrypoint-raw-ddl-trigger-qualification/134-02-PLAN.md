<objective>
Hand-qualify every raw-DDL object Ecto does not auto-prefix — the events immutability
function + trigger, the v01/v03 CHECK constraints, and all down/0 raw drops — to the
runtime schema prefix, while keeping `citext` in `public`. Then prove the milestone's
load-bearing correctness guarantee: the immutability trigger raises SQLSTATE 45A01 under
the `mailglass` schema with NO `search_path` pin.

Purpose: Close MIGR-03 (schema-qualified, `SET search_path = ''` immutability function +
trigger, no global-name collision), MIGR-04 (qualify the CHECK constraints + all raw
`down/0` drops), and MIGR-05 (the load-bearing regression: citext stays public, up/down
round-trips against a non-public prefix, and the trigger fires 45A01 without a search_path
crutch). This depends on Plan 134-01 issuing CREATE SCHEMA so the schema physically exists.

Output: schema-qualified v01/v03 raw DDL; a prefix-threaded v01 `down/0`; and a dedicated
immutability regression test that deletes the FACADE-04 search_path crutch.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator config → raw DDL SQL | The `:schema` prefix (operator-controlled `config :mailglass, :schema`) is interpolated into raw `execute()` DDL strings (`#{q}.` qualification). Not request input, but interpolated into SQL. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-134-01 | Tampering (SQL injection) | v01/v03 raw `execute()` `#{q}.` qualification + `CREATE SCHEMA` | high | mitigate | Every prefix is validated through `Mailglass.Identifier.validate!/2` (the single unquoted-identifier chokepoint, decision 132-01) BEFORE any interpolation; `inspect(prefix)` double-quotes it. `:schema` is operator config, not request input. Acceptance check (WR-01 lineage): no `#{q}.` / `CREATE SCHEMA` interpolation site is reachable without a prior identifier validation. No `high`-severity residual once every new interpolation site is gated. |
| T-134-02 | Elevation of Privilege | `SET search_path = ''` on the immutability function | low | mitigate | The function body references nothing unqualified; the empty search_path is defense-in-depth (Postgres best practice) that immunizes it against a caller's ambient path / CVE-2018-1058. |
| T-134-03 | Tampering (ledger mutation) | `<prefix>.mailglass_events` append-only trigger | high | mitigate | The immutability trigger + function are relocated INTO the schema but MUST still raise SQLSTATE 45A01 on UPDATE/DELETE (MIGR-05 proof). The core invariant is preserved, not weakened. |
| T-134-SC | Tampering | npm/pip/cargo installs | n/a | accept | No package-manager installs in this phase (pure Elixir/SQL DDL edits). No `## Package Legitimacy Audit` required. |

Residual risk: none `high` once identifier validation gates every new interpolation site
and the 45A01 trigger is proven to still fire under the relocated schema.
</threat_model>
