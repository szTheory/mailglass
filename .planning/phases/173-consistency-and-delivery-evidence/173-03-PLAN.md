## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local checkout → review candidate | Dirty or unrelated changes must not be silently promoted into the committed review source. |
| GitHub Actions → delivery claim | Run/job data must match the exact candidate SHA and required job name. |
| Preview/evidence → owner review | Served asset identity and temporary resource disposition must be truthful and inspectable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-173-10 | Tampering | Candidate checkout and generated assets | high | mitigate | Tasks 1 and 3 verify committed source, generated/served CSS bytes and clean candidate checkout before final evidence. |
| T-173-11 | Denial of Service | Owner preview during delivery review | high | mitigate | Tasks 1–3 use disposable synthetic browser reset, scoped evidence cleanup, and retain the separate feedback preview. |
| T-173-12 | Information Disclosure | Retained handoff artifacts | medium | mitigate | Task 2 labels synthetic artifacts and their retention; Task 3 emits only hashes, paths, status and run URLs, never recipient/message data or reset tokens. |
