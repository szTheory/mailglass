<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external webhook sender → provider verifier | Untrusted JSON and signature fields cross into crypto and timestamp validation |
| provider verifier → ETS replay cache | Attacker-controlled token strings cross into shared in-memory replay state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | S | `Mailglass.Webhook.Providers.Mailgun.verify!/3` | mitigate | Verify lowercase hex HMAC-SHA256 over `timestamp <> token` with `Plug.Crypto.secure_compare/2`, reject malformed signature payloads, and require configured `:signing_key` per D-01. |
| T-15-02 | D | `MailgunReplayCache` | mitigate | Bound replay entries by TTL, replace expired rows in-place, and keep cache operations in ETS to avoid DB hot-path exhaustion per D-02. |
| T-15-03 | T | `Mailglass.Webhook.Providers.Mailgun.normalize/2` | mitigate | Map only the D-09 stable event set; preserve ambiguous Mailgun details in string-key metadata instead of inventing normalized semantics per D-10. |
</threat_model>
