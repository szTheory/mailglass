`mailglass_inbound`. Today every inbound test uses an in-memory `FakeRepo`/`ReplayRepo`
stub — there is no `MailglassInbound.TestRepo`, no inbound `config/test.exs`, no migration
runner in `test_helper.exs`, and `mix credo --strict` from repo root never even reads

must actually run against inbound).

dedupe, and without Credo path-scope widening the PII check silently passes by never
reading inbound. Both are mechanism gaps, not feature gaps.

`test_helper.exs` + a Postgres inbound CI job + widened `.credo.exs` + defensively-widened
`TelemetryEventConvention` + `gen_smtp` optional dep in inbound mix.exs + api_stability
inventory entries for the two new public surfaces (`MailglassInbound.MIMEError`,
