<objective>
Close the PII leak (WARNING): `plug.ex:84` interpolates `inspect(reason)` into the JSON
500 body on a persist failure. `Persist.persist/2` returns `{:error, %Ecto.Changeset{}}`
whose `changes` carry recipient PII (`subject`/`from`/`to`/`cc`/`bcc`/`reply_to`/
`text_body`/`html_body`, built in `persist.ex:118-137`), so `inspect(reason)` renders
recipient email contents in plaintext to Postmark/SendGrid on a transient DB failure —
contradicting the strict no-PII posture (telemetry/logs are already clean; only this
egress path leaks).

Fix:
- **Body:** return a static closed code `%{status: "error", reason: "persist_failed"}` —
  never interpolate `reason`. Converges on the core webhook plug, which already returns a
  static/empty 500 body.
- **Status: keep 500.** Verified-correct retry semantics: Postmark/Mailgun/SES retry
  non-2xx; SendGrid Inbound Parse DROPS 4xx with no retry — downgrading would
  permanently lose the email on a transient DB error. A DB error is operational, not an
  Anymail rejection.
- **Detail (adopter DX) goes where it's safe:** a PII-free classified atom in the
  telemetry stop-metadata via `classify_persist_error/1` as `error_kind`. The full-fidelity
  record already lives in the committed tenant-scoped `InboundEvidence` row.
- **Recurrence guardrail:** a new `NoPiiInResponseBody` Credo check that flags
  `inspect(...)` / changeset / bare error-var inside `send_resp`/`send_json`/`put_resp_body`
  argument heads within the webhook + ingress path prefixes — closing the "no PII in ANY
  egress (logs, telemetry, AND response bodies)" hole the current checks miss.

Purpose: make the no-PII-on-egress non-negotiable hold on the response path and become
enforceable rather than convention.
Output: PII-safe plug error path + new egress check + its fixture test + registration.
</objective>
