Test idiom (all custom-check tests in test/mailglass/credo/):
- `use ExUnit.Case, async: true`; `setup_all` does `{:ok, _} = Application.ensure_all_started(:credo)`.
- Run a check: `source |> Credo.SourceFile.parse(filename) |> CheckModule.run(params)` — `params` is a keyword list (default `[]` uses the check's param_defaults).
- Both checks below are NOT path-gated (no `included_path_prefixes`), so any fixture filename works.

RequireAtomicUnsubscribeHeaders check (credo_checks/require_atomic_unsubscribe_headers.ex) — DO NOT EDIT:
- `run/2` defaults `params \\ []`; no param_defaults. Traverses modules/functions tracking header writes.
- FLAGS a write of the literal string "List-Unsubscribe" or "List-Unsubscribe-Post" via one of:
  the bare local calls `put_header`/`put_header_if_absent`, OR a `<Module>.header(...)`/`<Module>.put(...)`
  where the module tail is `Email` or `Map` — UNLESS the enclosing module/function is exactly
  `Mailglass.Compliance.inject_unsubscribe_headers` (the sanctioned injector).
- ALSO flags the sanctioned `Mailglass.Compliance.inject_unsubscribe_headers/_` itself (postwalk) if it
  does NOT write BOTH "List-Unsubscribe" and "List-Unsubscribe-Post" (the atomic-pair requirement).
- Issue message for the out-of-place write mentions "Mailglass.Compliance.inject_unsubscribe_headers/2".
- No issue when: a non-unsubscribe header is written anywhere, OR both unsubscribe headers are written
  together inside `Mailglass.Compliance.inject_unsubscribe_headers`.

StreamPolicyConsistent check (credo_checks/stream_policy_consistent.ex) — DO NOT EDIT:
- `param_defaults: [mailable_module: Mailglass.Mailable]`; `mailable_module` param identifies mailables by module tail.
- FLAGS a `use Mailglass.Mailable, opts` node where `opts` enables tracking (`tracking: true`, or a non-empty
  tracking keyword/map, or `tracking: [open: true]`) AND `:stream` is nil OR `:stream == :transactional`.
- No issue when: `tracking: true` paired with `stream: :bulk` or `stream: :operational`, OR no `:tracking`
  key, OR `tracking: false`/`nil`/`[]`, OR the `use` target tail is not `Mailable`.

Naming convention (load-bearing for the meta-test): `credo_checks/<name>.ex` → `test/mailglass/credo/<name>_test.exs`.
There are 16 check files; today exactly two lack a test: `require_atomic_unsubscribe_headers.ex` and
`stream_policy_consistent.ex`. (45-07 adds `no_pii_in_response_body.ex` together with its own test.)

.credo.exs structure (load-bearing for the sentinel):
- `Code.eval_file(".credo.exs")` returns `{config_map, _binding}`; config is `%{configs: [%{checks: ...}]}`
  (the `checks` value may be a keyword-style list of `{CheckModule, params_keyword}` tuples, possibly grouped
  under `enabled`/`extra`/`disabled` keys — locate the custom-check tuples by their first element /module name).
- NoBareOptionalDepReference tuple params hold `gated_modules` (a map); must contain `:mimemail` + `:gen_smtp_client` (CR-01).
- TelemetryEventConvention tuple params hold `required_root` (atom or list); `List.wrap/1` must include `:mailglass_inbound` (WR-02).
