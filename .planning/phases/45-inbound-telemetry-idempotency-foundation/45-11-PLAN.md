The real inbound emission shape (mailglass_inbound/lib/mailglass_inbound/telemetry.ex) — DO NOT EDIT:
- Four PUBLIC named helpers, each passing a LITERAL atom list as the first arg to the PRIVATE
  local `span/3`:
    def ingress_span(metadata, fun)   -> span([:mailglass_inbound, :ingress, :request], metadata, fun)   # 3 segments
    def route_span(metadata, fun)     -> span([:mailglass_inbound, :route, :match], metadata, fun)        # 3 segments
    def persist_span(metadata, fun)   -> span([:mailglass_inbound, :persist, :record], metadata, fun)     # 3 segments
    def execution_span(metadata, fun) -> span([:mailglass_inbound, :execution, :run], metadata, fun)      # 3 segments
- The private `defp span(event_prefix, metadata, fun)` calls `:telemetry.span(event_prefix, ...)`
  with a VARIABLE `event_prefix` — invisible to a literal-only `:telemetry.span` AST clause.
- So the literal event names live at the `span([...], ...)` CALL SITE inside each `*_span` helper.
  These prefixes are 3 segments; the runtime appends `:start`/`:stop`/`:exception` to reach 4
  (min_segments). They are validated against `min_segments - 1` (the existing span threshold).

The check today (credo_checks/telemetry_event_convention.ex) — the file under edit:
- `param_defaults: [required_root: :mailglass, min_segments: 4]`; `.credo.exs` configures
  `required_root: [:mailglass, :mailglass_inbound], min_segments: 4`.
- `run/2` does `Credo.Code.prewalk(source_file, &walk/5, ctx)` and returns `result.issues`.
- TWO existing `walk/5` clauses match the qualified-call AST
  `{{:., _, [:telemetry, :execute]}, meta, [event_ast, _, _]}` (threshold: `min_segments`,
  trigger ":telemetry.execute") and `{{:., _, [:telemetry, :span]}, meta, [event_ast, _, _]}`
  (threshold: `min_segments - 1`, trigger ":telemetry.span"). A fall-through clause returns
  `{ast, ctx}`.
- Shared `validate/8` (keyword opts `threshold:` + `trigger:`): calls `literal_atom_list(event_ast)`;
  if `{:ok, [root | _] = event}` with `length(event) >= threshold` and `root in required_roots` →
  no issue; if root not allowed OR too short → one `root_issue`; if `:error` (non-literal/var) →
  no issue. REUSE this `validate/8` for the new clause (same root/length/false-positive logic).
- `literal_atom_list/1` returns `{:ok, list}` only when every element is an atom, else `:error`
  (so a variable prefix yields `:error` → no issue).

The MATCH SHAPE for a `*_span` helper call site (what the new clause must recognize):
- A LOCAL call to a `*_span`-suffixed function: AST `{fn_name, meta, [event_ast | _rest_args]}`
  where `fn_name` is an atom whose string form ends with `"_span"` and `event_ast` is its FIRST
  argument. (The four real helpers are `ingress_span`/`route_span`/`persist_span`/`execution_span`;
  match by the `*_span` suffix so the rule generalizes to the webhook package's `*_span` helpers
  too, NOT a hardcoded four-name allowlist.)
- The first arg is the LITERAL event prefix (3 segments in real code) → validate against the SPAN
  threshold `min_segments - 1` (same off-by-one as the `:telemetry.span` clause), since these
  helpers wrap `:telemetry.span/3`.
- A `*_span` call whose first arg is NOT a literal atom list (a variable) → `literal_atom_list`
  returns `:error` → no issue (false-positive avoidance — e.g. the private `span(event_prefix,...)`
  wrapper itself, whose first arg is a variable, must NOT be flagged).
- Beware self-matching: the existing `:telemetry.span` clause matches a QUALIFIED `:telemetry.span`
  call; a bare local `*_span(...)` call has a different AST head (atom function name, not a
  `{:., _, [:telemetry, :span]}` dotted call), so the new clause is additive and does not collide.

The dual-clause AST analog to MIRROR (credo_checks/no_pii_in_telemetry_meta.ex) — reference only:
- Shows the idiom of multiple narrow `telemetry_metadata/1`-style clauses each extracting the
  relevant arg from a different call shape, with a fall-through `:error` clause — the same
  multi-clause discipline the new `*_span` clause should follow.
