<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Trust-entry docs -> docs checker | If the scanner misses a trust-entry doc, boundary wording can drift outside deterministic enforcement. |
| Docs checker/test rules -> CI release proof | If the rules are weak or split across parallel mechanisms, internal implementation details can be misrepresented as public guarantees. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-61-01 | Tampering | `mailglass.docs.check` trust-entry coverage | mitigate | Add all D-04 trust-entry docs to `@tier1_paths` / `@tier1_surface_rules` so missing boundary tokens fail deterministically. |
| T-61-02 | Spoofing | Internal modules or checkpoint details treated as public contract truth | mitigate | Add a trust-boundary overreach detector plus ExUnit assertions that require explicit non-contract framing near internal names. |
| T-61-03 | Repudiation | Unscanned trust docs or unenforced wording drift bypasses review | mitigate | Extend both the Mix task and ExUnit docs-contract suite so the canonical enforcement path is CI-compatible and fail-closed. |
| T-61-SC | Tampering | npm/pip/cargo installs | n/a | No package-manager installs in this plan. |
</threat_model>
