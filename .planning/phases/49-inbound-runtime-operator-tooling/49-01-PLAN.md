<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider webhook poster → Ingress.Plug | Untrusted HTTP POST crosses here; signature verify is the wall, limiter sits behind it |
| operator app env → MailglassInbound.Config | Config values validated at boot via NimbleOptions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-01 | Denial of Service | Ingress.Plug rate limiter placement | mitigate | Limiter check sits in persist_and_respond/5 AFTER verify + resolve_tenant! — a forged-payload flood returns 401 before any budget is read (D-49-14). Test asserts forged request burns no budget. Placing it pre-verify would make it an unauthenticated-DoS amplifier (high → mitigated). |
| T-49-02 | Information Disclosure | rate_limit telemetry + 429 body | mitigate | Body + telemetry carry bucket TYPE (:tenant/:recipient/:sender_domain) only, never the value. Sender bucket keyed on DOMAIN, never full address (D-49-16/17). Asserted via PII-absence test + NoPiiInTelemetry denylist. |
| T-49-03 | Denial of Service | limiter raising → 500 retry-storm | mitigate | The limiter branch NEVER raises; it returns the `{resp, meta}` 429 tuple (D-49-14). A raise would escape the rescue allowlist as 500 and trigger provider retry storms. |
| T-49-04 | Tampering | per-node ETS rate state | accept | ETS is node-local; an N-node cluster enforces N× the limit. Acceptable for single-node-default library posture; cluster-global enforcement is out of scope (D-49-18). Documented, not mitigated. |
| T-49-05 | Spoofing/Input Validation | :mailglass_inbound app env config | mitigate | NimbleOptions schema validates the config shape at boot; invalid values raise with helpful errors (D-49-02). |
</threat_model>
