<objective>
Ship the suppression flag-only contract (IOPS-05): a suppressed-sender message persists normally with a boolean flag, surfaces in the admin list, and reaches mailbox callbacks through a new framework-owned typed `%InboundMessage.Signals{}` nested struct — with no auto-bounce.

Purpose: Forwarders, complaint replies, and false-positive recovery require that webhook-accepted mail from a suppressed sender is preserved as diagnostic signal, never auto-bounced (backscatter avoidance). The adopter reads `signals.suppression_flagged` and decides. This is the one genuinely-novel public-API surface in the phase — the `:signals` typed nested struct follows the `Ecto.Schema.Metadata` archetype (framework writes, adopter reads).
Output: `suppression_flagged` column + migration, `InboundRecord` field, the `Signals` nested struct + `:signals` field on `%InboundMessage{}` + a `suppression_flagged?/1` predicate, the degrade-OPEN compute in `Ingress.Persist`, the projection in `Execution.message_from_record/1`, the IADM-02 select, and the suppression-flag telemetry emit (using the helper from plan 01).
</objective>
