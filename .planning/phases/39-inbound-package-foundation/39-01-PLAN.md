<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adopter router DSL -> compiled route data | Untrusted author input becomes executable route configuration that later provider ingress and replay flows will trust. |
| mailbox callback -> internal runners | Adopter code returns an outcome that later execution modes will record and act on. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-01 | Tampering | `InboundMessage` public contract | mitigate | Keep raw payload, replay IDs, verification facts, and provider-only extras out of the stable struct per D-39-05 so contract drift cannot smuggle operational state into the public API. |
| T-39-02 | Elevation of Privilege | router matcher | mitigate | Restrict Phase 39 matchers to recipient, subject, and headers with exact/regex support only per D-39-10; block deferred predicate and multi-match features that would widen trust boundaries. |
| T-39-03 | Repudiation | mailbox outcomes | mitigate | Lock outcomes to the four approved classes and document that crashes/exits/throws are execution failures, not semantic outcomes, per D-39-14 through D-39-16. |
</threat_model>
