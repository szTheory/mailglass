    1. Existing Dark Token Inventory — extract and tabulate all dark-mode token values from `brandbook/tokens.css` [data-theme="dark"] block. For each token, note the hex value and compute or state the WCAG contrast ratio against its expected pair (text on surface, border on surface, focus-ring on surface). Flag any that fall below AA (4.5:1 for text, 3:1 for non-text).

    2. Phase 86 Dark-Feedback Extension — record the four committed dark-feedback contrast figures from STATE.md (success-bg #142B22/6.56:1, warning-bg #2B2314/7.37:1, error-bg #2E1B1E/6.65:1, info-bg #11293A/11.18:1).     3. External Pitfalls Research — synthesise the key dark-mode pitfalls from web.dev and WCAG: (a) elevation inversion (lighter = higher in dark), (b) desaturation of accent colors to prevent vibrance overload, (c) focus-ring contrast degradation (accent color may fall below 3:1 against dark surface), (d) overuse of pure black (#000000 vs Ink #0D1B2A), (e) glassmorphism / blur temptation in dark mode (banned by constraint). Cite each pitfall with URL.

    4. Current mailglass_admin Dark-Mode Gap Analysis — map the existing dark token set against the pitfalls. Specifically: does --mg-color-focus-ring (#277B96 Glass) maintain 3:1 contrast on the dark surface tokens? Does the preview chrome currently switch its surface tokens when `dark_chrome?` is true (GAP-03)? What elevation tier tokens are missing or wrong in dark?

    5. Draft Decisions — propose specific locked decisions for: (a) dark surface elevation tier mapping (surface-sunken, surface, surface-raised in dark — which hex values), (b) dark focus-ring strategy (token vs alternate), (c) dark desaturation rule for accent in dark (10% rule still applies; does the accent need adjustment?), (d) preview chrome dark implementation — what attribute or CSS variable the preview_live must set to activate dark tokens (closing GAP-03), (e) dark border token for interactive inputs, (f) dark status feedback token confirmation or amendment.

    6. Adversarial Synthesis — challenge each draft decision against (a) the hard design constraints (flat elevation = border-first, no glassmorphism/bevels, semantic tokens only, `brandbook/tokens.css` is SoT) and (b) the open GAP rows. Does the preview chrome decision close GAP-03? Does the focus-ring decision maintain ≥3:1 on the dark surface? Revise any decisions that fail. Note D-08 axis ownership: "COMPONENT-STATES owns which states exist; DARK-MODE owns how they render in dark — cross-reference STATE-LD-NN for the state that requires a dark variant."

    - Constraint-binding cell: name the specific hard design constraints (e.g. "semantic tokens only; flat elevation; no glassmorphism; brandbook/tokens.css is SoT")
    - Closes-GAP cell: reference the GAP-NN ID or "—"
    - Must include at minimum: dark elevation tier rows (surface-sunken/surface/surface-raised), dark focus-ring row, dark accent desaturation row, dark status-feedback row (confirming Phase 86 figures), preview chrome dark implementation row
    - GAP-03 (preview ignores dark theme) must appear in Closes-GAP for at least one row
