## Decisions recorded here (never made by omission)

1. **Task naming: ONE task, `--kind hex|deps`, not two Mix tasks** (RESEARCH Open Question #1,
   resolved). Mirrors `mailglass.publish.check`'s own `--package` flag convention. Both `ci.yml` jobs
   invoke the same task with a different flag value.

2. **D-10's `expired_entries/1` / `unused_entries/1` checks run ONLY inside `--kind hex` evaluation,
   never `--kind deps`.** Both allowlist entries are EEF-CVE-keyed (hex.audit-native); `mix deps.audit`
   is currently clean for cowlib 2.19.0 in every directory (mirego's DB range excludes it — F4). A
   naive per-kind unused-check would report BOTH entries "unused" on every `--kind deps` run for a
   reason that has nothing to do with staleness (the tool simply doesn't cover this version), which
   would self-inflict exactly the "promote a lane that immediately red-blocks everything" failure
   Plan 04 (VULN-03) must avoid. `--kind deps` still applies alias-aware SUPPRESSION (so a real future
   GHSA match still works); it just doesn't independently re-litigate "is this entry still needed" —
   that question is scoped to the tool that natively detects these entries.

3. **`unused_entries/1`'s signal source is `matched_hex_audit_ids/1` aggregated across all three
   scanned directories in a single `--kind hex` invocation**, not per-directory. An entry counts as
   "used" if it matched a finding in ANY scanned directory.

4. **`expired_entries/1` uses strictly-after semantics (`Date.compare(today, recheck_by) == :gt`).**
   An entry whose `recheck_by` is today does not yet block — it blocks starting the day after.
