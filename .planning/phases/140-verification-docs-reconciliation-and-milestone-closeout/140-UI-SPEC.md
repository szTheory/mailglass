# Phase 140 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 140 is a verification, documentation reconciliation, and milestone closeout phase. It does not add or redesign product UI. Preserve the existing admin visual system and update written truth so user-facing and maintainer-facing docs match the Phase 139 asset proof: hard refreshes and direct deep links should stay styled across the verified route matrix, including alternate mount roots. Source: `140-CONTEXT.md` D-01..D-11, `140-RESEARCH.md`, `.planning/REQUIREMENTS.md` DOC-01/DOC-02 plus SCHEMA/AAU/GATE traceability.

## Design System

| Property | Value |
|----------|-------|
| Tool | none - manual Phoenix LiveView + Tailwind v4 + daisyUI semantic themes |
| Preset | not applicable; no `components.json`; shadcn gate not applicable because this project targets Phoenix/LiveView, not React/Next/Vite |
| Component library | `MailglassAdmin.Components` plus page-local Phoenix components; daisyUI semantic utility classes only |
| Icon library | vendored Heroicons inline Tailwind plugin via `Components.icon/1`; no new icon package |
| Font | Inter for body/UI, Inter Tight for headings, IBM Plex Mono for identifiers/code; self-hosted WOFF2 under each admin mount path |

Design-system source of truth:
- Color themes and structural tokens live in `mailglass_admin/assets/css/app.css`.
- Usage rules live in `mailglass_admin/docs/design-system.md`.
- Brand voice and palette live in `brandbook/brand-book.md`.
- Asset URL behavior is proven by Phase 139 through `MailglassAdmin.MountPathHook`, `MailglassAdmin.MountPath.base/1`, `MailglassAdmin.Layouts.css_url/1`, first-HTML tests, and serialized Playwright hard-load tests.

Phase 140 must not introduce a competing styling system: no CSS-in-JS, no new CSS file, no `@apply`, no BEM layer, no React component registry, no Node asset pipeline, and no shadcn registry usage. If an executor unexpectedly touches admin CSS or HEEx class usage, they must rebuild with `mix mailglass_admin.assets.build` and keep `mailglass_admin/priv/static/` bundle-clean in the same change. The preferred Phase 140 path is docs/planning text only, with zero admin CSS or component edits.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: keep existing control-size floors only. Icon-only and touch controls must remain at least 44px (`min-h-11` and `min-w-11` when square width matters). Existing non-touch compact control tiers may remain 36px only where already documented, such as tab strips. Phase 140 must not add layout spacing, resize existing admin surfaces, or introduce new markdown/HTML layout treatments in docs.

Source: `mailglass_admin/assets/css/app.css` `@theme` spacing tokens and `mailglass_admin/docs/design-system.md` spacing checklist.

## Typography

Declared sizes are exactly the existing admin type scale: 12, 14, 20, and 28px. Declared weights are exactly 400 and 700; do not use `font-medium`, `font-semibold`, 500, or 600.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 700 | 1.5 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.2 |

Docs copy added in this phase is markdown prose, not a new UI type system. If any admin UI text is touched incidentally, it must keep the existing token classes: `text-label`, `text-body`, `text-heading`, `text-display`, default weight 400, and `font-bold` for emphasis. Do not add negative letter spacing, arbitrary font sizes, or synthesized weights.

Source: `mailglass_admin/assets/css/app.css` type tokens and `mailglass_admin/docs/design-system.md` type rules.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `base-100` / `--mg-color-background`: light `#F8FBFD`, dark `#0D1B2A` | Page ground and primary admin background |
| Secondary (30%) | `base-200` / `--mg-color-surface-raised`: light `#FFFFFF`, dark `#152538`; borders use `base-300` / `--mg-color-border`: light `#C7DCE5`, dark `#315069` | Cards, sidebars, list panes, filter panes, nav chrome, bordered group surfaces |
| Accent (10%) | `primary` / `--mg-color-accent`: light `#277B96`, dark `#A6EAF2` | Existing selected row border, selected nav/pill/timeline node, primary CTA, focus ring, and computed-style proof anchors only |
| Destructive | `error` / `--mg-color-error-solid`: light `#B42318`, dark `#E29089` | Existing destructive/manual repair actions and error status only |

Accent reserved for: selected-row border, active nav link/pill, active timeline node, primary CTA, focus ring, and Phase 139 computed-style proof anchors. Do not use accent as the default border, default badge color, decorative fill, docs callout color, or closeout status ornament.

Phase 140 must not change any color token, status token, theme mapping, or contrast rule. Documentation may refer to resolved behavior in words; it must not introduce new visual emphasis or screenshots.

Source: `brandbook/brand-book.md`, `mailglass_admin/assets/css/app.css`, and `mailglass_admin/docs/design-system.md`.

- Plain, exact, calm, and user-recoverable.
- Prefer specific nouns: `stylesheet href`, `font response`, `hard refresh`, `direct deep link`, `verified route matrix`, `focused gate`.
- Do not use `Oops`, `Whoops`, `Uh oh`, `Something went wrong`, or hype language.
- Do not expose `MountPathHook`, `MountPath`, or `Layouts.css_url` internals in user-facing docs unless the context is maintainer diagnosis.
- Do not make a fixed behavior sound like an expected limitation.

Source: `140-CONTEXT.md` D-04..D-07, `brandbook/brand-book.md`, and `CLAUDE.md` brand voice.

## Phase-Specific Visual Contract

Expected visual result: no visible product UI change. The admin should render exactly as the existing design system already specifies. Phase 140 may update text documentation about that behavior, but it must not change the admin's layout, spacing, colors, typography, motion, tokens, component structure, router macro API, or asset strategy.

Allowed visual/interaction work:
- Re-run and cite existing focused verification lanes.
- Update stale current-state wording in `mailglass_admin/docs/design-system.md`, `guides/run-the-demo.md`, and `.planning/backlog/admin-relative-asset-url-styling.md`.
- Preserve or strengthen explicit deferral wording in active planning artifacts if needed for DOC-02.
- Add a narrow stale-phrase docs guard only if it remains low-churn and directly tied to DOC-01.

Disallowed work:
- Admin redesign, brand refresh, token changes, component changes, layout changes, motion changes, or full UI/a11y sweep.
- Screenshot or pixel-diff baselines.
- New visual regression infrastructure beyond the existing network and computed-style proof.
- Public router macro option changes, duplicate nested asset routes, CDN/host asset rewrites, `<base>` tags, or redirects as the primary asset fix.
- Whole-suite no-search-path fixture migration.
- SEED-003 ecosystem integrations, Cloudflare routing, synthetic inbound dev UI, `gen_smtp`, provider additions, release ceremony, version bump, or Hex publish work.

If a focused gate fails, the interaction contract is: fix or replan the targeted regression only, then rerun that gate. Do not widen Phase 140 into deferred work.

## Verification Interaction Contract

Schema-prefix gate:
- Primary command: `mix verify.schema_prefix`
- Trust model: fail-closed proof for hostile no-search-path schema-prefix correctness.
- Broad dual-schema advisory matrix remains a canary and must not replace the focused proof.

Admin first-HTML gate:
- Command: `cd mailglass_admin && MIX_ENV=test mix test test/mailglass_admin/admin_asset_url_test.exs test/mailglass_admin/mount_path_test.exs --warnings-as-errors`
- Required behavior: stylesheet hrefs remain rooted at the effective admin mount path for preview, scenario, error, gallery, operator, inbound, query, and alternate route shapes.

Admin hard-load/style gate:
- Command: `cd mailglass_admin && npm run test:operator-browser -- --grep "admin asset hard load"`
- Required behavior: direct `page.goto` loads observe CSS/font responses with 200 status and token-backed computed styling. No screenshots or pixel diffs.
- Keep existing serialization through the project Playwright script.

Bundle/token gate:
- Command: `cd mailglass_admin && MIX_ENV=test mix test test/mailglass_admin/token_parity_test.exs test/mailglass_admin/bundle_test.exs --warnings-as-errors`
- Required behavior: token-backed compiled CSS remains coherent and bundle checks pass. Phase 140 should not touch the bundle.

Docs drift gate:
- Command: `rg -n "Navigate from the dashboard|Tracked as GAP-22|hard refresh on a deep URL can load unstyled|direct loads unstyled" guides/run-the-demo.md mailglass_admin/docs/design-system.md .planning/backlog/admin-relative-asset-url-styling.md`
- Required behavior: no current-state stale hits remain after DOC-01 reconciliation. Historical references may remain only when clearly framed as resolved history, not present limitation.

Deferral drift gate:
- Command: `rg -n "broader UI verification discipline|SEED-003 ecosystem integrations|whole-suite no-search-path" .planning/ROADMAP.md .planning/REQUIREMENTS.md .planning/PROJECT.md .planning/STATE.md`
- Required behavior: active planning artifacts continue to keep broader UI verification discipline, ecosystem integrations, and whole-suite no-search-path cleanup deferred.

Closeout handoff:
- Phase 140 prepares evidence for audit/archive.
- `/gsd-complete-milestone` performs milestone archive after Phase 140, not inside Phase 140 implementation.
