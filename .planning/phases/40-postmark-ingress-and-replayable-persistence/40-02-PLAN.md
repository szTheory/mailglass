| provider retries/manual retries -> idempotent storage | External retry behavior can repeatedly hit ingress and must not create duplicate receive truth. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-40-04 | Tampering | `MailglassInbound.Ingress.Persist` | mitigate | Use one `Repo.transact` / `Ecto.Multi` boundary so canonical and evidence rows succeed or fail together per D-40-13. |
| T-40-05 | Information Disclosure | `InboundEvidence` storage | mitigate | Keep raw payload, selected raw headers, verification facts, parse warnings, and attachment blobs in evidence only; never expand the canonical row or public struct with those fields per D-40-15 and D-40-16. |
| T-40-06 | Repudiation / Denial of Service | Postmark retry and duplicate handling | mitigate | Enforce the `(tenant_id, provider, provider_message_id)` idempotency anchor and return explicit duplicate outcomes so retries do not create new receive truth or repeated downstream work per D-40-14 and D-40-18. |
</threat_model>
