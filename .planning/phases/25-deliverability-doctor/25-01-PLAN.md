<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User-supplied `--domain` / selector input -> runtime contract | Untrusted CLI text becomes DNS lookup targets and result identifiers |
| OTP DNS responses -> result model | External DNS answers cross into operator-facing findings |
| Shared result model -> future JSON formatter | Internal data becomes a versioned machine contract |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-01 | Tampering | DNS-derived facts | mitigate | Normalize resolver output into closed reason/data shapes and keep raw facts separate from interpreted findings so later plans can show evidence without trusting malformed tuples. |
| T-25-02 | Denial of Service | resolver seam | mitigate | Convert DNS timeouts, NXDOMAIN, and malformed TXT/CNAME answers into `resolver_errors` data and `cannot_verify`-compatible inputs instead of raising. |
| T-25-03 | Integrity | result contract | mitigate | Close statuses to `pass|warn|fail|cannot_verify`, centralize summary counting in `Result`, and reject ad hoc status atoms that would drift the JSON/human contract. |
| T-25-04 | Information Disclosure | future machine output | accept | The result model contains only domain-level DNS facts and remediation copy, not message bodies, recipients, or tenant secrets. |
</threat_model>
