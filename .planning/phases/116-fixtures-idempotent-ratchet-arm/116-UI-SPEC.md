## Spacing Scale

**[SOURCE: design-system.md — `@theme` block, 4px grid, tokens are canonical]**

|-------|-------|-------|

| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |

| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

class is a SPACE-GATE failure. This gate already runs in CI — do not introduce violations when
authoring the 6 net-new Bucket-A guards.

## Typography

**[SOURCE: design-system.md — `@theme` type scale; weights 400 and 700 only]**

| Role | Token | Size | Weight | Line Height |
|------|-------|------|--------|-------------|
| Label | `text-label` | 12px | 400 (default) | 1.5 |
| Body | `text-body` | 14px | 400 (default) | 1.5 |
| Heading | `text-heading` | 20px | 700 (`font-bold`) | 1.2 |
| Display | `text-display` | 28px | 700 (`font-bold`) | 1.2 |

**Weight enforcement (non-negotiable):** Only `font-bold` (700) or the default (400) are valid.
`font-medium` (500) and `font-semibold` (600) are NOT loaded — the browser synthesizes faux-bold,
which is a conformance failure caught by the TYPE-GATE. Raw `text-xl`, `text-lg`, `text-base` etc.
are banned; use the semantic token utilities only (`text-body`, `text-heading`, etc.).

**Phase 116 application:** Long Mailable module names and long delivery IDs (`del_01JXW…`) rendered
inside the `fjordline-aps` stress persona MUST use `text-label` or `text-body` at 400 weight with
CSS truncation (`truncate` / `overflow-hidden text-ellipsis`) — they must NOT overflow their
container. Non-ASCII characters (`"Bjørn Hansen"`, `"山田太郎"`) must render at the same token
sizes without font fallback artifacts.

## Color

**[SOURCE: design-system.md §1 Color — daisyUI semantic tokens; never raw hex in HEEx]**

| Role | Semantic Token | Light (Brand) | Dark | Usage |
|------|---------------|---------------|------|-------|
| Dominant (60%) | `base-100` | Paper `#F8FBFD` | resolved by daisyUI dark theme | App/detail surface, page background |
| Secondary (30%) | `base-200` | Mist `#EAF6FB` | resolved by daisyUI dark theme | Cards, list/filter panes, sidebar |
| Accent (10%) | `primary` | Glass `#277B96` | resolved by daisyUI dark theme | **Reserved elements only (see below)** |
| Destructive | `error` | Crimson (daisyUI) | resolved by daisyUI dark theme | Destructive actions only |

**Accent (`primary`/Glass) is reserved for exactly:**
1. Selected-row left border (`border-l-2 border-primary`)
2. Primary CTA buttons (`btn-primary`)
3. Active nav/timeline node highlight
4. Focus rings (`ring-primary` — resolves to Glass in light, Ice in dark per DARK-LD-03)

Accent must NOT appear on default borders, default badge backgrounds, or any non-interactive
decorative element. Status tints use opacity (`bg-warning/10`) — never new tokens.

**WCAG 2.2 AA constraint (RATCHET-03 / A16):** All text must achieve ≥ 4.5:1 contrast against its
background surface in ALL three theme modes (light, dark, system-dark). The axe baseline
(D-03 `axe-baseline.json`) is the durable enforcement artifact. Key verified contrast figures:
- `text-muted` on `surface-selected`: 6.66:1 (AA, light) — confirmed per STATE.md [86-01]
- Feedback backgrounds (dark theme): success-bg #142B22 (6.56), warning-bg #2B2314 (7.37),
  error-bg #2E1B1E (6.65), info-bg #11293A (11.18) — per STATE.md [86-01]
- `border-input` on selected surfaces: `border-input` < 3:1 resolved as a usage rule — form
  controls must never sit on selected rows (see STATE.md [86-01])

**System theme (A16-system):** The `system` theme must render contrast-equivalent to explicit `dark`
when `prefers-color-scheme: dark` is active. The axe scan for the `system` cell sets BOTH
`page.emulateMedia({ colorScheme: 'dark' })` AND app theme = system so the media-query branch is
genuinely exercised (mirrors Phase 109 precedent).

## Interaction Invariants

**[RATCHET-03 / D-01 — Binary pass/fail Playwright gates, NOT LLM-scored pillars]**

Each invariant is a true/false property verified in-browser by Playwright. The test name IS the
diagnosis. No screenshots. No pixel diffs.

### Invariant 1: Panel Above Scrim (existing gate, extended)

**What:** When a `[role=dialog]` panel is open, a centroid hit-test via `document.elementFromPoint`
returns the panel element or a descendant — not the scrim.

**Contract:** `hit === el || el.contains(hit)` must be truthy for every surface × theme combination.

**Parameterization:** deliveries modal (replay dialog), inbound modal, preview panel — in each of
light / dark / system theme.

**Extension from RATCHET-01:** Must also pass when the panel is opened against `fjordline-aps` data
(single-delivery surface) and against `northstar` data (high-count surface). The interaction
invariant must hold regardless of data density.

### Invariant 2: Scroll Chaining / Overscroll Contain

**What:** When the user scrolls a modal/panel to its end, the background document must not scroll.

**Contract:** After scrolling the overlay element to `scrollTop = scrollHeight`, assert
`window.scrollY` is unchanged.

**Parameterization:** Any surface where a scrollable modal/detail panel exists × light / dark /
system.

### Invariant 3: Focus Restore to Trigger

**What:** When a modal/panel closes, keyboard focus returns to the element that opened it.

**Contract:** After closing the overlay (via `phx-remove` / `JS.hide`), assert
`document.activeElement === triggerElement` (the element with `id=replay-open-btn` or equivalent
per STATE.md [Phase ?]).

**Parameterization:** Replay modal on deliveries × light / dark / system.

### Invariant 4: Layout Jump / CLS

**What:** Surfaces with loading states must not shift layout between the skeleton/loading state and
the settled/loaded state.

**Contract:** Capture a region's `getBoundingClientRect().height` in the loading state and in the
loaded state. Assert `|loaded_height - loading_height| ≤ threshold`.

**Threshold:** The precise pixel threshold is implementation discretion (see CONTEXT.md Claude's
Discretion) but must be ≤ 8px to be meaningful; 0px is ideal for synchronous surfaces.

**A22 synchronous-surface constraint:** Surfaces where data is available synchronously on mount
(inbound mount) must show NO skeleton at all — asserting 0px delta is the correct floor for these.
Surfaces with genuine async loading may show a skeleton, but `getBoundingClientRect().height` must
not jump when the skeleton is replaced.

## Accessibility Contract

**[RATCHET-03 / D-03 — axe-JSON baseline, schema_version: 1]**

### Axe Baseline Structure

File: `mailglass_admin/docs/axe-baseline.json`
Schema: `schema_version: 1` (distinct from the score baseline's schema_version 3)
Shape: `surface → theme → { total: <node_count>, rules: { <rule_id>: <node_count> } }`

| Axis | Values |
|------|--------|
| Surfaces | `deliveries`, `inbound`, `preview` |
| Themes | `light`, `dark`, `system` |
| Total cells | 9 (3 × 3) |

`[role=dialog]` overlay violations are folded into the surface that opened them — NOT a separate
surface. The 9-cell count is invariant.

### Scan Configuration

Tags: `['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa']`
Tool: `@axe-core/playwright ^4.11.2` (resolves to 4.11.3 as of 2026-06-20)
Theme emulation: `page.emulateMedia({ colorScheme: 'light|dark' })`; for the `system` cell set
BOTH app theme = system AND `colorScheme: 'dark'` so the media-query branch is genuinely exercised.

### Meet-or-Beat Contract

The axe comparator (`axe_baseline_test.exs`) enforces these invariants in CI:
1. `schema_version == 1` — hard assert
2. All 9 surface×theme cells present in BOTH `prior` and `current` — fail closed on missing cell
3. `prior.run_id != current.run_id` — anti-vacuity guard (a forgotten promotion fails loudly)
4. Per cell: `current.total ≤ prior.total` (zero-new-violation floor)
5. Per rule-id: `current.rules[rule_id] ≤ prior.rules[rule_id]` — a rule swap that keeps `total`
   flat but moves violations to a NEW rule still regresses
6. A rule-id present in `current` but absent in `prior` with `count > 0` is a regression even if
   `total` held flat

Failure message shape: `"inbound.dark: color-contrast 0 → 2 (REGRESSION)"`

**WCAG 2.2 AA target:** The axe baseline should land at zero violations across all 9 cells after
Phase 116 applies the Bucket-A accessibility fixes. This is the aspirational target; meet-or-beat
enforces it durably.

## Bucket-A Defect Closure Contracts

**[RATCHET-05 / D-11 — audit (verify-and-lock), not author-all-24]**

~18 of the 24 Bucket-A defects already have green guards from phases 109–115. Only 6 need net-new
guards. The visual/interaction contracts for those 6:

### A3: Hover on Non-Interactive Empty State

**Contract:** On the no-data surface (`helios-void` tenant direct URL), every element that has a
hover-triggered CSS transition must be `a`, `button`, `[role=button]`, `[phx-click]`, or
`[tabindex]`. Decorative elements in the empty state (icons, illustration copy, headings) must NOT
have hover transitions.

**Visual specification:** Empty states must use passive presentation — no hover-lift, no hover-color
change, no hover-border. Only the single CTA (if present) may have a hover state.

### A4 / A23: Floating Element Overlap of Primary CTA

**Contract:** When a floating element is open (theme menu, tooltip, flash notification), its
bounding rect must NOT overlap any `btn-primary` bounding rect on the same surface.

**Z-index layer enforcement (existing `--z-sticky/dropdown/overlay/modal/toast` = 10/20/30/40/50):**
- Flash (`z-toast` = 50) and modals (`z-modal` = 40) must not visually obscure `btn-primary`
  elements that are BELOW them in the stacking context unless the primary CTA is itself inside the
  modal.
- If a flash notification opens over a primary CTA, the CTA must be either (a) temporarily
  scrolled out of viewport or (b) the flash must be positioned so it does not overlap.

**Test approach:** Playwright `getBoundingClientRect()` intersection check per open floating element
vs each `btn-primary` rect.

### A16 (System): Dark Contrast Parity

**Contract:** The `system` theme with `prefers-color-scheme: dark` active must produce contrast
ratios ≥ 4.5:1 for ALL text/background pairs that pass in explicit `dark` theme. There must be no
regression in the `system` cell relative to `dark` cell.

**Verification:** Extend the axe baseline `system` cell scan as specified in Accessibility Contract
above. Parity check: `axe_system.total ≤ axe_dark.total` for each surface.

### A21: Loading-State CLS (Layout Jump)

**Contract:** See Invariant 4 in Interaction Invariants section above. Threshold ≤ 8px; 0px for
synchronous surfaces. Measured via `getBoundingClientRect().height` delta.

**Visual specification:** Loading skeletons must exactly match the height of the loaded content.
Use fixed-height skeleton placeholders (`h-4`, `h-6`, `h-8` at scale) that match the settled
layout dimensions. Never use `height: auto` or content-sized skeletons.

### A22: Skeleton Overuse on Synchronous Surfaces

**Contract:** A surface where data is guaranteed to be available on mount (synchronous render) must
show NO skeleton. Inbound mount is a confirmed synchronous surface.

**Visual specification:** The `mg-skeleton` class (`.phx-loading .mg-skeleton`) must not appear on
synchronous surfaces. The phx-loading/phx-connected CSS hook exists for genuinely async surfaces
only.

**Test:** Assert synchronous surfaces (inbound mount) have zero `.mg-skeleton` elements in the
settled DOM (after LiveView mount completes).

### A11: Table Overuse

**Contract:** `<table>` is appropriate only when data is genuinely tabular (multiple named columns
with row-level relationships). A `<table>` used as a layout device for a list of homogeneous items
is a violation.

**Audit artifact:** A per-`<table>` justification row in the Bucket-A coverage manifest
(`bucket_a_coverage_test.exs`), plus a count-must-not-increase grep inventory. The count of
`<table>` elements in `mailglass_admin/lib/` must not rise above its value at Phase 116 start.

## Copywriting Contract

**[SOURCE: STATE.md locked decisions COPY-LD-01..16; voice = "thoughtful maintainer"]**

The voice is: clear, exact, confident (not cocky), warm (not cute), technical (not intimidating).
"Oops" is the canonical anti-pattern — never permitted. Errors follow:
`"[Noun] [past-tense verb]: [specific cause]"`.

| Element | Copy |
|---------|------|
| Primary CTA (deliveries empty state) | "Configure your first Mailable" |
| Primary CTA (preview orientation) | "Preview the first Mailable" (STATE.md COPY-LD-05) |
| Deliveries empty state (no deliveries ever) | "No deliveries have been recorded yet." |
| Deliveries empty state (filters active) | "No deliveries match the current filters." |
| Inbound empty state (no records ever) | "No records have been recorded yet." |
| Inbound empty state (filters active) | "No records match the current filters." |
| `helios-void` tenant direct-URL empty state | "No deliveries have been recorded yet." (same copy — the empty-state rendering path is shared; tenant context is provided by the URL/session, not a separate copy variant) |
| Error state (generic pattern) | "[Resource] [past-tense verb]: [specific cause]" e.g. "Delivery failed: recipient is on the suppression list" |
| `reject_reason: nil` display | No reject-reason label rendered — nil is a legitimate absence, not an error to display |
| Non-ASCII name display | Rendered verbatim — `"Bjørn Hansen"`, `"山田太郎"` — no transliteration, no placeholder |
| Destructive: replay confirmation | "Replay delivery: This will re-dispatch the message to [provider]. Confirm?" |
| Destructive: any irreversible action | Name the action explicitly: "[Action]: [consequence]. Confirm?" |
| Banned words | "Oops", "Sorry", "Uh oh", "Hmm" — zero tolerance; voice_test.exs enforces this |

**Time window label (STATE.md COPY-LD-10):** "Time window" not "Window".

## Motion Contract

**[SOURCE: design-system.md — motion vocabulary; no new motions in Phase 116]**

Phase 116 does NOT introduce any new motion. All net-new guards and fixtures inherit the existing
motion vocabulary. Constraints that matter for Phase 116:

- The Bucket-A guard for A21 (CLS) must not introduce any height/width/padding transitions — the
  MOTION-GATE in `check-conformance.sh` bans these.
- Loading skeleton transitions use `transition-opacity duration-(--duration-reveal)` only.
- All transitions must honor `@media (prefers-reduced-motion: reduce)` — snaps to instant.
- The interaction pillar's CLS assertion (Invariant 4) must not be triggered by intentional motion.
  Use `waitForLoadState('networkidle')` or equivalent to measure the settled state, not a mid-animation frame.
