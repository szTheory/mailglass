<objective>
Close verification gap SC5 / INUX-06 (review WR-01): the Inbound evidence card's "Payload size" fact and its revealed raw source must describe the same stored field. Bundle advisory WR-03 (same file): announce a denied reveal from the persistent status region, as D-26 specifies. Bundle advisory IN-04 (same selector): a record with nothing stored has nothing to reveal, so, as D-26 says ("Not stored → keep 'No raw provider source was stored for this message.' and hide the button"), the card renders no reveal control and shows that sentence as static text. It never offers a reveal that would claim an empty payload, so its "Unavailable" size and its body agree (SC5).

Purpose: D-26 truth fixes. Phase 176 made the size raw_mime-first while the reveal stayed raw_payload-first, so for SES (which stores both) the card states the size of one field and reveals another.
Output: one shared source selector in `evidence_card.ex`, a both-fields regression test that fails before the fix, and a denial announced from the always-present region.

Precedence decision (reversible, recorded here and in the moduledoc): raw_payload-first, then raw_mime. Reasons: (1) it is the pre-phase order for BOTH functions (c96c8a4f), so the regression is undone rather than replaced; (2) the reveal already renders raw_payload first, so what an authorized operator sees does not change — the disclosure surface is identical before and after this fix (D-27); (3) the existing tests built on `raw_payload: %{}` plus a MIME (evidence_card_test "raw_mime backs the payload size (3 bytes, not 2)", retained scenario `evidence_large_revealed`, gallery "revealed") keep their meaning because an empty map falls through to the MIME. Review WR-01 sketched mime-first; that would change the revealed bytes for every SES and Mailgun record, which is a wider change than the gap requires.

Measurement decision: the size is the byte size of the exact revealed text. For a map payload that is the pretty JSON the `<pre>` shows, so `%{"a" => 1}` now reads 12 bytes instead of the compact 7. One existing assertion changes for that reason (see Task 1). This is an operator-visible value change: every stored record with a non-empty, encodable map payload (SES and Mailgun store one; see interfaces) shows a larger Payload size than Phase 176 showed before this plan, by the pretty-printing whitespace. The SUMMARY must flag it under its own "Operator-visible value change" heading with the before/after example, so release notes and verify-work do not read it as a regression.

Unencodable carve-out (one rule, matching D-26's encode-failure clause): a non-empty map payload that Jason cannot encode stays the selected source even when raw_mime is non-empty. Its size is "Unavailable"; the reveal shows the existing `inspect/2` fallback of that payload. The size is not measured from the inspect text, because that text is a debugging rendering rather than the stored bytes, and D-26 already says encode failure renders "Unavailable". The MIME is never consulted for size or reveal in that case, so size and reveal still name the same field.

Assumption-delta record (detector fired on roadmap prose "fallback", "multiple", "custom"): the one real singular-vs-plural question in this gap round is which of two stored raw fields is the primary source. Noun now primary: "raw source" = the selector result. Decision: `no-change` to the identity model (raw_payload stays primary, raw_mime is the fallback), now named in one function instead of two disagreeing ones. The both-fields test is the invariant test that goes red if a future change reintroduces two orders.
</objective>
