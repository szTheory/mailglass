<objective>
Close verification gap SC4 / INUX-05 (review WR-04): complete Inbound contact addresses must be exposed to assistive technology. Today every address renders only through `Components.copy_value/1`, whose `aria-label` ("Copy To address") replaces the visible address as the button's accessible name.

Purpose: WCAG 2.5.3 Label in Name (level A). The visible text of a control must be contained in its accessible name.
Output: `copy_value/1` names its button "Copy <label>: <value>", a component test, a contact-list test over every contact button, and the browser specs that located copy controls by the old exact name.

Decision (reversible, no owner question): fix the shared component, not only the Inbound header. Every `copy_value` call site shows its value as the button text, so all of them had the same Label-in-Name defect; a per-site opt-in would leave the IDs failing the same rule. The "<label>: <value>" shape follows the existing timestamp copy control in the same file. The visible text, `data-copy-value` and the toast are unchanged, so behaviour for sighted users does not change.
</objective>
