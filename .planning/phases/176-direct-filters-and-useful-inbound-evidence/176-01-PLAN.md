<objective>
Prove the phase architecture on one real path: Deliveries filters commit on change with an Enter commit, history is useful, and the Account stays server-held.

Purpose: tracer-first. One thin, production-quality slice through the LiveView commit path and a connected browser, then the pure history policy (`FilterCommit` truth table + unit tests) wired behind it, before the debounced search/focus hook (plan 176-06), Inbound (plan 176-07) and the read-state work (plan 176-04) build on it.
Output: `FilterCommit` module + unit tests, rewired `OperatorLive` commit path with history policy, accessible mobile Filters toggle, connected tracer on LV 1.2.13.

Scope split (checker iteration 1, W8): Task 1 wires the select path end-to-end and creates only the `FilterCommit` functions that path needs; Task 2 owns the pure `history_kind/2` truth table and every `filter_commit_test.exs` unit test plus the history wiring; the debounced search input and the `FilterSearchSync` spike moved to plan 176-06.

Orchestrator decisions recorded here (rationale):
- Decision 1 (D-08 "drop defaults"): canonical URLs drop only blank values and page=1. `window_hours=168` stays because `operator_live_test.exs:200-209` is an existing URL contract and `same_location?` compares decoded queries, so dropping it would cause a spurious replace on every commit. Keys are explicitly sorted with `Enum.sort/1`; search is trimmed at commit time.
- Decision 2: Operator `support_state` is carried through filter commits (it is neither page nor selection), which keeps `e2e/phase168-plan03-acceptance.spec.js:171` truthful. Clear filters keeps its existing support-state behavior.
- Decision 5 (D-06 Enter): Enter pushes except when it finalizes an in-flight search edit whose debounced commit already created this intent's history entry (last kind `:search`) — then `:replace`. Encoded in the `history_kind/2` truth table.
- Decision 7: the hook's `updated()`-on-focused-input behavior (A2/A3) is proven by plan 176-06's spike on both clients before any dependent hook work (plan 176-07). If the spike disproves it, plan 176-06 ships the server-driven fallback described there; no human checkpoint.
- Bundle ownership (I10): this plan does not own `mailglass_admin/priv/static/app.css` (plan 176-02 rewrites it in the same wave). The operator-browser script rebuilds the bundle before Playwright, so this plan uses only utilities already present in the committed bundle and never stages or commits `priv/static/app.css` (stage files by explicit path only). The bundle-clean assertion lives in plan 176-10 Task 3 (`mix mailglass_admin.assets.build && git diff --exit-code priv/static/`).
- Decision 8: zero human UAT (D-52); every check below is automated.
