<objective>
Build the one sanctioned door for sandbox ownership, with the invariant that makes the acquire/release bug
structurally impossible to re-type, plus the deterministic mechanism-level regression test D-04 requires.

The two confirmed leak sites share one shape: **acquire → work that can raise → register release**, and
**release-last inside a teardown whose earlier statements can raise**. `test/support/data_case.ex:35-36` is
the control — the `on_exit` is the next statement after `start_owner!`. `checkout!/1` generalises that
control and makes it the only way in.

Purpose: fixing the two known sites leaves the pattern re-typable and fails SEED-007's Definition of Done
#3. Centralising behind one helper is the fix (D-06).
Output: the full `SandboxOwnership` public surface, its async-policy guards, its `LeakError`, and a
regression test that proves the mechanism against the real repo.
</objective>

Grow `Mailglass.TestSupport.SandboxOwnership` into the full public surface. Keep everything in
`test/support/` — never `lib/`, never `dev/`.

Define an exception `Mailglass.TestSupport.SandboxOwnership.LeakError` with `defexception`, carrying at
minimum the offending module, the observed pool state, and a composed message. This is the error the
Wave-3 classifier counts alongside the raw `MatchError` term; without it, replacing the raw badmatch would
launder the signature and make ROADMAP criterion 3 pass vacuously. Say that in the exception's `@moduledoc`.

Public functions, each with a `@spec` and a `@doc`:

- `checkout!/1` — takes the same option list `Ecto.Adapters.SQL.Sandbox.start_owner!/2` takes, defaulting
  the repo to `Mailglass.TestRepo`. Its non-negotiable invariant: call `start_owner!/2`, then on the
  **immediately following statement** register `ExUnit.Callbacks.on_exit/1` with the release. Every
  statement the helper performs after that point sits below the registration, so a raise anywhere below
  still releases. Inside the `on_exit`, match `Sandbox.stop_owner/1`'s return rather than discarding it,
  and when the checkout was shared, follow it with `assert_manual!/2` so the release is verified rather
  than assumed. Returns the owner pid. Comment the ordering as the invariant, not as a style preference.
- `unsandboxed_module/1` — an ExUnit `setup` callback (arity 1, taking the context) that switches the pool
  to `:auto` for the whole module and registers the revert to `:manual` on the immediately following
  statement. Because `on_exit` callbacks run in reverse registration order, a registration made first here
  runs **last**, which preserves today's semantics for the nine `:auto` files: each file's own
  baseline-restore `on_exit` (registered later) still runs while `:auto` is in effect. Document that
  ordering guarantee in the `@doc`, because plan `143-06`'s migrations depend on it.
- `unsandboxed/2` — wraps `Ecto.Adapters.SQL.Sandbox.unboxed_run/2`. Document it as the **preferred forward
  idiom** for a new test needing committed writes: process-local rather than pool-global, which removes the
  bug class. Document equally plainly that it cannot replace pool-wide `:auto` where
  `Ecto.Migrator.with_repo/2` spawns a process `unboxed_run` cannot cover.
- `assert_manual!/2` — takes a repo and a caller identifier; probes the pool and raises `LeakError` when it
  was not `:manual`, naming the caller.
- `live_holder/0` — returns the currently-registered shared owner pid when the pool is shared and that pid
  is alive, otherwise `nil`. Key it on the **pool mode**, not on agent liveness: after a timeout-driven heal
  the zombie Agent is still alive but holds no connection and no mode, so a liveness-keyed reader would
  misreport. Say so in the `@doc`.

Async-policy guards. Both `checkout!/1` with `shared: true` and `unsandboxed_module/1` must raise when
called from a module whose `async` tag is true. Copy the microcopy shape of the I-12 guard at

Expose an injectable seam for the failure paths the way `CitextProbe` exposes `probe_fun:`, so the guard

Do not rescue `MatchError` anywhere. Do not change `probe/1`'s or `baseline_tables_present?/1`'s existing

Write `test/mailglass/test_support/sandbox_ownership_test.exs` as the deterministic, mechanism-level
regression test. Use `use ExUnit.Case, async: true` so the test module does not itself acquire the sandbox
through a case template, and drive `Ecto.Adapters.SQL.Sandbox` directly. This file plus the helper are the
only two the Credo check in plan `143-08` allowlists — note that in the moduledoc so a future reader does
not "clean up" the direct calls.

Because these tests mutate pool-global state, tag the module so it cannot run concurrently with anything
that shares the pool, and restore the pool to `:manual` in an `on_exit` registered before any statement
that can raise — this file must obey the invariant it is testing.

Pin all four branches of the mechanism, each as its own named test:

1. **Leak reproduces.** Start a shared owner and abandon it (do not stop it). Assert the next
   `start_owner!(TestRepo, shared: true)` fails, and assert on the **verbatim nested term** —
   `{:error, {{:badmatch, :already_shared}, _stack}}` reached through the outer match at `sandbox.ex:451` —
   not on a message string. CLAUDE.md forbids pattern-matching errors by message. Include the assertion
   message explaining that a top-level match on the badmatch tuple would match nothing.
2. **`shared: false` survives.** With the same leaked owner live, assert `start_owner!(TestRepo, shared: false)`
   succeeds, because `sandbox.ex:460` takes the `allow/3` branch instead. This is D-01's falsifiable
   prediction #3 pinned as a permanent regression test.
3. **`stop_owner/1` heals.** Stop the leaked owner and assert the pool probes clean and a fresh shared
   acquisition succeeds.
4. **`mode(repo, :auto)` heals.** With a fresh leak, assert a switch to `:auto` and back to `:manual`
   clears the shared mode, and a fresh shared acquisition succeeds. This is the behaviour that makes seed
   bisection converge on the wrong pair, and it is why the leaker and its victim are not adjacent.

Add tests for the helper's own contract:

5. **Release-first.** Tag this test `@tag :release_first` so it is individually runnable. Call `checkout!/1`
   in a process, raise from a callback registered to run after it, and assert the owner was released
   anyway — the invariant is that a raise below the registration line still releases.
6. **Async guard raises.** Assert `checkout!(shared: true)` and `unsandboxed_module/1` each raise from an
   `async: true` context, with `assert_raise` anchored on the message prefix, and assert the message names
   the one-line edit that fixes it.
7. **`assert_manual!/2` raises `LeakError`** on a shared pool and returns `:ok` on a manual one.
8. **`live_holder/0`** returns the owner pid while shared and `nil` after a heal, keyed on pool mode.

Do not claim, in this file or its moduledoc, that these tests reproduce the full-suite failure. They pin the
mechanism; the full-suite behaviour is bounded by the healing paths and is not deterministic across seeds.
