<objective>
Exercise the gate for real without publishing anything, then record the decision the phase goal asks for.

The milestone ships no Hex release, so the gate change would otherwise land unexercised. The rehearsal pair
closes that: a positive run proving a green gate permits the publish path, and a negative run proving a red
gating leg blocks it. The negative is the one the goal criterion actually asks for — "demonstrably blocks a
Hex publish (not merely a PR merge)."

The ordering constraint is not incidental. Both the pre-publish summary job and the publish job check out the
dispatched tag, and a dispatch runs the workflow file as it exists at that ref. Dispatching against an
existing release tag would run the old gate and prove nothing. The throwaway tag is created **after** the
gate change is on `main`.

Purpose: the phase goal asks for "a recorded, evidence-backed answer to whether it should gate a release."
This plan produces the evidence and the record.
Output: two rehearsal run URLs, two deleted tags, and a decision record.
</objective>
