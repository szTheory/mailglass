<objective>
Make the deliberate-failure probe usable against a non-required lane, and capture the finding that it has
been vacuous against `CI Green` since it was written.

HARNESS-03 requires "a deliberate-failure probe following the existing `gate-self-test.yml` pattern pointed
at Core Full Suite." Research proved the workflow cannot do that today: its poll loop passes `--required` to
`gh pr checks`, branch protection's required set is exactly `{CI Green, Guard Release Trigger}` (locked by
`required_checks_test.exs:45-58` and kept that way by D-26), so `Core Full Suite (` would never appear and
the run would burn 25 minutes and exit 1 with `result=timeout`.

Purpose: build the probe capability now, in parallel with the instrumentation track, so it is ready the
moment the lane is renamed and green.
Output: two new `workflow_dispatch` inputs, a distinct never-appeared outcome, a recorded D-18a finding, and
the run URL proving it.
</objective>

  <action>
Extend the existing workflow. Do not rebuild it — it already handles stale-branch cleanup, the failing-test
injection, the draft PR, fail-closed-on-SUCCESS, and orphan-branch teardown.

Add two `workflow_dispatch` inputs alongside the existing `cleanup_only` and `check_name`, following the
`check_name` declaration shape at `:19-22`:

- `required_only` — `type: boolean`, `default: true`. Description states that the default preserves today's
  behaviour (poll only branch-protection-required contexts) and that `false` is needed to observe an
  advisory-matrix lane, because branch protection's required set is exactly `{CI Green, Guard Release
  Trigger}` and a matrix lane will never appear in it.
- `deadline_minutes` — `type: string`, `default: "25"`. Description states this is the poll deadline and
  that a cold-cache Core Full Suite leg runs roughly ten and a half minutes, so the default has headroom.

Bind both through the poll step's existing `env:` block next to `GH_TOKEN`, `PR`, and `CHECK_NAME` — as
`REQUIRED_ONLY` and `DEADLINE_MINUTES`. Never interpolate `${{ inputs.* }}` directly into the `run:` body.

Rewrite the poll loop so that:

- The `gh pr checks` invocation includes the `--required` flag only when `REQUIRED_ONLY` is `true`. Build
  the flag into a shell variable and expand it; keep the `--json name,state` and the `startswith` jq filter
  byte-identical otherwise.
- `DEADLINE=$((SECONDS + DEADLINE_MINUTES * 60))` replaces the hardcoded `1500`.
- The loop tracks whether the polled check was ever *seen*. Each iteration additionally captures the full
  observed check list (`gh pr checks "$PR" --json name,state`, honouring the same required flag) into a
  variable; set a `SEEN=1` marker the first time the filtered status is non-empty.
- On deadline, branch on `SEEN`. If the check was seen at least once, keep today's behaviour:
  `result=timeout`, exit 1. If it was never seen, emit the new distinct outcome `result=never-appeared`,
  print the full observed check list so the failure names itself, and exit 1. Both remain fail-closed.

Extend the summary step to render the `never-appeared` outcome. Follow the existing microcopy: the failure
lines use the literal prefix `Delivery blocked: ` and then name the cause and the recovery. For
`never-appeared`, the recovery line names the exact re-dispatch command including
`-f required_only=false`. Do not replace the existing `blocked` / `leaked` / `timeout` summary text.

Do not add a `schedule:` trigger. Do not change the `permissions:` block. Do not touch the injection point,
the branch naming, or the cleanup logic.
