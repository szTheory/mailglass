<objective>
Prove the lane catches a real regression, then hold a blocking checkpoint before anything gains veto power
over a Hex publish.

ROADMAP criterion 3's third clause asks for a deliberate-failure probe against Core Full Suite confirming the
lane still catches a real, deliberately-injected regression. Plan `143-02` built the capability and recorded
that the existing probe was vacuous against the aggregate required check. Plan `143-11` gave the lane a name
that no other lane is a prefix of. This plan runs the probe for real.

Then the five-condition promotion checkpoint. Its bar is deliberately not "merged" — it is **observed green
in the shape the gate will actually read it**. The tag-shaped-ref condition in particular is the only proof
of the exact code path the gate uses, and the one nobody would think to run.

Purpose: a gate that can block every future release is not a change to make on a lane that has been green
once.
Output: a `result=blocked` run URL and a pasted five-condition checkpoint record.
</objective>

Dispatch `gate-self-test.yml` against the renamed lane with non-required polling enabled and a deadline with

Use the lane's name prefix — the renamed gating job's display name up to and including its opening
parenthesis — as the check name, so the probe matches an interpolated runtime name on the pull-request run

branch creation, PR opening, and job scheduling.

`mix test` invocation, the lane goes red, and the probe reports that the gate caught it.

Record in `143-PROBE-EVIDENCE.md`, in the section plan `143-02` reserved: the dispatch command verbatim
including both input values, the run URL, the `result` value, the observed lane conclusion, and the PR
number the probe opened. Then confirm cleanup: no `gate-self-test/` branch and no open `gate-self-test/` PR
remains.

stop and investigate before anything else. If the outcome is `timeout` or `never-appeared`, the probe could
not observe the lane; read the observed check list it printed, correct the name prefix or the required-only
setting, and re-run. Neither is an acceptable substitute for a blocked result, and neither may be recorded
as "inconclusive but probably fine".
