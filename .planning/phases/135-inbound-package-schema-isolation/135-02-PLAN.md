head (D-10).

files removed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator `:schema` config → raw `CREATE SCHEMA`/`DROP SCHEMA`/`COMMENT ON TABLE` interpolation | The `:schema` value is interpolated into unquoted-identifier DDL in the runner. This is the one raw-interpolation surface in the phase (D-10 — V01 has no other raw DDL). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-135-03 | Tampering (SQL injection) | `CREATE SCHEMA`/`DROP SCHEMA`/`COMMENT` interpolation in `Migrations.Postgres` | high | mitigate | Every interpolation is gated through `Mailglass.Identifier.validate!/2` (regex + 63-byte NAMEDATALEN guard) before `inspect/1` (D-11). The value is operator app-env config, not request input; validated again at boot in Phase 132. |
| T-135-04 | Denial of Service | `DROP SCHEMA … CASCADE` silently nuking adopter objects | medium | mitigate | `DROP SCHEMA IF EXISTS … RESTRICT` (never CASCADE) — a non-empty schema fails loudly (D-11), and the drop fires only on full teardown to version 0 and only when inbound created the schema. |
| T-135-05 | Tampering | version-anchor collision between core + inbound in a shared schema | low | mitigate | Inbound anchors its version comment on `mailglass_inbound_records`, core on `mailglass_events` — fully independent version lines even in one shared schema (D-07). |
| T-135-SC | Tampering | npm/pip/cargo installs | low | accept | No new package-manager installs in this phase — pure `mailglass_inbound` lib code + migration files. No package legitimacy gate needed. |
</threat_model>
