## Implementation Decisions

### Status map (BRPOL-02)
- **D-01:** The universe is **26 atoms, not 25**. The 25 are the `attr :status` values on `MailglassAdmin.Components.status_badge/1` (`mailglass_admin/lib/mailglass_admin/components.ex` ~1360-1388, labels 1722-1746). The 26th is `:subscribed`, a real `Mailglass.Events.Event.__types__/0` member with no badge clause (it falls to "Unknown" today). Classify it "not a delivery status". The module doc says why, so nobody "fixes" 26 back to 25. A plan task amends the "25" wording in BRPOL-02 and the ROADMAP success criterion to 26.
- **D-02:** `MailglassAdmin.StatusMap` is a **pure module in `mailglass_admin`, not core**. Core is public API and brand words in core would become contract. Classes: `:sent | :delivered | :delayed | :failed | :not_sent | :not_a_delivery_status`. One compile-time `%{atom => class}` table, `classify/1` generated by comprehension with **no catch-all clause**. A separate UI-only `classify_or_unknown/1` carries the fallback, and `nil` and unmapped atoms fail loudly in tests.
- **D-03:** Classification:

  | Class | Atoms |
  |---|---|
  | Sent | `:dispatched`, `:sent`, `:queued` |
  | Delivered | `:delivered` |
  | Delayed | `:deferred` |
  | Failed | `:failed`, `:bounced`, `:rejected` |
  | Not sent | `:suppressed` |
  | Not a delivery status | `:complained`, `:unsubscribed`, `:opened`, `:clicked`, `:autoresponded`, `:unknown`, `:subscribed`, `:accepted` (inbound mailbox-accept, never Sent), `:no_match`, `:ignore`, `:no_change`, `:missing_history`, `:failed_ingest`, `:reconciled`, `:webhook_replay_requested`, `:webhook_replay_succeeded`, `:webhook_replay_failed` |

  `:queued` is pre-handoff, so its class is Sent only with a qualifier; its on-screen label wording is Phase 182's job, constrained to never read "Delivered" or imply handoff succeeded. `:complained` and `:unsubscribed` as "not a delivery status" is a judgment call, recorded here as the default (veto-able, cheap to change because only the map moves).
- **D-04:** The coverage test **enumerates atoms from source, never from a hand-copied list**: union of `Event.__types__/0`, `Ecto.Enum.values(Delivery, :status)`, `Delivery.__event_types__/0`, the `status_badge` attr values, and inbound outcomes through `Components.normalize_inbound_outcome/1`. Assert `Map.keys(table) == universe` in both directions (unmapped atom fails, stale key fails). Include a detector self-test with a synthetic unmapped atom. Prefer `Components.__components__()` attr introspection for the badge values; fall back to a source grep of the `values:` list if the attr metadata does not expose it (planner verifies).
- **D-05:** Atom class is not enough. `delivery_display_status/1` (`components.ex` ~1528) returns the latest event, so a late `:opened`/`:clicked` hides `:delivered` and those atoms are "not a delivery status". Add a pure `StatusMap.delivery_class(delivery)` that uses `delivered_at`, `bounced_at`, `terminal` and `status`, so engagement never implies delivered and never erases it. Not wired to screens in this phase (Phase 182 consumes it). Planner confirms the projection fields exist and are populated on the rows the password-reset job uses.
- **D-06:** **"Not sent" is a pre-send block only; no library code persists `Delivery.status :suppressed`.** Recorded answer for BRPOL-02, settled from code:
  - `Outbound.send/2` and `deliver_later/2`: `lib/mailglass/outbound/preflight.ex:12-14` -> `lib/mailglass/suppression.ex:41-46,66-79` returns `{:error, %SuppressedError{}}`, emits `[:mailglass,:suppression,:pre_send_blocked,:stop]`, and `outbound.ex` (~277-283, ~316-320) short-circuits before any insert. Pinned by `test/mailglass/outbound/deliver_later_test.exs:203`.
  - `deliver_many/2`: `outbound.ex:339-366` builds an in-memory `%Delivery{status: :failed}` via `Persistence.build_failed_delivery/2` (`persistence.ex:218-230`), never inserted. Pinned by `deliver_many_test.exs:187-211`.
  - Status writers are only `persistence.ex` (`:queued`, `:sent`, `:failed`); `Projector.update_projections` (`projector.ex:48-121`) never writes `status`; no lib code appends an Event of `type: :suppressed`. Only fixtures (`mailglass_admin/test/support/operator_fixtures.ex:136-146`, `demo_data.ex`) produce `:suppressed` rows.
  - **Consequences:** `:suppressed` still maps to Not sent (the enum member and event type are reserved and dormant), but real data will not produce it yet. A send-time `:failed` (including the batch in-memory struct) reads Failed, **never** "Not sent". "Not sent" for suppression belongs where the suppression card and entry are shown (`mailglass_admin/lib/mailglass_admin/operator/suppression_card.ex`), not as an Activity row promise.
  - Add a new DB-backed test that delivers to a suppressed address and asserts **zero `Delivery` rows and zero events**, so the recorded answer is machine-proven. (Existing tests assert only the raise and the error return.)

## Specific Ideas

- The book itself says (`toReview`) no trademark or look-alike search was run, including against well-known sign marks, and that logo and book are MIT "unless the repository says otherwise". BRPOL-05 is a real gate, not paperwork.
- Cross-language evidence for the five statuses: Postmark (Delivered = recipient server accepted, not inbox; UI "Delayed"), SendGrid (Dropped = no attempt, Deferred carries SMTP response), Resend (`suppressed` = never attempted; `sent` blurs handoff/delivered). Good designs keep Delayed separate from Failed and suppression separate from bounce; mailglass stores no retry time, so Delayed must never promise a retry.
- Documented real-world bug class: late events overwriting `delivered` (hence D-05).
- Another copy beats another dep: no YAML or hashing dependency; `:crypto` and Jason already exist.
</specifics>
