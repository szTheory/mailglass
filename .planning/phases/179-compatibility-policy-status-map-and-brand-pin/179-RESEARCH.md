#### Status map (BRPOL-02)
- **D-01:** The universe is **26 atoms, not 25**. The 25 are the `attr :status` values on `MailglassAdmin.Components.status_badge/1` (`mailglass_admin/lib/mailglass_admin/components.ex` ~1360-1388, labels 1722-1746). The 26th is `:subscribed`, a real `Mailglass.Events.Event.__types__/0` member with no badge clause (it falls to "Unknown" today). Classify it "not a delivery status". The module doc says why, so nobody "fixes" 26 back to 25. A plan task amends the "25" wording in BRPOL-02 and the ROADMAP success criterion to 26.
- **D-02:** `MailglassAdmin.StatusMap` is a **pure module in `mailglass_admin`, not core**. Core is public API and brand words in core would become contract. Classes: `:sent | :delivered | :delayed | :failed | :not_sent | :not_a_delivery_status`. One compile-time `%{atom => class}` table, `classify/1` generated by comprehension with **no catch-all clause**. A separate UI-only `classify_or_unknown/1` carries the fallback, and `nil` and unmapped atoms fail loudly in tests.
- **D-03:** Classification:

  | Class | Atoms |
  |---|---|
  | Sent | `:dispatched`, `:sent`, `:queued` |
  | Delivered | `:delivered` |
  | Delayed | `:deferred` |
  | Failed | `:failed`, `:bounced`, `:rejected` |
  | Not sent | `:suppressed` |
  | Not a delivery status | `:complained`, `:unsubscribed`, `:opened`, `:clicked`, `:autoresponded`, `:unknown`, `:subscribed`, `:accepted` (inbound mailbox-accept, never Sent), `:no_match`, `:ignore`, `:no_change`, `:missing_history`, `:failed_ingest`, `:reconciled`, `:webhook_replay_requested`, `:webhook_replay_succeeded`, `:webhook_replay_failed` |

  `:queued` is pre-handoff, so its class is Sent only with a qualifier; its on-screen label wording is Phase 182's job, constrained to never read "Delivered" or imply handoff succeeded. `:complained` and `:unsubscribed` as "not a delivery status" is a judgment call, recorded here as the default (veto-able, cheap to change because only the map moves).

## Summary

Phase 179 is three file-disjoint pieces of governance, all verifiable with plain ExUnit and no new dependency. (1) A pure `MailglassAdmin.StatusMap` plus a `MailglassAdmin.Copy` table that replaces 78 one-line `defp` clauses in `components.ex` with zero visible change, guarded by a three-layer contract test and a recorded mutation run. ### Pattern 1: Pure atom table with no catch-all (BRPOL-02)
**What:** one compile-time `%{atom => class}` and `classify/1` generated by `for`, so an unmapped atom raises `FunctionClauseError`. `classify_or_unknown/1` returns `:unknown` (not a seventh class) for the UI.
**When to use:** StatusMap only. The six classes stay a closed set.
**Example:** see Code Examples 1. [VERIFIED: universe and table cardinalities computed from source this session]

### Pattern 2: One table, three delegating defps (BRPOL-03)
**What:** `Copy` owns `%{atom => %{label, icon, class}}` for the 25 badge atoms. `components.ex` keeps `defp status_label(s), do: Copy.status_label_or_unknown(s)` (and icon/class), preserving today's fallback (`"Unknown"`, `"hero-question-mark-circle"`, `"badge-outline"`). `Copy` asserts at compile time that its keys equal `StatusMap.atoms() -- [:subscribed]`.

[VERIFIED: `components.ex:1528-1542` and `components_test.exs` "subscription feedback preserves confirmed delivery"]

### Pattern 3: `delivery_class/1` over the real row shape (BRPOL-02, D-05)
**What:** operator rows expose exactly `status`, `last_event_type`, `delivery_confirmed` (plus ids/times). Define precedence over those three. Recommended precedence: (1) `last_event_type in [:bounced, :rejected, :failed]` -> `:failed`; (2) `status == :suppressed or last_event_type == :suppressed` -> `:not_sent` (dormant); (3) `delivery_confirmed == true or last_event_type == :delivered` -> `:delivered` (engagement and complaints never erase it); (4) `status == :failed` -> `:failed`; (5) `last_event_type == :deferred` -> `:delayed`; (6) otherwise `:sent` (handed off, queued, or engagement with no delivery report, so engagement never implies delivered). **Evidence:** `delivery_projection` selects `status`, `last_event_type`, `delivery_confirmed: not is_nil(delivery.delivered_at)`, no `terminal` or `bounced_at`. [VERIFIED: `lib/mailglass/operator/deliveries.ex:119-134`] Projector sets `delivered_at`/`bounced_at` once and `terminal` as a latch. ### Anti-Patterns to Avoid
- **Deriving `attr values:` from `StatusMap`:** makes the oracle circular (see Alternatives).
- **A catch-all in `classify/1`:** silently classifies `:subscribed` or a new atom.
- **Time-dependent CI assertions on `expires`:** guarantees a future red. Inject `today`.
- **A skip-if-no-zip online test:** passes silently and needs a `config/test_exceptions.exs` entry.
- **Hand-editing `.planning/publish/*-files.expected`:** ordering is generated; copy `_publish_check/<pkg>-files.actual`.
- **Planning tokens in new lib comments or docstrings** (`D-07`, `Phase 182`, `Plan 2`, `GSD`, `REQ-...`): the files ship in the Hex tarball.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| sha256 | custom hashing | `:crypto.hash(:sha256, bin) \|> Base.encode16(case: :lower)` | verified this session against the real zip |
| Zip reading | shell `unzip` + path joins | `:zip.zip_open(bin, [:memory])` + `:zip.zip_get/2` for allow-listed names only | no extraction to disk, no zip-slip surface |
| TLS download | `curl` shell-out in a test | `:httpc` with `verify: :verify_peer`, `cacerts: :public_key.cacerts_get()` | executed against the pinned URL |
| JSON read/write | string concatenation | `Jason.decode!`, `Jason.OrderedObject` for stable key order | `scripts/reconcile_release_versions.exs` precedent |
| Atom universe | a hand-copied list | `Event.__types__/0`, `Ecto.Enum.values/2`, `Delivery.__event_types__/0`, `Components.__components__()`, `ExecutionRun.__outcomes__/0` | the whole point of D-04 |
| Visible-text extraction | regex over HTML | `Floki.parse_fragment!` + `Floki.filter_out("script")` + `Floki.text(sep: " ")` | Phase 175 helper, avoids the phoenix.mjs "noops" false positive |

defmodule MailglassAdmin.StatusMap do
  @moduledoc false
  # 26 atoms: the 25 badge atoms plus :subscribed (a real Event type with no badge).
  # Classes describe outbound delivery meaning. Inbound outcome atoms share names
  # (:rejected, :bounced, :failed) but are mailbox outcomes, not delivery statuses.
  @classes [:sent, :delivered, :delayed, :failed, :not_sent, :not_a_delivery_status]

  @table %{
    dispatched: :sent, sent: :sent, queued: :sent,
    delivered: :delivered,
    deferred: :delayed,
    failed: :failed, bounced: :failed, rejected: :failed,
    suppressed: :not_sent,
    complained: :not_a_delivery_status, unsubscribed: :not_a_delivery_status,
    opened: :not_a_delivery_status, clicked: :not_a_delivery_status,
    autoresponded: :not_a_delivery_status, unknown: :not_a_delivery_status,
    subscribed: :not_a_delivery_status, accepted: :not_a_delivery_status,
    no_match: :not_a_delivery_status, ignore: :not_a_delivery_status,
    no_change: :not_a_delivery_status, missing_history: :not_a_delivery_status,
    failed_ingest: :not_a_delivery_status, reconciled: :not_a_delivery_status,
    webhook_replay_requested: :not_a_delivery_status,
    webhook_replay_succeeded: :not_a_delivery_status,
    webhook_replay_failed: :not_a_delivery_status
  }

  def classes, do: @classes
  def atoms, do: @table |> Map.keys() |> Enum.sort()
  def table, do: @table

  for {atom, class} <- @table do
    def classify(unquote(atom)), do: unquote(class)
  end

  def classify_or_unknown(atom) do
    classify(atom)
  rescue
    FunctionClauseError -> :unknown
  end

  def delivery_class(%{} = row) do
    status = Map.get(row, :status)
    last = Map.get(row, :last_event_type)
    confirmed? = Map.get(row, :delivery_confirmed) == true

    cond do
      last in [:bounced, :rejected, :failed] -> :failed
      status == :suppressed or last == :suppressed -> :not_sent
      confirmed? or last == :delivered -> :delivered
      status == :failed -> :failed
      last == :deferred -> :delayed
      true -> :sent
    end
  end
end

### 5. Pin verifier core (offline)
```elixir
def verify(pin, read_file, list_dir) do
  issues =
    for %{"to" => to, "sha256" => want, "bytes" => bytes} <- pin["shipped"],
        issue <- case read_file.(to) do
          {:ok, data} when byte_size(data) != bytes -> [{:asset_size_mismatch, to}]
          {:ok, data} -> if sha256_hex(data) == want, do: [], else: [{:asset_hash_mismatch, to}]
          {:error, _} -> [{:asset_missing, to}]
        end,
        do: issue

  listed = MapSet.new(pin["shipped"], & &1["to"])
  unlisted =
    for dir <- pin["owned_dirs"], f <- list_dir.(dir), f not in listed, do: {:asset_unlisted, f}

  case issues ++ unlisted do
    [] -> :ok
    errs -> {:error, errs}
  end
end
```
