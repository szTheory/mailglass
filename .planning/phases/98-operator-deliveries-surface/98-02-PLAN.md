<resolved_decisions>
- **1440 breakpoint (Research A1):** use the arbitrary variant `min-[1440px]:grid-cols-[33%_67%]`
  for literal-1440 fidelity (IA-LD-03 says "at 1440"), UNLESS that arbitrary breakpoint trips a
  conformance grep gate. check-conformance.sh GAP-GATE matches `gap-3/4/6` and HEX-GATE matches
  `color…#hex` — neither matches `min-[1440px]:` or `grid-cols-[33%_67%]`. So `min-[1440px]:` is
  safe and is the chosen utility. The structural spec (Plan 04) asserts computed grid-template-columns
  at viewport 1440. Full grid class: `grid gap-lg md:grid-cols-[40%_60%] min-[1440px]:grid-cols-[33%_67%]`.
- **390px reveal-with-back (D-01/IA-LD-03):** selection already lives in the URL (delivery_id).
  At 390px (default, no prefix), when @selected_delivery != nil the detail column shows at 100%
  and the master list is hidden; render a Back affordance as a `<.link patch={build_path(@base_path,
  @filter_params, nil, @dark_chrome)}>` (clears delivery_id, NOT a new route). Use responsive classes:
  the list aside gets `class="... md:block #{if @selected_delivery, do: "hidden", else: "block"}"` and
  the detail column is always visible. The existing 390px "list before detail when unselected" e2e
  assertion (operator.spec.js:73-102) must stay green — only change layout when a row IS selected.
- **Back affordance icon:** use `hero-arrow-left` ONLY if it is already embedded in heroicons-inline.js;
  otherwise use a text "Back to deliveries" link (no new SVG, no bundle gap — Pitfall 3). Verify with
  `grep arrow-left mailglass_admin/assets/vendor/heroicons-inline.js` before using the icon.
</resolved_decisions>
