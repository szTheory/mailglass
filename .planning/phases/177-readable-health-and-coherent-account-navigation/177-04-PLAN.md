<objective>
Recompose Health's structure into one readable column with a cohesive observation group, fixed-order issue rows with 44px links and a tertiary per-issue help, adjacent notices and subordinate activity, without changing any population, link or visible string.

Purpose: OUTUX-06 (D-14, D-16, D-17 structure) implementing the expected winner A. Plan 177-05 then changes the copy and the docs (D-17 copy). The bounded A-vs-B comparison (D-15) runs in plan 177-08 against this production markup. If B wins there, plan 177-08 converts it.
Output: split `HealthOverview`, slimmer `OperatorLive` Health region, Health CSS classes and rebuilt bundle, structural component tests, the retargeted golden count extractor, the markup-coupled assertions, and the browser geometry assertion.

Revision W8 (scope split): the former single Health plan (about 70k tokens, 10 files) is split. This plan covers markup, classes and the bundle. Plan 177-05 covers copy, the copy-coupled assertions and the design-system amendment. Both edit `health_overview.ex`, `operator_live.ex` and the same tests, so 177-05 runs after this plan (wave 3). Sequential execution on main stays valid.

Owner todo 2026-10-25 item 3 ("every row is an underlined link plus an (i) icon at equal weight: 7 info icons"). Decision (CLAUDE.md Decision Policy, no owner ask): keep one help per issue and make it the row's tertiary element, measured rather than asserted.
- Treatment: count (body, bold) and label link (body, `text-base-content`, underlined) are primary. The help trigger is tertiary: the `field_help` default `text-secondary`, a 16px glyph, no underline, placed after the label. The "Not refreshed" tag is `text-label text-secondary`.
- What removes the equal-weight complaint: the 22px mono count is reduced to body size, and the 1000px dividers are capped to the 42rem column.
- Why not consolidate into one "What these mean" disclosure: it would separate each category's definition (Deferred, Unrouted inbound and Orphan events are jargon) from the row it explains. It would also drop the per-category accessible description, add a new pattern the design system lacks, and break the per-trigger anchoring contract in `e2e/health-tooltips.spec.js`.
- Why not reveal on hover: there is no affordance on touch.
- Why not dim with opacity: it risks WCAG 1.4.11 non-text contrast below 3:1.
- Why not a 44px target (the checker's example): the UI-SPEC declares `field_help` the only 24x24 exception (WCAG 2.5.8). A 44px box would enlarge the very icons the owner called noisy.
- Proof: the component test here plus the browser hierarchy test in plan 177-08 Task 3 (glyph <= 16px, help colour differs from the link colour, help glyph contrast >= 3:1 in light and dark, help not underlined, exactly one trigger per row).
- UI-SPEC delta (recorded here; UI-SPEC.md itself is not edited): the Component Inventory row for `field_help` ("Period help and per-issue help; unchanged.") gains "per-issue help is the row's tertiary element: secondary colour, 16px glyph, no underline, after the label; one per row". The markup class set is unchanged.
