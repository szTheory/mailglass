Orchestrator decisions recorded here (RESEARCH Open Question 1, CLAUDE.md Decision Policy):
- D-07 deny form (revision BLOCKER 1; this supersedes the earlier A1 plain-`/demo/login` decision, which contradicted locked D-07, so RESEARCH A1 and Open Question 1 are now marked RESOLVED/REFUTED). The new clause redirects to `/demo/login?return_to=<URL-encoded path?query>`. It needs no router plug: the auth context already carries `socket`, and `Phoenix.LiveView.get_connect_info(socket, :uri)` returns the request path and query on the disconnected render. That was verified in the demo LV 1.1.33 and admin LV 1.2.13 `conn_connect_info(conn, :uri)`, which builds `%URI{path: conn.request_path, query: conn.query_string}`. A logged-out request never reaches a connected mount, because the dead render halts with the redirect. The adapter falls back to `/ops/mail` plus the binary `tenant_id` and `view` arrival params (each at most 255 bytes, sent through `URI.encode_query/1`) when the URI is nil, which happens on a connected mount without `:uri` connect_info, or when path plus query would exceed 2048 bytes. The adapter calls `get_connect_info/2` only when the context holds a `%Phoenix.LiveView.Socket{}`; `Operator.Mount` is the only caller of `:operator_access` and always passes the root socket during mount. The value is URL-encoded with `URI.encode_www_form/1`, and the demo login's existing `safe_return_to/1` remains the validator (no scheme, no host, `/ops/mail` or `/ops/mail/...` path). Demo-only and reversible.
- The new clause is placed after the logged-in `:operator_access` clause and matches any remaining `:operator_access` context, so only callers without a binary `subject_id` reach it; the catch-all for other actions is unchanged.
- The demo ExUnit test is the blocking proof (conn-level through the real demo router, mailglass Operator.Mount and AdminAuth on the path dependency); the demo browser spec is advisory by project convention.
</objective>
