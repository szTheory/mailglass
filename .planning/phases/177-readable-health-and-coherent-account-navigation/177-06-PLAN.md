<objective>
Make the Account control head the group it scopes, on every operator surface and width, and keep Preview visibly outside that scope.

Purpose: UXF-09 (D-09, D-10, D-11, D-13). The Account control leaves the topbar for a scope-group header in `SurfaceNav`; Preview gets a static scope label and a caption; the topbar no longer wraps at 320/375.
Output: rewritten `SurfaceNav.nav/1`, re-homed and variant-aware `Shell.account_context/1`, `tenant_state` threading, rewritten narrow-chrome CSS + rebuilt bundle, component/connected tests, a visible-only e2e helper and the Account tracer spec.

Orchestrator decisions recorded here:
- `SurfaceNav` gets `attr :scope, values: [:account, :preview], default: :preview` and `slot :scope_header`. `Shell` passes `:account` plus the header slot; Preview needs no call-site change and renders "Scoped to an Account" by default. A default of `:preview` is the safe side: a forgotten operator call shows no Account identity rather than a fake one.
- Duplicate render (sidebar + mobile band are both in the DOM): ids are layout-suffixed (`surface-nav-scope-header-<layout>`, `surface-nav-scope-desc-<layout>`, `surface-nav-preview-caption-<layout>`, `operator-account-switch-status-<layout>-<index>`); base testids stay and gain `data-layout` (RESEARCH Open Question 2). A single e2e helper filters to the visible copy.
- `tenant_state` is a new `Shell.shell/1` attr (default nil) so Inbound's `:unavailable` reads correctly (RESEARCH Pitfall 3).
- Browser lane note: existing specs that locate `operator-account-*` by testid (flows, structural, inbound-layout, phase170-journey, phase175-inbound) hit strict-mode duplicates after this plan and are migrated in plan 177-07, which runs next. This plan's browser verifies run only `phase177-account.spec.js`.
- This plan owns `priv/static/app.css` in Task 3 (rebuild, TokenParity and Assets, commit as emitted; revision W-8, the one bundle procedure defined in plan 177-04). Tasks 1-2 use only utilities already in the committed bundle and restore it after browser runs.
- File count (revision W-9): 10 files in `files_modified`, deliberately not split. The CSS rewrite must be committed with its rebuilt bundle, and the scope-group markup (`surface_nav.ex`, `shell.ex`) with the CSS it depends on, so splitting would leave a commit whose bundle or chrome is inconsistent.
- Scope (revision W8): the bundle rebuild stays in Task 3. The CSS rewrite and its rebuilt bundle must land in one commit, because CI runs `git diff --exit-code` on `priv/static/` and TokenParityTest reads the committed bundle. Moving the rebuild into another plan would leave a commit whose bundle differs from a fresh build. The per-task verifies stay small instead: no full `operator_live_test.exs` / `inbound_live_test.exs` per task, and Playwright runs only this plan's tests by `--grep`.
- Depends on plan 177-03 (revision I-10): Task 1 reads PreviewLive's threaded nav (`preview_surface_paths/1`, `return_context`) from plan 177-03 and asserts that the Back link stays first above the group on a Preview page with a valid context.
</objective>
