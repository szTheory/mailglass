# Phase 177 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope and source locks

Locked by `177-CONTEXT.md` (D-01..D-21) and not re-opened here: the closed-set Preview return seam (`return_surface` ∈ {overview, deliveries, inbound} plus opaque `return_tenant_id`, D-01..D-08); the Account control as scope-group header with Preview outside the group (D-09..D-13); the Health single-reading-column expected winner and bounded A/B comparison with seven hard gates (D-14..D-17); the verification set (D-18..D-21). Research inputs: `.planning/research/phase-177/{HEALTH-COMPOSITION,ACCOUNT-CONTROL,RETURN-DESTINATION}.md`. Where those documents disagree with CONTEXT, CONTEXT wins: the "Previews use sample data" copy is superseded by D-12, and the operator-side tenant allow-list is not adopted (D-05).

This spec adds only what CONTEXT left to the UI layer: exact layout and class-level composition, spacing/type/colour use, microcopy, state coverage, the comparison protocol's measurable form, and machine-checkable acceptance. It adds no design system, no dependency, no new icon, no new colour, no new type size, no new weight, no new spacing token, no new JS hook, and no router option.

Surfaces touched (all existing): `MailglassAdmin.Operator.HealthOverview` (split into function components, plus the observation markup moved in from `operator_live.ex`); `MailglassAdmin.SurfaceNav`; `MailglassAdmin.Operator.Shell` (`shell/1`, `account_context/1`); `MailglassAdmin.AdminShell` (slot usage only; no API change); `MailglassAdmin.PreviewLive` chrome (sidebar, mobile_nav, page_header, return link); `Preview.Sidebar` and the other Preview URL builders (return params threaded, no visual change); `reference/demo_app` Preview `navigation`. Out of scope and not specified: Health populations or `health_issues/7` semantics, Account-scoped Preview rendering, global current-Account state, Preview authoring controls (Phase 178), any new Health metric, chart or KPI card.

| Use in this phase | Token |
|-------------------|-------|

| Observation group to verdict; verdict to issue list | md 16px |
| Issue-row internal gap (count to label to help icon to "Not refreshed") | sm 8px between count and label; xs 4px inside the label cluster |
| Notice vertical offset from the issue list | sm 8px |
| Issues/notices to Recent activity (margin above hairline, padding below it) | lg 24px above (`mt-lg`), md 16px below (`pt-md`) |

| Scope group to Preview block (divider offset above and below) | md 16px (`mt-md`, `pt-md`) |
| Preview caption offset beneath the Preview link | 0 (caption sits inside the 44px row block; see Account control) |

Exceptions (not spacing values, declared so the checker does not flag them):

- Interactive controls keep the 44px minimum target (`min-h-11`, `--size-control-md`). New 44px targets: each Health issue link and the Preview return link.
- Health reading column width `max-w-2xl` (42rem, 672px) and the container thresholds `30rem` (activity row) and `56rem` (Candidate B only) are layout measures, not spacing tokens.
- Count gutter `min-w-10` (40px) is retained from the current markup; it is a multiple of 4.
- Help-icon trigger (`field_help/1`, `h-6 w-6`, 24x24px) is the only sub-44px target in the phase. It is retained unchanged and meets WCAG 2.2 SC 2.5.8 (Target Size Minimum, 24x24 CSS px) by its own size; it is NOT given `min-h-11`. Every other link and button in the Health column, scope group and Preview return link is >= 44px.
- No other exceptions.

### A. Health composition (OUTUX-06)

**D-16 reading (explicit).** D-16 says counts "lose the large bold gutter treatment". This spec reads that as removing the three things that made the gutter large: heading size (20px), mono face and the dominant right-aligned heading-weight column. Counts therefore render at body size (16px) in the same size and face as their label, `tabular-nums`, and keep weight 700. Bold is retained because the count is the row's one quantity and the scan key, and weight 400 would make a 1-2 digit number indistinguishable from the label text; the weight is applied identically to every row, so it carries no severity (count never drives order, colour, size or severity wording, and a fixture with swapped counts must render identical classes). The 40px `min-w-10` gutter stays only to keep labels aligned for counts up to 4 digits. The planner must not restore heading size or mono.

**Bounded comparison A vs B (D-15) — measurable form.**

- Exactly two candidates built from the same production components in a temporary story. A = the column above. B = A below `56rem`; at container >= `56rem`, `@[56rem]:grid-cols-[minmax(0,42rem)_16rem] gap-xl justify-start` with Recent activity as a content-sized aside (`bg-base-200 rounded-box p-md`, top-aligned with the verdict). Candidate selection exists only in the story (story-local `composition: :a | :b` attr); production code has no `layout` attr and no toggle.
- Fixed scenarios: normal-many (all 8 categories), one issue, none-active, empty, stale-partial, unavailable, long-count/long-Unicode (Fjordline). Fixed container widths 288, 358, 480, 736, 992 and 1152px (derived: viewport minus 240px sidebar minus 48px main padding; 320 and 390 viewports use 288 and 358) plus the real main width beside the 15rem sidebar, measured not assumed. Light at every width; dark at 358 and 1152.
- Hard gates (failing any eliminates a candidate): G1 no horizontal overflow (`scrollWidth - clientWidth <= 1`); G2 DOM order = visual order for observation, verdict, each issue, notices, activity (`compareDocumentPosition` vs bounding-box top/left); G3 period, timestamp and Refresh share one `[role=group]` ancestor, horizontal gap timestamp-to-Refresh <= 16px on a shared line or vertical gap <= 8px when wrapped; G4 every link and button in `operator-overview-health` is >= 44px tall, except the `field_help` trigger, which must be >= 24x24 (WCAG 2.5.8 minimum, declared in the Spacing exceptions) and is the only permitted sub-44px target; G5 byte-identical `{testid, count, href}` population fingerprint vs the pre-change capture (taken BEFORE the refactor); G6 verdict and stale cues present as text, no state by colour alone; G7 no new axe violations (existing baseline, no quiet rebaseline).
- Tie-breakers, decided in this order from measurement: (1) scan path = vertical distance from observation top to last issue bottom, lower wins; (2) row slack = issue row width minus content width, lower wins; (3) activity subordination = heading font-size < verdict's, activity count font-size <= issue count's, activity top >= last issue bottom (A) or >= verdict top (B); (4) fewer layout rules and breakpoints.
- Expected winner A. If B wins on gates, ship B; no owner call is needed unless every gate ties and the residual choice is purely visual (then escalate as a brand/visual-identity hand-off with the measurement table and screenshots). Record results (numbers, widths, scenarios, winner, reason) in `.planning/phases/177-readable-health-and-coherent-account-navigation/177-HEALTH-COMPARISON.md`. Delete the losing candidate from the story; retained stories use the winner only.
