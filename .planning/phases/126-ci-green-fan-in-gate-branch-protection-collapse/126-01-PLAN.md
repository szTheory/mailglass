<objective>
Collapse the five required leaf branch-protection contexts into a single `CI Green` aggregate job (plus
`Guard Release Trigger` as the 2nd required context), and add the set-equality coverage meta-test that
makes it impossible for a required lane to silently drop out of the aggregate. Solve the workflow-level
`paths-ignore` trap so `CI Green` ALWAYS reports a status — a docs/planning-only PR must be mergeable,
never stuck "Expected — waiting for status".

Purpose: One required aggregate context (GATE-01) removes the per-lane branch-protection bookkeeping that
drifts every time a lane is renamed, and the meta-test (GATE-03) turns "a lane silently missing from
`needs`" — the plan's central footgun — into a failing test instead of a silently-degraded gate.

Output: A `ci_green` job (display name `CI Green`, `if: always()`, explicit `needs:` of the 5 required
leaves) + a `changes` detection gate that lets doc-only PRs skip the matrix while `CI Green` still posts;
a collapsed `REQUIRED_CHECKS` (`{CI Green, Guard Release Trigger}`); and an extended
`required_checks_test.exs` that asserts set-equality across the three sources and reconciles the
stability-lock / clean-baseline sub-tests.
</objective>

|----------|-------------|
