# Phase 139 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 139 is verification-only UI work. Preserve the existing admin visual design and prove the first-load asset contract across direct loads, deep links, and alternate mount roots. Do not redesign the admin, change tokens, alter component behavior, add a public router option, add duplicate asset routes, introduce screenshot baselines, or add pixel-diff checks. Source: `139-CONTEXT.md` D-01..D-08, `139-RESEARCH.md`, `.planning/REQUIREMENTS.md` AAU-01..04/GATE-03.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing |
| md | 16px | Default element spacing |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: keep existing control-size floors only. Icon-only and touch controls must remain at least 44px (`min-h-11` and `min-w-11` when square width matters). Existing non-touch compact control tiers may remain 36px only where already documented, such as tab strips. Phase 139 must not add layout spacing or resize existing surfaces.

## Typography

Declared sizes are exactly the existing admin type scale: 12, 14, 20, and 28px. Declared weights are exactly 400 and 700; do not use `font-medium`, `font-semibold`, 500, or 600.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 700 | 1.5 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.2 |

Computed-style proof may assert that visible admin text resolves to the loaded Inter family and that headings resolve to Inter Tight. It must not introduce new text sizes, negative letter spacing beyond existing heading defaults, or generated font weights.

Accent reserved for: selected-row border, active nav link/pill, active timeline node, primary CTA, focus ring, warning-free proof anchors that assert CSS loaded. Do not use accent as the default border, default badge color, decorative fill, or route-matrix highlight.

Phase 139 must prove style loading through computed values, not by changing visual emphasis. Preferred computed-style anchors:
- `body` or a visible page root resolves `font-family` containing `Inter`.
- A visible heading resolves the existing heading size (`20px`) and `font-weight` `700`.
- A visible card/sidebar/list surface resolves a non-transparent `background-color` matching the semantic surface family.
- A visible selected/current/focusable element resolves the accent color only where the existing allowlist permits it.

## Phase-Specific Visual Contract

The expected visual result is the current admin UI rendering with its existing tokens after a hard load. This phase does not require screenshots or new visual baselines. It requires proving that the browser receives and applies the existing CSS and fonts on first load.

Route matrix:

| Surface | Required direct-load path shape | Effective mount root |
|---------|---------------------------------|----------------------|
| Preview index | `/dev/mail` and query variants such as `/dev/mail?theme=dark` | `/dev/mail` |
| Preview scenario | `/dev/mail/<Mailable>/<scenario>` | `/dev/mail` |
| Preview render error | `/dev/mail/<BrokenMailable>/__error__` | `/dev/mail` |
| Gallery | `/dev/mail/gallery` | `/dev/mail` |
| Operator | `/ops/mail` plus tenant/query deep links | `/ops/mail` |
| Inbound | `/ops/mail/inbound` plus tenant/query deep links | `/ops/mail` |
| Alternate preview mount | Test-only route using `mailglass_admin_routes/2` at an arbitrary prefix | alternate preview root |
| Alternate operator/inbound mount | Test-only route using `mailglass_operator_routes/2` at an arbitrary prefix | alternate operator root |

First HTML stylesheet contract:
- Each route emits one root-layout stylesheet link whose `href` is rooted at the effective mount path: `/<mount>/css-<md5>`.
- The link must never be a bare relative path such as `href="css-..."`.
- Nested surfaces must not emit nested asset paths such as `/gallery/css-...`, `/inbound/css-...`, `/<Mailable>/<scenario>/css-...`, or `/<BrokenMailable>/__error__/css-...`.
- Query strings must not change the computed stylesheet mount root.

Browser network/style contract:
- Use direct `page.goto` loads for every route category above.
- Capture both `requestfailed` and `response` events for `stylesheet` and `font` resource types; HTTP 404 responses must fail even though Playwright treats them as completed responses.
- Every stylesheet response must have status 200, `content-type` containing `text/css`, and a pathname under the expected mount root.
- Every font response must have status 200, `content-type` containing `font/woff2`, and a pathname under `<mount>/fonts/`.
- At least one stylesheet response must be observed for each direct load. At least one self-hosted Inter-family font response or a successful `document.fonts.check()` against Inter must be observed before the route passes.
- After network checks, assert token-backed computed styling on visible content so unstyled HTML cannot pass.

Interaction contract:
- Tests may authenticate or seed through existing browser support routes, then use direct `page.goto` for proof. Do not rely on in-app LiveView navigation to keep a previously loaded stylesheet alive.
- Preserve existing keyboard, focus, modal, theme-picker, and replay interactions. Do not add hooks, browser storage, router macro options, redirects, `<base>`, duplicate nested asset routes, or client-side asset rewriting.
- Browser proof stays serialized with the existing Playwright worker discipline.
