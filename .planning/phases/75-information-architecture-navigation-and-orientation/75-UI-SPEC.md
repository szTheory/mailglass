## Deep-Link Disposition Decision (IA-04) — documentation deliverable, not code

**Decision: DEFER the deep-link-unstyled-CSS bug (GAP-22) to Phase 79 (VERIF-04).** (D-17)

**Recorded rationale:** A robust fix touches the **stable asset-serving seam** (`docs/design-system.md:141-150`): CSS/font URLs are relative so the bundle resolves under any adopter mount path; the consequence is that a **hard refresh on a deep URL** (e.g. `/ops/mail?tenant_id=foo&delivery_id=bar`) resolves the relative `css-<md5>` against the deep path rather than the mount root, loading unstyled. This seam is explicitly out of churn scope for v1.7 (D-24 / Out of Scope: "Changes to stable seams"). The bug is **stable under normal in-app live navigation** (live navigation keeps the stylesheet loaded); only a hard refresh on a deep URL is affected.

**Disposition mechanics:**
- GAP-22 is held at **severity 3** (not 4/5) so it does not falsely block Phase 79 closeout before the decision is reconfirmed there.
- Phase 75 owns the formal in-scope/deferred decision (this section); **Phase 79 owns closure** (VERIF-04 — either fix it or re-affirm the deferral with rationale so no open sev-4/5 row blocks milestone closeout, per Pitfall 16).
- This is a **decision/documentation artifact, not a code change.** Satisfies IA-04. The recorded rationale should be reflected in the Phase 75 plan/CONTEXT and (optionally) a note appended near `docs/design-system.md:141-150`.
