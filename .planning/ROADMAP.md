## v2.10 — UI Repairs & Faithful Storybook

**Roadmap status:** All 31 requirements approved 2026-10-26. Phase 174 completed and passed automated verification 2026-10-27; Phase 175 is planned in six plans across five waves and ready to execute. No owner UAT remains for Phase 174.

### Phase 175: Delivery Investigation and Safe Replay

**Goal:** Operators can investigate a Delivery through useful technical/suppression evidence, review one exact permitted webhook and understand its outcome; the same replay interaction quality is available on Inbound.
**Depends on:** Phase 174
**Requirements:** UXF-12, OUTUX-07, OUTUX-08, REPLAY-04, REPLAY-05, REPLAY-06, REPLAY-07, REPLAY-08
**Success Criteria** (what must be TRUE):
1. Starting from a scoped Delivery list, an operator can select a record, inspect grouped technical evidence visible by default, refresh suppression evidence, perform permitted recovery and return with the relevant Account/filter/selection context. Retain this complete early Delivery path in composed production-component scenarios plus connected proof; Inbound full-detail technical evidence is also visible by default. (UXF-12; continuing STORY-07 obligation)
2. Suppression Refresh/Retry performs a real scoped read in a consistent location, distinguishes ready/empty/stale/unavailable states and handles expiry/external changes and failed reads truthfully. Removal support and unknown expiry are explained in user terms without a nonexistent removal control. (OUTUX-07, OUTUX-08)
3. Either quick view and full detail expose replay for the exact eligible selection; unavailable cases explain why before a dialog, with no dead-end primary action. Changed/denied eligibility remains enforced at action time. (REPLAY-04, REPLAY-05)
4. Outbound and Inbound replay share concise accessible dialog structure with identifiable stored-request evidence, an X named Close, Escape, focus containment/return and a clear primary action. Distinct domain commands and consequences remain intact; use the requested ux-writing guidance. (REPLAY-06)
5. Connected permitted replay closes the dialog, shows an accessible success toast and updates evidence according to the actual new-work/no-change outcome. Auth-denied and other failures remain visible inside the open dialog with a safe retry or explicit re-review route, without flicker, hidden flash or unexplained disabled review. Preserve exact correlation, revalidation, authorization, idempotency and audit behavior. (REPLAY-07, REPLAY-08)

## Continuing delivery obligations

Every phase obeys [REQUIREMENTS.md](REQUIREMENTS.md#acceptance-applying-to-every-repair-slice). One phase owns each requirement for traceability; later phases preserve the delivered behavior. In particular:

- **Stories and first job:** Phase 174 establishes the faithful first repaired story; Phase 175 delivers the composed Delivery investigation/recovery path. Each subsequent repair adds its own realistic retained production rendering and connected proof. STORY-07's final ownership in Phase 178 accounts for the completed set, not permission to defer stories.
- **Feedback ledger and minimal fixtures:** Begin current-source dispositions and scenario IDs with Phase 174; update them in every repair. Separate pure facts/builders from persistence materialization; check representative projection agreement at consuming boundaries. Start with the existing three cohorts and add cases only for distinct reachable risk. No catalogue/extraction prerequisite.
- **Themes, motion and accessibility:** Phase 174 owns System/OS behavior and fresh axe comparison. Each interaction-owning phase proves keyboard/focus and reduced motion; each rendered area receives representative light/dark and viewport/container checks. Phase 178 owns final real-zoom/receipt coverage reconciliation. Use the named landmarks and defect widths without a Cartesian screenshot grid.
- **Trust and cost:** Preserve Account/auth/exact replay/rendering contracts and separate ordinary contacts from sensitive diagnostics. Start the cold/warm cost pilot in Phase 174, update it as checks expand and reconcile it in Phase 178; provisional ≤5 added PR wall minutes / ≤10 runner-minutes includes setup. No measured-speed, DB-free startup, required-gate or aesthetic precision claim precedes evidence. Preserve existing gates and label advisory findings.
- **Scope and stop:** Keep every feedback row visible. Trim speculative infrastructure before known repairs. Whole-job breadth beyond this envelope, new profiles, custom dates, F7 and comprehensive Gallery migration remain deferred; the published Gallery route stays. No rebrand, account-aware Preview, dependency campaign, CI-wide redesign, merge, publication or deployment is authorized by this roadmap.
