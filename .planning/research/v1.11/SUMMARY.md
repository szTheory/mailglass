## Axis-Ownership Map

Per CONTEXT D-08, each cross-cutting axis has exactly one owning dossier. Other dossiers
reference the owner's LD-IDs; they never lock a competing decision on a borrowed axis.

| Axis | Owner | Non-owners must |
|------|-------|-----------------|
| Animation / transition / motion timing / reduced-motion | **MOTION** | cite a `MOTION-LD-*` ID; never lock their own easing/duration/property |
| Component state matrix (rest/hover/focus/active/disabled/loading/empty/error) + light-mode token classes | **COMPONENT-STATES** | cite a `STATE-LD-*` ID for which states exist on an archetype |
| Dark-mode token resolution (elevation tiers, contrast, focus-ring color, desaturation) | **DARK-MODE** | cite a `DARK-LD-*` ID for the dark rendering of a token |
| Layout / placement / information architecture (master-detail, filter placement, nav labelling, empty-state placement) | **IA** | cite a `IA-LD-*` ID for where an element sits |
| Literal user-facing copy strings | **MICROCOPY** | cite a `COPY-LD-*` ID for wording |

No axis has two owners. The three overlap axes flagged by the plan were checked and resolved:

1. **MOTION × COMPONENT-STATES** — COMPONENT-STATES locks *which states exist* and their
   light token classes; it locks **no animation**. Every motion reference in a STATE-LD row
   points at a MOTION-LD row (pointers corrected — see Reconciliation Notes). No conflict.
2. **DARK-MODE × COMPONENT-STATES** — COMPONENT-STATES locks light-mode token classes;
   DARK-MODE locks the dark resolution of those same semantic tokens (e.g. the focus ring in
   STATE-LD-06 resolves to `DARK-LD-03` in dark; structural borders resolve to `DARK-LD-02`).
   Refinement, not contradiction. No conflict.
3. **DARK-MODE × MOTION** — `MOTION-LD-09` governs `prefers-reduced-motion`; `DARK-LD-08`
   governs `prefers-color-scheme`. Independent media queries; dark mode does not alter any
   reduced-motion behaviour. No conflict.
