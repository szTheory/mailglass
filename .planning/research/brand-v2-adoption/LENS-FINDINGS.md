## C. Admin UX / JTBD (truthful slice)

- Data reality: `Delivery.status` has 5 values (queued, sent, dispatched, failed, suppressed); `last_event_type` 16; `Components.delivery_display_status/1` (`components.ex` ~1528) already collapses to one display status — the single seam for pane marks. `last_error` is exception text (not safe for support staff). `Event.reject_reason` ∈ {invalid,bounced,timed_out,blocked,spam,unsubscribed,other}, mostly nil. Filter form already says "recipient email address or subject". Health already has a "Needs attention" card (`health_overview.ex:23`). - Dishonest-copy list (never render): "Next try at …", "the provider will retry", any cause sentence on a failed row with nil reason, "Delivered" as "in the inbox", opened/clicked implying delivered, "Not sent" for a send-time `:failed` (different from suppressed), counts styled as statistics.
- Verdict sentences only from known event types with "reported/recorded" language (delivered: receiving server took it, may not be in inbox; delayed: asked to try again later; failed: did not get through; suppressed: on your suppression list; sent/no outcome: "Sent with <provider>. No delivery report yet."). Next step is static and status-keyed (suppressed → remove from list; failed → check address / replay if granted; delayed → nothing yet). Seams: `outcome_help`, `outcome_badge`.
- Out of scope (later "insight" milestone): retry times, provider reason capture, SMTP codes, per-mailer rollups.
- Prove-first job: "customer says the password reset never arrived": search email → Needs attention → open → verdict + "sent is not delivered" → next step; light/dark/375px; zone shown; via the real LiveView with seeded data.
- Fixtures: reuse `reference/persona_spec/personas.ex` (Northstar high volume; Fjordline one delivery, long ids, non-ASCII, nil reject_reason; Helios empty). Add: hard bounce to a typo domain (`:bounced`), bounce with nil reason, deferred with no retry time, suppressed with manual reason, delivered with no open event, queued/sent with no report, send-time `:failed` with `last_error`, spam complaint, two emails to one customer with different subjects, unicode recipient; vary mailer names incl. a long module name.

## F. Brand risk / legal / docs / launch (not legal advice)

- Dilution (15 U.S.C. 1125(c)) needs a famous mark; the golden arches qualify, confusion not required. Mitigations: azure, overlap, inside a lowercase word, developer-tools field, non-commercial OSS. Old arch cases (McDonald's v. Moore, 5th Cir. 1966; Gunvill 1977) favored defendants where presentation differed; nothing found against a blue overlapping-arch "m" in software (thin search). Practical risk judged low; residual is a takedown letter. Diligence (1–2 h): USPTO tmsearch design codes + words, EUIPO TMview, WIPO Global Brand DB, reverse-image search; optional flat-fee attorney. Gate only the announcement and any ™/® claim; keep a one-color/wordmark fallback.
- Name clearance: `mailglass` absent on npm/PyPI/crates/RubyGems; on Hex only ours; GitHub `Mr-Anderson-403/MailGlass-v3.1` (0 stars, unrelated); mailglass.com registered 2024-10; near-names MailGlyph, Mailglider. Registers NOT searched (USPTO fetch blocked).
- Fonts: OFL; bundling with MIT is fine; OFL text must accompany the fonts; no Reserved Font Name declared in the bundled OFL texts; woff2 subsetting counts as modification but no rename needed without an RFN. Only Funnel's upstream metadata was checked; verify Atkinson Next/Mono upstream.
- ExDoc 0.40.4 current (repo pins `~> 0.40`): `logo`/`favicon` PNG/JPEG/SVG (48×48 area), `before_closing_head_tag`, `assets`. Hex package pages show no logo field — the README is the only brand surface on hex.pm (inferred; confirm on the live page). README `<picture>` with `prefers-color-scheme` is GA on GitHub; non-GitHub renderers show the light image. GitHub social preview: PNG/JPG/GIF < 1 MB, 1280×640, manual upload in repo settings (checklist item).
- Verification list: `mix docs --warnings-as-errors` in each package; toggle ExDoc theme; check `doc/assets/` for logo/favicon/CSS; 320 px and dark; favicon at 16/24/32 px in Chrome/Safari/Firefox tabs light+dark (the book admits an untested "two n's" risk); `.ico` is light-only; azure #1895C2 on white ≈ 3.0–3.5:1 — graphics only, never text; avatar plate inside circular crops at 40 px.
- Lowercase "mailglass": module names, `mix mailglass.*` fixed; README H1 is `# Mailglass`; CHANGELOG headings are machine-generated; need an automated lint or it drifts; contract tests that grep the capitalized name can break.
- Rollout practice (general knowledge, lower confidence): stage docs → README/repo → admin UI; one CHANGELOG line; keep old asset URLs for a minor; social/avatar swap last in one sitting.
