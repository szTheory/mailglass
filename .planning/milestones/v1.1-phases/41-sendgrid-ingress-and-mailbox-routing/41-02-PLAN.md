<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| durable receive truth -> mailbox side effects | Mailbox execution consumes persisted truth and must not happen inside the transaction that defines receive durability. |
| mailbox callback -> execution lineage | User-defined mailbox code can misbehave, so the runner must classify failures without corrupting receive truth. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-41-04 | Tampering | receive transaction and mailbox runner | mitigate | Commit canonical and evidence truth before any mailbox side effect and never mutate the canonical row with latest execution state. |
| T-41-05 | Repudiation | execution history | mitigate | Append one lineage row per attempt with explicit source, mailbox, outcome, and failure metadata. |
| T-41-06 | Denial of Service / Logic corruption | mailbox callback return handling | mitigate | Validate outcomes strictly and classify invalid shapes, raises, throws, and exits as failures rather than semantic mailbox results. |
</threat_model>
