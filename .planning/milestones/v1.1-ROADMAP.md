# Milestone v1.1: Inbound Core Slice

**Status:** ✅ SHIPPED 2026-05-06
**Phases:** 39-44
**Total Plans:** 17 (12 product + 3 Phase 43 verification recovery + 2 Phase 44 closeout reconciliation)

## Overview

v1.1 was the first deliberate sibling-package expansion after the `v1.0` core
lock. The milestone opened `mailglass_inbound` with one canonical inbound
contract, two first-party providers (Postmark, SendGrid), tenant-safe storage
that preserves both normalized canonical data and raw provider source for
replay, and async mailbox execution that prefers Oban without requiring it.
Phases 43 and 44 closed verification-evidence and bookkeeping gaps surfaced by
the `v1.1` milestone audit so the full evidence chain for every requirement
reaches `satisfied` under the workflow's three-source check.

The milestone deliberately did **not** include the live `v1.0` publish closeout,
a Conductor-style dev UI, or Mailgun / SES / `gen_smtp` relay ingress — those
remain deferred so the first inbound milestone stays narrow and supportable.

## Milestone Summary

**Decimal Phases:**

- None planned at milestone open. Phases 43 and 44 were inserted after the v1.1 audit surfaced verification-evidence and bookkeeping gaps; both followed the standard sequential numbering rather than decimal insertion.

**Key Decisions:**

- Keep the first inbound milestone narrow: Postmark and SendGrid only, not full provider parity (D-22).
- Store both normalized inbound records and raw provider source material so replay/debug truth is first-class from day one.
- Preserve Mailglass's optional-Oban philosophy rather than making inbound execution Oban-only.
- Phase 44 does not invoke `$gsd-complete-milestone v1.1` itself (D-44-11); the user runs the close ceremony explicitly.

**Issues Resolved:**

- Original `v1.1-MILESTONE-AUDIT.md` `status: gaps_found` (10 partial requirements + 1 partial integration + 1 broken flow) reduced to `status: passed` after Phase 43 and Phase 44 recovery.
- Phase 41 verification artifact upgraded from a plan-check report to an execution-evidence report, and a new Phase 41 validation artifact added.
- `REQUIREMENTS.md` traceability for all 10 v1.1 requirements aligned with summary frontmatter and execution-level VERIFICATION.md files.

**Issues Deferred (out of scope for v1.1):**

- Live `v1.0` publish closeout and external branch-protection proof.
- Conductor-style dev UI for inbound message synthesis and replay.
- Mailgun, SES, and `gen_smtp` relay ingress.
- Adjacent deliverability workflow bets unrelated to the inbound package contract.

**Technical Debt Incurred:**

- None additive in this milestone. Environment debt from the original audit (`mailglass_inbound` deps not fetched in audit workspace) was resolved during Phase 43 by running `mix deps.get` against the existing lockfile.
- v1.0 closeout debt carried forward unchanged: partial Nyquist bookkeeping for Phase 35, non-blocking boundary warnings in support-summary / admin probe verification paths, manual GitHub branch-protection verification, bare `mix test` citext-OID-cache race.
