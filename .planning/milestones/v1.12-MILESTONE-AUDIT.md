## Release ceremony notes (Phase 108)

The v1.12 feature body (phases 104–107) was developed locally and had **never run through
full CI** until the release push. Pushing it to `origin/main` before merging the release PR
(the correct sequence) surfaced six genuine pre-flight regressions, all fixed in Wave 0:

1. **Format Check** — v1.12 doctor/test files not `mix format`-clean → formatted.
2. **Installer Host Smoke** (required) — the new fail-closed installer correctly blocked the
   stock-endpoint smoke → smoke updated to `mix mailglass.install --force`.
3. **Dialyzer** — `mailglass.doctor` `run/1` `no_return` (exits to set the three-state code) →
   suppressed with `@dialyzer {:nowarn_function, run: 1}`.
4. **Docs (ex_doc)** — guides linked unregistered files + documented a wrong `resolve_outbound_adapter_ref/2`
   arity → de-linked + corrected to the real `c:Mailglass.Tenancy.resolve_outbound_adapter_ref/1`.
5. **Docs (`mix mailglass.docs.check`)** — stale required token `{:mailglass, "~> 0.3"}` contradicted
   phase 105's `~> 1.6` bump → aligned.
6. **Demo Browser Evidence** — v1.11 responsive preview split made `getByText("AccountMailer")` a
   Playwright strict-mode violation (2 matches) → scoped to `preview-sidebar-desktop`.

Also notable:
- **Publish fan-out raced** (one `publish-hex` run per release event). One run published all three
  packages; the other two `publish-core` jobs failed as race-losers (already-published). Verified
  directly against Hex — all three live. Known "racing fan-outs" behavior.
- **First post-publish-smoke** false-negatived on a 5-minute Hex-index timeout during the racing
  publish; a re-dispatch on the tag passed fully green.
- The hands-free auto-merge did not fire (non-required advisory lanes red + Release Please's hourly
  PR regeneration churn); the merge was completed via maintainer admin-override after explicit
  go/no-go approval, with all branch-protection-required checks (`guard-release-trigger` + the full
  required `ci.yml` set) green.

## Follow-ups (non-blocking, for next milestone)

- **gate-ci-green advisory classification gap:** `isAdvisory()` in `publish-hex.yml` only matches
  `"Operator Browser Gate"` or the `" Advisory ("` naming convention. "Demo Browser Evidence
  (Docker Compose / Chromium)" matches neither, so a red Demo Browser Evidence lane would be treated
  as blocking despite not being a branch-protection required check. This release sidestepped it by
  fixing the test green, but the classifier should be hardened (add to `ADVISORY_LANES` or rename the
  lane) to match the documented "non-required ⇒ advisory" rule of thumb.
- **`guard-release-trigger`** was exercised and passed on the release PR; consider registering it
  formally as the single required branch-protection check is already done — no action needed.
- **Reference baseline pin bump** (`~> 1.4` → `~> 1.7`) deferred — `~> 1.4` already resolves 1.7.0;
  out of v1.12 scope.
