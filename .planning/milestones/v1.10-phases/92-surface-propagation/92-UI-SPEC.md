# Phase 92 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none; project uses brandbook assets plus Phoenix/admin CSS tokens |
| Preset | not applicable |
| Component library | Phoenix Components + daisyUI theme tokens in `mailglass_admin/assets/css/app.css`; no shadcn/Radix/Base UI |
| Icon library | Heroicons via vendored `heroicons-inline` Tailwind plugin; no new icons required for this phase |
| Font | Brand assets use outlined paths only. Admin UI uses Inter / Inter Tight / IBM Plex Mono self-hosted with system fallbacks; only weights 400 and 700 are loaded |

---

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, tight brand-copy separation |
| sm | 8px | Compact element spacing, README image-to-badge gap if Markdown needs explicit spacing |
| md | 16px | Default element spacing, admin logo row padding, documentation paragraph separation |
| lg | 24px | Section padding, README header-to-content rhythm |
| xl | 32px | Layout gaps when adding preview/upload instruction blocks |
| 2xl | 48px | Major section breaks; use only if README/brandbook docs need a clear policy break |
| 3xl | 64px | Page-level spacing; no expected new use in Phase 92 |

Exceptions: admin controls keep the existing 44px touch-target floor (`--size-control-md`). README image intrinsic size is controlled by `brandbook/examples/readme-header.svg` width/height, not by CSS spacing.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px admin UI / host Markdown default in README and GitHub docs | 400 | 1.5 |
| Label | 12px admin UI / host Markdown default for badges and captions | 700 only for existing uppercase operator label | 1.5 |
| Heading | 20px admin UI / host Markdown heading scale in docs | 700 | 1.2 |
| Display | 28px admin UI; README brand display comes from outlined SVG paths only | 700 | 1.2 |

Typography contract: do not introduce live text inside brand SVGs. README header, OG card, and replacement admin wordmark must remain outlined paths with no font dependency. Do not add new font files.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light: Paper `#F8FBFD` / white host surfaces; dark admin: Ink `#0D1B2A` | Page ground, README/social-card light fields, admin shell background |
| Secondary (30%) | Light: Mist `#EAF6FB`; dark admin: elevated Ink `#152538`; muted Slate `#5C6B7A` for secondary copy | Admin sidebar/header surfaces, documentation wells, tagline and secondary text |
| Accent (10%) | Light: Glass `#277B96`; dark: Ice `#A6EAF2`; admin monochrome logo inherits current text color | Sealed-flap seal, README lockup paths, focus rings, primary action/status accents, dark-surface logo expression |
| Destructive | Light: Error Crimson `#B42318`; dark: Crimson readable family `#E29089` / existing admin token `#D47368` | Destructive or failure states only; not expected for Phase 92 propagation work |

Accent reserved for: sealed-flap identity paths, focus rings, primary action fills, links, status accents, and the admin logo expression. Do not use Glass/Ice as generic decoration. README header must keep its existing Glass + Slate fills for GitHub light/dark legibility. Admin dark chrome must not place the light primary lockup on Ink; use monochrome/currentColor or an explicit dark expression.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Upload social preview |
| Empty state heading | Social preview not uploaded yet |
| Empty state body | Export `brandbook/examples/og-card.png`, then upload it in GitHub Settings > Social preview. GitHub does not provide a write API for this surface. |
| Error state | Social preview export is invalid. Re-run the Playwright export and confirm the PNG is 2400x1260 and under 1 MB before uploading. |
| Destructive confirmation | None. This phase has no destructive user action. If a surface is deferred, record the reason instead of deleting or silently skipping it. |

Copy rules: use the brand voice from `brandbook/brand-book.md`: plain English, exact nouns, strong verbs, no hype, no "Oops/Whoops/Uh oh." The README keeps existing technical copy intact; Phase 92 may add only the brand header and narrow upload/export documentation needed for SURF-01..03.
