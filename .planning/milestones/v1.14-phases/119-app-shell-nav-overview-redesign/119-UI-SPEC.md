## Spacing Scale

All tokens declared in `@theme` block of `assets/css/app.css`. Use the named token utilities
(`p-md`, `gap-sm`, `px-lg`…). Do NOT use arbitrary values or off-grid steps (Tailwind footgun).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding |
| sm | 8px | Compact element spacing, nav item gaps (`gap-xs p-sm`) |
| md | 16px | Default element spacing, card/section padding |
| lg | 24px | Section padding, `mb-lg` heading block, main content `py-lg` |
| xl | 32px | Layout gaps, main content `md:py-xl` |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Touch targets: `min-h-11` (44px) on all interactive controls — required by WCAG 2.2 AA;
  already enforced on `btn`, `nav_link`, and `stat_card` wrappers.
- `mt-xs` (4px) and `mt-sm` (8px) used within card internal spacing (see `stat_card` pattern).
- Mobile top-bar: `py-sm` on `<header>` (tight, compact chrome).

**Source:** `assets/css/app.css` @theme block (lines 107–144). Pre-populated; no user input needed.

## Typography

Exactly 4 sizes, exactly 2 weights (400 default / 700 bold). Weight 500/600 are NOT loaded —
faux-bold is a conformance failure. Use `font-bold` or omit weight class (default 400).

| Role | Token class | Size | Weight | Line Height | Usage |
|------|-------------|------|--------|-------------|-------|
| Label | `text-label` | 12px | 400 / 700 | 1.5 | NAV section label ("OPERATOR"), stat card label, filter tag |
| Body | `text-body` | 14px | 400 / 700 | 1.5 | Overview subtitle, card descriptions, orientation tips |
| Heading | `text-heading` | 20px | 700 | 1.2 | Page `<h1>`, section `<h2>` ("Health"), nav surface title |
| Display | `text-display` | 28px | 700 | 1.2 | Stat card metric values (IBM Plex Mono for counts) |

Rules for this phase:
- The Overview page `<h1>` ("Operator overview") uses `text-heading font-bold`.
- Stat card values use `text-display font-bold` with `font-mono` (IBM Plex Mono) and `tabular-nums`.
- Nav section label "OPERATOR" uses `text-label font-bold uppercase text-secondary`.
- Overview subtitle (SHELL-03 rewrite): `text-body text-secondary` — one short triage-framed line,
  no boilerplate, no signpost to another surface.
- The new "Overview" sidebar nav link label uses `text-body` (same as existing Deliveries/Inbound).

**Source:** `assets/css/app.css` @theme type tokens + `shell.ex` HEEx patterns.

## Color

Light/dark handled by two daisyUI theme blocks (`mailglass-light` / `mailglass-dark`) via
`[data-theme]` attribute on the root `div`. Dark is enabled by `data-theme="mailglass-dark"`.
Use ONLY semantic token class names — never raw hex or raw palette classes (`text-gray-500`).

| Role | Light (brand) | Dark (brand) | Semantic class | Usage |
|------|--------------|--------------|----------------|-------|
| Dominant (60%) | Paper `#F8FBFD` | Ink `#0D1B2A` | `bg-base-100` | App background, main content area |
| Secondary (30%) | White `#FFFFFF` / Mist | Ink-raised `#152538` | `bg-base-200` | Sidebar, cards, header bar, filter pane, stat cards |
| Border | Mist-edge `#C7DCE5` | Ink-edge `#315069` | `border-base-300` | All component borders, dividers |
| Primary text | Ink `#0D1B2A` | Mist `#EAF6FB` | `text-base-content` | Body copy, headings |
| Secondary text | Slate `#5C6B7A` | Mist-soft `#B8CAD4` | `text-secondary` | Subtitles, meta, labels |
| Accent (10%) | Glass `#277B96` | Ice `#A6EAF2` | `text-primary` / `bg-primary` / `border-primary` | See reserved list below |

### Accent reserved for (the 10% rule — do NOT use outside this list):
1. Active nav item: left `border-l-2 border-primary` + `text-primary` weight (existing `nav_link` active class)
2. Active nav pill (mobile): matching accent treatment
3. Focus ring: `ring-primary` (`mg-focus-ring` utility class) on all interactive elements
4. Primary CTA button: `btn-primary` on the stat_card drill-through links
5. "Selected" row border in Deliveries list (inherited; not touched in this phase)

The Overview health stat_card row uses `text-error` / `text-warning` / `text-success` for severity
color — these are status-semantic, not accent. They conform to WCAG 1.4.1 (color + icon + label,
never color alone).

### Semantic status colors (status only, never accent):
- `text-error` / `border-error` / `bg-error/10`: Recent failures > 0
- `text-warning` / `border-warning` / `bg-warning/10`: Orphan backlog > 0
- `text-success` / `border-success` / `bg-success/10`: All-clear / healthy
- `text-secondary`: neutral / zero / loading states

**Source:** `assets/css/app.css` theme blocks + `docs/design-system.md` accent discipline.

## Interaction Contracts

### SHELL-01: Nav active-state fix

**Current bug:** `operator_live.ex:349` has hardcoded `active={:deliveries}`. The shell's `active`
attr enum at `shell.ex:201` only declares `values: [:deliveries, :inbound]`.

**Contract:**
1. Extend the `active` attr enum to `values: [:overview, :deliveries, :inbound]`.
2. Add a new "Overview" nav link ABOVE Deliveries in the sidebar — always visible (no `inbound_available?` gate).
3. Add a matching "Overview" nav pill in the mobile top-bar nav.
4. Replace `active={:deliveries}` at `operator_live.ex:349` with `active={@view}`.
   `@view` resolves to `:overview` / `:deliveries` / `:inbound` — no new logic required.
5. Thread the same fix through the Inbound surface caller so Inbound doesn't regress to false Overview highlight.

**Overview nav link spec:**
- Label: "Overview"
- Icon: `hero-squares-2x2` (semantic — "a grid of information panes at a glance"; NOT `hero-home`,
  which implies a homepage rather than an ops triage surface)
- Verify `hero-squares-2x2` SVG is present in `assets/vendor/heroicons-inline.js`. If absent,
  embed it and rebuild `priv/static/app.css` before committing (heroicons-inline landmine).
- Href: bare operator root (`@deliveries_path` with `view` param stripped — the operator root
  with no `?view=` is the Overview).
- Active condition: `@active == :overview` (matches the new enum value).
- The link MUST use the enabled `nav_link` branch (not the `<span>` disabled branch) so
  `aria-current="page"` renders when active. This is what the `nav-active-correctness` judgment
  gate asserts.

**Non-color-alone rule:** Active nav state is conveyed by BOTH the `border-l-2 border-primary`
accent stripe AND `font-bold` weight change — not color alone. Both light and dark themes satisfy this.

### SHELL-02: Overview as triage destination

**Delete:** the `operator-overview-nav` block at `operator_live.ex:416-448` (the redundant "Navigate"
section with "View Deliveries" and "View Inbound" cards). Also remove the signpost subtitle
("Navigate to Deliveries to inspect individual sends") — replaced by the SHELL-03 rewrite.

**Health stat_card drill-through:**
- "Recent failures" stat_card → wrap in `<.link patch={build_path(@base_path, Map.put(@filter_params, "view", "deliveries") |> Map.put("status", "failed"), nil, @dark_chrome)}>` (links into Deliveries filtered to `:failed`).
- "Active suppressions" stat_card → wrap in `<.link patch={build_path(@base_path, Map.put(@filter_params, "view", "deliveries") |> Map.put("status", "suppressed"), nil, @dark_chrome)}>` (links into Deliveries filtered to `:suppressed`).
- "Orphan backlog" stat_card → keep the existing `phx-click` / `phx-value-focus="orphan_backlog"` focus drilldown from `support_cards.ex`. Do NOT invent a Deliveries `status=` filter for orphans — none maps to them.
- "Overall status" stat_card → no drill-through (it is a summary readout, not an actionable item).

**Wrapping pattern (a11y):** Wrap each stat_card in `<.link>` at the call site in `operator_live.ex`.
Do NOT modify the `stat_card` primitive in `components.ex` — it stays a presentational `<article>`.
The `<.link>` wrapper avoids nested-interactive violations (the card itself has no `<a>` or `<button>`
inside, so a wrapping link is semantically clean).

**Drill-through link styling:**
- The `<.link>` wrapper that wraps a clickable stat card gets `class="block mg-focus-ring rounded-box"`.
  `rounded-box` matches the card's own radius so the focus ring traces the card edge cleanly.
- Hover state: add `hover:border-primary` to the stat_card's wrapping link (the card `<article>` has
  `border border-base-300`; this escalates to accent on hover). Achieved by overriding via `@rest` passthrough
  OR by adding a hover class to the wrapping `<.link>` — do NOT mutate `stat_card`'s default classes.
- Non-drill-through stat cards (Overall status) remain plain `<article>` with no link wrapper.

**Orientation strip — empty-pane-only:**
- The `<MailglassAdmin.Operator.Shell.orientation_strip surface={:deliveries} />` at `operator_live.ex:375`
  is rendered **unconditionally on Overview** today. Change it to render only when the Overview is in the
  all-clear / empty state (no health events needing attention) — i.e., when `@support_summary` is all-clear
  AND `@suppression_count == 0` (or nil).
- The strip's copy (`copy_for(:deliveries)` in `shell.ex:392-410`) stays **byte-frozen** — only its
  render condition changes.
- When there ARE health events: the strip is suppressed; the health stat_card row is the primary content.
- When all-clear: the strip renders as a calm, contextual orientation for a new operator.

**All-clear state — calm and short:**
- When the Overview has no actionable health events (all-clear), the layout should be compact and calm.
  The all-clear path MUST NOT render the same height as the attention state.
- Proposed IA: single `<p>` line ("Your email delivery system is healthy — nothing needs your attention
  right now.") followed by the orientation strip. No duplicate section headers, no redundant copy.
- This directly answers D-MOBILE-INFODUMP (the 375/320 scroll being too tall in the zero-data persona test).

### SHELL-03: Microcopy contract

**Overview page title:** "Operator overview" — kept as-is (`text-heading font-bold`).

**Overview subtitle rewrite (the signpost line is deleted):**
- Old: "A task-oriented overview of your email delivery health. Navigate to Deliveries to inspect individual sends."
- New (attention state, health events present): "Your delivery system needs attention." (concise, triage-first)
- New (all-clear state): "Your delivery system is healthy." (calm, single-truth)
- The subtitle is set in `operator_live.ex:357-363` — thread `@view` AND a health predicate to pick the correct line.
- Never use "Oops". Never duplicate the sidebar navigation in copy.

**Health section heading:** Keep "Health" (`<h2 class="text-heading font-bold">`) — accurate and short.

**Stat card labels (existing, do NOT change):**
- "Recent failures" / "Orphan backlog" / "Active suppressions" / "Overall status" — on-brand, domain-precise.
- Severity labels are computed by existing helpers — do not touch them.

**Clickable stat card accessible name:**
- Each drill-through `<.link>` wrapping a stat card needs `aria-label` if the stat card label alone
  is insufficient for screen readers: e.g. `aria-label="View recent failures in Deliveries"`.
- The non-clickable "Overall status" card needs no `aria-label` addition.

**Banned words (applies to all copy in this phase):** "Oops", "Navigate to [surface]" (sidebar already does this).

**Orientation strip copy:** `copy_for(:deliveries)` in `shell.ex:392-410` — byte-frozen. Zero changes.

## States and Viewports

### States (Overview branch — all required)

| State | Trigger | UI contract |
|-------|---------|-------------|
| Happy / attention | `@support_summary` has non-zero failures/orphans OR `@suppression_count > 0` | Health stat_card row (4 cards); NO orientation strip; subtitle = "Your delivery system needs attention." |
| Happy / all-clear | All metrics zero or nil; `@suppression_count == 0` | Calm single-line copy + orientation strip; subtitle = "Your delivery system is healthy." |

| Loading | Between mount and data arrival | Existing skeleton/`aria-busy` on stat cards — inherited |
| Error / boundary | Data load failure | Existing error card pattern — inherited |
| Disconnected | LiveView socket drop | Existing `phx-disconnected` / reconnect flash — inherited |

### Viewport rules (mobile-first — inherited, confirmed for this phase)

| Breakpoint | Layout |
|------------|--------|
| 320px | Single column; sidebar hidden; mobile top-bar shows Overview/Deliveries/Inbound pills; stat cards stack 1-wide |
| 375px | Same as 320; all-clear state must be 1-screen-height or less (D-MOBILE-INFODUMP fix) |
| 768px (md) | Sidebar appears; mobile top-bar nav hidden; stat cards → 2 columns (`sm:grid-cols-2`) |
| 1024px+ | Stat cards → 4 columns (`lg:grid-cols-4`); sidebar full |
| 1440px / wide | Same as 1024; `max-w-7xl` constrains the content column |

No horizontal overflow at any viewport. Stat card values truncate with `truncate` class (existing).

## Motion Contract

**Principle:** Reuse existing motion tokens ONLY. No new keyframes. No new CSS.

| Element | Motion | Token/class |
|---------|--------|-------------|
| Sidebar nav item (active change) | Color transition | `transition-colors duration-(--duration-fast)` (existing `nav_link`) |
| Overview health row (mount) | Reveal | `.motion-reveal` (opacity + translateY 6px, 220ms) applied to the overview div on mount via `phx-mounted` |
| Flash messages | Reveal | `.motion-reveal` (existing `flash_region`) |
| Stat card link hover | Color transition | `transition-colors duration-(--duration-fast)` on border — same row-state token |

**Reduced-motion:** `@media (prefers-reduced-motion: reduce)` already neutralizes all `.motion-*`
classes to instant — this phase adds no new motion CSS, so reduced-motion compliance is inherited.

**Forbidden in this phase:**
- No `height` / `width` / `padding` transitions.
- No `ease-in`.
- No new `@keyframes` declarations.
- No JS animation hooks.

## A11y Contract (WCAG 2.2 AA)

| Rule | Contract |
|------|----------|
| `aria-current="page"` | Present on the active nav item (Overview, Deliveries, or Inbound) — the `nav_link` component emits this when `active={true}`. Requires the Overview link to use the enabled branch (real `<a>`, not `<span>`). |
| Color not sole indicator | Active nav state: accent stripe (visual) + font-bold (weight) + `aria-current` (semantic). Stat card severity: icon + color + label (existing). |
| Keyboard navigation | Tab reaches all drill-through stat card links; Enter activates. Existing `mg-focus-ring` applies to `<.link>` wrappers. |
| Touch targets | All interactive elements `min-h-11` (44px). Drill-through `<.link>` wrapping each stat card must result in a ≥44px clickable region — `block min-h-11` or the card's natural height (stat cards are taller than 44px). |
| Focus restoration | No modal introduced in this phase; no focus-trap change needed. |
| `aria-label` on link wrappers | "View recent failures in Deliveries" / "View active suppressions in Deliveries" — prevents ambiguous "article" link text for screen readers. |
| Landmark nav | Both sidebar `<nav aria-label="Operator sections">` and mobile `<nav aria-label="Operator sections">` — existing, preserved. |
| Semantic heading hierarchy | `<h1>` for page title, `<h2>` for "Health" section — no skipped levels. Overview branch must not introduce an `<h3>` above "Health". |
