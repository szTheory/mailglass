## Core Model And Routing

- [x] **MODEL-01**: Adopter can depend on one canonical `%InboundMessage{}` struct for the first-party inbound package, with stable fields for routing, tenancy, and provider provenance. — Phase 39 (verification recovered under Phase 43)
- [x] **ROUTE-01**: Adopter can route inbound mail to mailboxes using one DSL that matches on recipient, subject, and headers. — Phase 39 (verification recovered under Phase 43)
- [x] **MAILBOX-01**: Adopter can implement mailbox handlers with explicit `:accept`, `:reject`, `:ignore`, and `{:bounce, reason}` outcomes. — Phase 39 (verification recovered under Phase 43)

## Provider Ingress

- [x] **INGRESS-01**: Maintainer can verify and normalize Postmark inbound payloads into the canonical inbound model through a first-party ingress plug. — Phase 40 (verification recovered under Phase 43)
- [x] **INGRESS-02**: Maintainer can verify and normalize SendGrid inbound payloads into the canonical inbound model through a first-party ingress plug. — Phase 41 (verification replaced under Phase 43)

## Storage And Replay

- [x] **STORE-01**: Operator can persist each inbound message as both normalized canonical data and raw provider source material sufficient for replay and debugging. — Phase 40 (verification recovered under Phase 43)
- [x] **STORE-02**: Operator can replay a stored inbound message through routing and mailbox processing without pretending it is a newly received provider event. — Phase 41 (verification replaced under Phase 43)

## Execution And Adoption

- [x] **EXEC-01**: Adopter can execute inbound routing asynchronously through Oban when Oban is installed and configured. — Phase 42 (verification recovered under Phase 44)
- [x] **EXEC-02**: Adopter can execute the same logical mailbox contract through a supported bounded fallback when Oban is absent. — Phase 42 (verification recovered under Phase 44)
- [x] **ADOPT-01**: Adopter can install, configure, test, and support the core inbound slice through honest first-party docs and verification lanes. — Phase 42 (verification recovered under Phase 44)
