<objective>
Thread the runtime `prefix: Config.schema()` injection through the `Mailglass.Repo`
facade (the universal choke point) and per-step into the three `Ecto.Multi` builders
(Events, Outbound, Suppression.Escalation), plus one defensive `put_query_prefix/2` on
the correlated orphans subquery. This is the CODE half of Design Phase B (FACADE-01,
FACADE-02).

Purpose: Every mailglass read/write — including admin's, which routes through the same
facade — resolves to the configured Postgres schema with zero changes at any call site.
This mechanism is the load-bearing dependency for Phase 134 (migration entrypoint) and
Phase 135 (inbound mirror).

Output: `put_prefix/1` (private) + `multi_opts/1` (public) in `repo.ex`; `aggregate/4`
signature; prefix threaded into `events.ex` / `outbound.ex` / `escalation.ex` Multi
builders; `put_query_prefix/2` on the `support_summary.ex` subquery.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| library code → Postgres | The injected `prefix:` becomes a schema identifier in every generated SQL statement |
| caller → Mailglass.Repo | Callers may pass an explicit `:prefix` (tests / advanced adopters); Keyword.put_new lets it win |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-133-01 | Tampering (SQL identifier injection) | injected `prefix:` at every facade / Multi site | low | accept | The injected value is `Mailglass.Config.schema()` — Phase-132 boot-validated against `Mailglass.Identifier`, sourced from static application config, NEVER from user input. Identifier injection is already mitigated upstream; facade threading introduces NO new user-controlled path into a SQL identifier. State and move on. |
| T-133-02 | Tampering (ledger immutability bypass) | events.ex / outbound.ex Multi steps | low | accept | The append-only `mailglass_events` immutability trigger (SQLSTATE 45A01) is unchanged; prefix threading is a pure opts transform routing writes to the configured schema. The 45A01 rescue/translate clauses in repo.ex are byte-unchanged. No new bypass. |
| T-133-03 | Information disclosure (cross-schema read leak) | operator subquery / facade reads | low | mitigate | A missed prefix on the correlated not-exists subquery could read from the wrong schema. Mitigated by `put_query_prefix/2` (Task 3) + asserted end-to-end in Plan B's integration test. |
| T-133-SC | Tampering | npm/pip/cargo installs | n/a | n/a | No package-manager installs in this phase — no new dependencies added. Legitimacy gate not applicable. |

**No high-severity threat is introduced by facade threading.** ASVS L1 block-on-`high` gate: PASS (no high findings).
</threat_model>
