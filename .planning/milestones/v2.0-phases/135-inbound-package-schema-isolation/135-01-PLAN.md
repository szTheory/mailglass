<objective>
Thread the already-built `MailglassInbound.Config.schema/0` accessor through the `MailglassInbound.Repo`
facade so inbound's 3 tables resolve to the configured Postgres schema, and inline-qualify the one
facade-bypassing DELETE in `internal/prune.ex` so the retention sweep targets the correct schema
(INB-01, plus the load-bearing D-02 correctness fix).

Purpose: mirror the locked Phase 133 core facade `put_prefix` shape onto the inbound sibling package.
Inbound is a strictly-simpler subset — no Multi builders to thread (D-03 defers `multi_opts/1`), no
`update`/`delete`/`aggregate`/`delete_all` on the facade (D-05 — only thread what inbound uses).

Output: prefix-aware inbound facade + schema-qualified prune DELETE + a dedicated schema-isolation test
that fails if either the facade default or the prune DELETE lands in the wrong schema.
</objective>
