## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, radio/input inner gaps, tight inline affordances |
| sm | 8px | Nav item gaps, compact shell spacing, tenant chip spacing |
| md | 16px | Default shell/header/card/list padding |
| lg | 24px | Main content vertical padding, tenant chooser panel padding |
| xl | 32px | Wide viewport page padding and major shell group gaps |
| 2xl | 48px | Major section breaks only |
| 3xl | 64px | Page-level spacing only; avoid inside shell chrome |

Exceptions: `min-h-11` / `min-w-11` equals the 44px interactive target floor for nav links, nav pills, tenant switch options, theme choices, pagination buttons, and clear/apply controls. Dense read-only identifiers may use smaller text, but interactive hit areas must stay at least 44x44.

Source: `mailglass_admin/assets/css/app.css` `@theme` spacing tokens, Phase 109/110 decisions, SHELL-01..06.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px | 700 for labels/headings, 400 for secondary metadata | 1.5 |
| Body | 14px | 400 | 1.5 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.2 |

Rules:

- Use only weights 400 and 700; do not introduce 500/600 classes.
- Use `text-label`, `text-body`, `text-heading`, and `text-display`; no ad hoc `text-lg`, `text-xl`, arbitrary tracking, or viewport-scaled type.
- Tenant ids, UUIDs, timestamps, and provider identifiers use `mono` plus truncation/title where space is constrained.
- Shell headings stay `text-heading`; tenant selector rows, pagination, and nav labels use `text-body` or `text-label`, never display scale.

Source: `mailglass_admin/assets/css/app.css`, Phase 109 type gate decisions, `112-CONTEXT.md` D-09/D-10.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#F8FBFD` / Dark `#0D1B2A` via `bg-base-100` | Page background, main shell canvas, broad negative space |
| Secondary (30%) | Light `#FFFFFF` / Dark `#152538` via `bg-base-200`; borders Light `#C7DCE5` / Dark `#315069` | Sidebar, header, cards, list rows, tenant chooser panel, pagination rail |
| Accent (10%) | Light `#277B96` / Dark `#A6EAF2` via `text-primary`, `border-primary`, focus ring | Current nav indicator, selected tenant, active theme option, focus ring, selected row strip, pagination current page |
| Destructive | Light `#B42318` / Dark `#E29089` | Destructive actions only; Phase 112 should not add destructive tenant/theme/navigation actions |

Accent reserved for: active/current navigation cue, selected tenant option, selected/current pagination state, focus outlines, active theme option border, selected list row strip, and small status icons where the label also carries meaning. Do not use accent as a general fill for all links, every button, decorative icons, or empty-state illustrations.

Semantic colors: use success/warning/error/info tokens only with visible label text. Use destructive/error only for real failures or destructive confirmations, not for ordinary unselected/empty tenant states.

Source: `brandbook/tokens.css`, `mailglass_admin/assets/css/app.css`, `112-CONTEXT.md` D-06/D-09/D-11.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Select tenant |
| Empty state heading | Select a tenant |
| Empty state body | Choose a tenant to inspect its deliveries and inbound routing. Tenant scope stays in the URL so refreshes and shared links keep the same view. |
| Error state | Tenant list unavailable: the scoped tenant read model could not be loaded. Retry the request or check the operator access configuration. |
| Destructive confirmation | none — Phase 112 introduces no destructive tenant, theme, navigation, or pagination actions |

Additional required copy:

- Sole-tenant auto-select: do not show explanatory chrome; silently patch/redirect to the canonical URL with `tenant_id`.
- Zero accessible tenants: heading `No tenants available`; body `This operator does not have a tenant with mail activity yet. Send a message with a tenant_id, or check the host tenant scope.`
- Multi-tenant switcher label: `Tenant`.
- Tenant chip title: `Tenant currently in view: {tenant_id}` when selected.
- Result count: `{N} results` for all list states, including one-page results. Use `1 result` singular.
- Pagination controls: `Previous` and `Next`; disabled boundary controls remain visible with `aria-disabled`.
- Theme choices remain exactly `System`, `Light`, `Dark`; system mode must not be described as a stored theme.
- Banned copy: `Oops`, `Whoops`, `Uh oh`, `Something went wrong`, cross-tenant/all-tenant language, tenant CRUD/invite/pin/favorite language.

Source: `112-CONTEXT.md` D-03/D-04/D-07/D-10/D-11, `112-RESEARCH.md` Phase Requirements, existing component copy conventions.

## Interaction Contract

### Tenant Selection

- Resolve accessible tenants through the core operator read model before loading surface data.
- Exactly one accessible tenant: canonicalize the URL by patching or redirecting to include `tenant_id`; do not render the picker.
- Two or more accessible tenants with no URL tenant: render a selector/list panel in the shell body area, not a dead-end empty list.
- Selected tenant option uses visible text, mono tenant id, `aria-current="true"` or equivalent selected semantics, and a non-color cue: accent border/left strip plus selected label/icon.
- Tenant switch action updates URL state and preserves the current surface when possible; it must not carry a selected delivery/inbound id across tenants.
- Tenant selector is not tenant management: no create, edit, invite, pin, favorite, or cross-tenant aggregate affordance.

### Navigation

- Continue using `Components.nav_link/1` for desktop and `Components.nav_pill/1` for mobile.
- Active state at both nav levels must include `aria-current="page"` and a visible non-color cue. Desktop uses border-left plus bold text; mobile must add an equally explicit non-color cue, such as border-bottom/left or selected marker, not only a tinted background.
- Surface navigation preserves `tenant_id` and theme choice. It intentionally drops surface-specific filters and selected record ids.
- Disabled/unavailable nav remains visibly inactive and programmatically disabled; do not render dead links.

### Theme

- Continue using `Components.theme_picker/1` for UI. Do not build a second segmented control.
- Explicit `light` and `dark` choices server-render `data-theme="mailglass-light"` / `data-theme="mailglass-dark"` on first response from a host-scoped namespaced cookie.
- `system` clears or omits the explicit cookie and emits no `data-theme` attribute; never emit `data-theme="system"`.
- Theme changes preserve current URL state, including `tenant_id`, filters, and current surface.
- First paint must not flash through the wrong explicit theme after reload.

### Pagination

- Render result count for every non-error list state.
- Render pagination chrome only when `total_pages > 1`.
- Previous/next controls stay visible but disabled at boundaries; they are not hidden.
- Page changes preserve `tenant_id`, surface, theme, and compatible filters; selected row ids may be cleared if not present on the target page.
- Pagination totals and boundaries must come from scoped read-model metadata, never from truncated entry length.

Source: SHELL-01..06, `112-CONTEXT.md`, `112-RESEARCH.md`, `mailglass_admin/lib/mailglass_admin/operator/shell.ex`.
