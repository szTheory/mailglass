# Phase 113 — UI Design Contract

> Visual and interaction contract for Phase 113: Data-Display. Generated by gsd-ui-researcher for `/gsd-ui-phase 113`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — in-house Phoenix.Component + Tailwind v4 standalone + daisyUI 5 token system |
| Preset | not applicable |
| Component library | Phoenix.Component function components; daisyUI semantic utilities; no Radix/Base UI/shadcn |
| Icon library | Vendored Heroicons via `mailglass_admin/assets/vendor/heroicons-inline.js` and `<Components.icon name="hero-*">` |
| Font | Inter for UI/body (weights 400/700 only), Inter Tight for headings/display (weights 400/700 only), IBM Plex Mono for code/IDs (weights 400/700 only) |

Source notes: `components.json` is absent and this is a Phoenix LiveView stack — the shadcn initialization gate does not apply. Phase 113 must not initialize shadcn, add a UI registry block, add a runtime Hex dependency, introduce a second styling system, or add screenshot/pixel-diff tooling. The canonical design system is defined in `mailglass_admin/assets/css/app.css` and `brandbook/tokens.css`.

Visual hierarchy on data-display surfaces: the first attention anchor is the result-count header, then the status column of the first data row (or the distinct data-state template when no data is present). Severity/status must be immediately scannable within 5 seconds for an operator under stress — status column appears first (leftmost) in the desktop table and as the first content block in every mobile card.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, status icon/label gap, inline compact pairs, table cell icon-left padding |
| sm | 8px | Table cell vertical padding, card internals gap, field label gaps, data-state icon/title gap |
| md | 16px | Default card padding, table row padding, data-state section padding, horizontal cell padding |
| lg | 24px | Section padding around result count header and data-state message blocks |
| xl | 32px | Large layout gaps, gallery section breaks |
| 2xl | 48px | Major page-level section breaks only |

No off-grid values, arbitrary spacing utilities, raw pixel style attributes, or dynamic class construction are permitted for Phase 113 data-display surfaces.

## Data-Display Patterns Contract

### Responsive List Presentation (DATA-01)

Both `DeliveriesList` and `RecordsList` must render two presentations from identical assigns:

| Width | Presentation | DOM |
|-------|-------------|-----|
| `>=768px` (`md:`) | Semantic `<table>` with `<thead>`, `<th scope="col">`, `<tbody>`, `<tr>` | `data-testid="operator-deliveries-table"` / `data-testid="inbound-records-table"` |
| `<768px` (`max-md:`) | `<ul>` of card list-item `<li><button>` elements | `data-testid="operator-deliveries-cards"` / `data-testid="inbound-records-cards"` |

Visibility toggling: `hidden md:block` wrapper for the table; `md:hidden` wrapper for the cards `<ul>`. Both presentations share the same LiveView assigns, `phx-click`, `phx-value-id`, `aria-current`, `aria-selected`, pagination, and result-count behavior. Neither presentation may invent fake row count or pagination from its own length.

Deliveries table column order: Status → Recipient (masked) → Tenant → Provider → Event → Last event timestamp

Deliveries card field order: Status badge (first, prominent) → Recipient (masked) → Tenant label + value → Provider → Event label → Timestamp

Inbound table column order: Outcome → Mailbox → Tenant → Provider → Received timestamp

Inbound card field order: Outcome badge (first) → Mailbox → Tenant label + value → Provider → Received timestamp

Selected row/card contract: selected state uses `aria-current="true"` or `aria-selected="true"`, a border-left or border-top accent cue (width change, not color alone), and a background shift to `--color-base-200` surface. Color alone is not sufficient.

### Canonical Stat-Card Usage (DATA-02)

Every stat/KPI card on all three surfaces (Operator, Inbound, Preview) must route through `MailglassAdmin.Components.stat_card/1`. No page-local stat card markup is permitted.

| Attribute | Contract |
|-----------|----------|
| `label` | Non-empty string; truncates with `title` tooltip in DOM |
| `value` | Non-placeholder string; `tabular-nums` class, never wraps |
| `state` | Explicit atom — `:ok`, `:warning`, `:error`, `:loading`, `:unavailable`, or `:empty`; no bare dash or underscore |
| `severity` | Required when `state` is `:warning` or `:error`; determines icon, label, and color |
| `severity_label` | Required alongside `severity`; the visible text component of severity encoding |
| "All clear" state | Must render as a real, readable `value` string (e.g., `"All clear"`) — not a dash or blank |

### Distinct Data-State Templates (DATA-03)

Four distinct state templates are required. They must not collapse into shared copy or shared testid:

| State | Test ID | Heading Copy | Body Copy | Icon | Icon Color |
|-------|---------|-------------|-----------|------|-----------|
| `:empty` / no-data | `data-state-empty` | "No deliveries" / "No records" (surface-specific noun) | "No [noun] match the current filters." or "No [noun] have been recorded yet." | `hero-inbox` | `text-secondary` |
| `:error` / unavailable | `data-state-error` | "Delivery data unavailable" / "Record data unavailable" | "There was a problem loading [noun]. Try refreshing the page." | `hero-exclamation-circle` | `text-error` |
| `:permission_denied` | `data-state-permission-denied` | "Access restricted" | "You don't have permission to view [noun] for this tenant." | `hero-lock-closed` | `text-warning` |
| `:stale` | `data-state-stale` | "Data may be out of date" | "The [noun] shown here may not reflect recent activity." | `hero-clock` | `text-secondary` |

State templates must be visually and semantically distinct — no shared icon/copy between `:empty` and `:error`, no shared copy between `:permission_denied` and `:empty`. "Oops", "Whoops", "Uh oh", "Something went wrong", and bare dashes are banned. Copy must follow the `COPY-LD-01..16` voice decisions: "[Noun] [past-tense verb]: [specific cause]" or "[description of state]: [next action]" pattern.

### Severity/Status Encoding (DATA-04)

`Components.status_badge/1` is the sole owner of status-to-icon/label/color mapping in list rows. No page-local badge helpers or local badge class maps are permitted.

Status badge usage in table rows and mobile cards:

- The badge must render icon + visible label + semantic color in every presentation (desktop table cell AND mobile card).
- Badge must never shrink to icon-only under space pressure.
- `data-testid="delivery-status-{status}"` or `data-testid="inbound-outcome-{outcome}"` must be present on each badge so Playwright can locate and assert the visible label.
- "All clear", "Pending", "No match", "Tracked", "Unknown" are meaningful text states, not placeholders.

### Long-Value Handling (DATA-05)

Field-level handling is deterministic — no field may overflow or force horizontal page scrolling:

| Field Type | Strategy | Classes |
|------------|----------|---------|
| UUID / delivery ID / record ID | Truncate + `title` tooltip; wrap in mono | `mono min-w-0 truncate` with `title={id}` |
| Tenant ID / tenant label | Truncate + `title` tooltip | `min-w-0 truncate` with `title={tenant_id}` |
| Provider ID / provider message ID | Truncate + `title` tooltip; mono | `mono min-w-0 truncate` with `title={provider_message_id}` |
| Module / function names | Truncate + `title` tooltip; mono | `mono min-w-0 truncate` with `title={module_name}` |
| Mailbox name / routing key | Truncate + `title` tooltip | `min-w-0 truncate` with `title={mailbox}` |
| URLs | `overflow-wrap-anywhere` or truncate + tooltip | `break-all min-w-0` or `truncate` with `title` |
| Non-ASCII names / subjects | `overflow-wrap-anywhere` inside constrained column | `min-w-0 overflow-wrap-anywhere` |
| Timestamps | No-wrap; mono; `title` with full ISO value | `mono whitespace-nowrap` with `title={format_datetime(ts)}` |
| Recipient (masked) | Truncate + `title` with masked value | `min-w-0 truncate` with `title={mask_recipient(recipient)}` |

Flex/grid table cells must include `min-w-0` on the containing element to allow truncation to engage. Table cells should not use `overflow-auto` horizontal scrolling as a default — horizontal scrolling is not permitted at the page level.

## Responsive Behavior Contract

| Width | Contract |
|-------|----------|
| 320–390px (mobile) | Card/list presentation only via `max-md:block`. Each card renders field labels + values vertically with `gap-sm`. Status badge is first. No horizontal overflow. `min-h-11` on card button. |
| 768px (breakpoint) | Table presentation activates (`md:block`). Cards hide (`md:hidden`). Table columns must not overflow or require horizontal scroll. |
| 1440px+ | Table columns distribute across available width; `table-fixed` may be used to control column widths and prevent long-value overflow. |

Both presentations must carry identical `phx-click`, `phx-value-id`, `aria-current`, `aria-selected`, and keyboard-operable semantics. Playwright must assert both testids and both presentations at the relevant viewport width.

## Accessibility Contract

| Area | Contract |
|------|----------|
| WCAG target | WCAG 2.2 AA throughout. |
| Table semantics | Desktop table uses `<table>`, `<thead>`, `<th scope="col">`, `<tbody>`, `<tr>`, `<td>`. No div-only table. |
| Mobile card semantics | Each card item is an interactive `<button>` or `<a>` within a `<li>` inside a `<ul>`. Visible field labels (not icon-only) repeat for each card. |
| Selected state | `aria-current="true"` or `aria-selected="true"` plus a non-color cue (border width change, border-accent). Color alone is not sufficient. |
| Status/severity | Icon + visible label + semantic color. Status badge must never render icon-only or color-only in table cells or mobile cards. |
| Target size | Interactive rows/card buttons must meet 44×44 via `min-h-11`. |
| Long-value a11y | Truncated values must provide a `title` attribute containing the full value for accessible name fallback; HEEx interpolation stays escaped (no `raw`). |
| Data-state a11y | Data-state sections use `<section>` with a visible `<h3>` heading. Icon is decorative (`aria-hidden="true"`) and accompanied by visible text. |
| Focus | Shared `mg-focus-ring` / `mg-focus-ring-inset` on interactive row elements; focus ring must be visible in light/dark/system. |
| Contrast | All text ≥4.5:1 AA; meaningful non-text indicators and borders ≥3:1; severity colors meet contrast on their background in both themes. |
| Keyboard | Table rows and mobile card buttons are keyboard-navigable (Tab/Enter/Space); focus order follows DOM order. |
| Motion | Existing Phase 109 MOTION-LD constraints apply: transform/opacity only, ease-out, ≤300ms per element, `prefers-reduced-motion` snaps to instant. No new animation is introduced in Phase 113. |
