# Milestone v1.0: Stability Lock

**Status:** ✅ SHIPPED 2026-05-06
**Phases:** 35-38
**Total Plans:** 12

## Overview

v1.0 closed the pre-release stability arc for the transactional and admin core
without expanding the product boundary. The milestone locked the public
contract, published the long-lived compatibility promise, added semantic proof
lanes that keep the docs honest, and produced committed release-rehearsal
artifacts for install, upgrade, and publish truth.

## Phases

### Phase 35: Stability Contract Audit

**Goal**: Adopters and maintainers can identify the exact stable `v1.x` contract across `mailglass` and `mailglass_admin`, including what remains internal.
**Depends on**: Phase 34
**Plans**: 3 plans

Plans:

- [x] 35-01: Publish the canonical core `mailglass` v1.x contract inventory and align root adopter docs
- [x] 35-02: Define the narrow `mailglass_admin` stable boundary and mark UI internals as non-contract

## Milestone Summary

**Decimal Phases:**

- None.

**Key Decisions:**

- Keep the `v1.x` contract narrow and docs-led instead of implying stability from every reachable export.
- Treat compatibility and upgrade policy as canonical guides that Tier 1 docs point toward, not prose scattered across READMEs.
- Reuse existing repo-native proof lanes and publish-check truth instead of adding heavier new release infrastructure.

**Issues Resolved:**

- The stable `mailglass` and `mailglass_admin` surface is now explicit, visible in generated docs, and backed by compiled-doc checks.
- The `1.x` compatibility promise and `0.x -> 1.0` upgrade path are now canonical and mechanically verified.
- Release-day install, upgrade, publish, and trust-doc proof no longer depend on maintainer memory.

**Issues Deferred:**

- Phase 35 Nyquist bookkeeping is still partial because `35-VALIDATION.md` reports `wave_0_complete: false`.
- Non-blocking boundary warnings remain in the support-contract verification lane.
- Live branch-protection confirmation remains an external manual closeout step.

**Technical Debt Incurred:**

- Accepted verification noise remains in the stability-contract workflow until the probe boundary warnings are normalized.
- Branch-protection verification is still recorded as honest external debt rather than repo-controlled proof.
