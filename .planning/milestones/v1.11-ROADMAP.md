# Milestone v1.11: mailglass_admin Design-System Uplift

**Status:** ✅ SHIPPED 2026-06-16
**Phases:** 94-103 (10 phases)
**Total Plans:** 42

## Overview

Re-baseline the `mailglass_admin` UI onto the canonical fable brand tokens, then
fractally audit-and-uplift every component, component-group, and page across the
Operator, Inbound, and Preview surfaces to award-winning quality in light + dark and
at every width (390/768/1440) — enforced by an idempotent, research-grounded quality
ratchet that only moves quality forward.

**Root cause fixed:** the admin's `app.css` never consumed `brandbook/tokens.css`,
every admin border was drawn in the *accent* color (`base-300`→Ice), cards sat one
brand-role off (`base-200`→Mist instead of `surface-raised`), and dark muted text was
below WCAG AA. This was the "UI feels off-brand / inbound looks ugly" perception.

**Scope locks:** Admin UI only — 3 surfaces. Core mailglass email-template HEEx
components and `brandbook/` HTML specimens were OUT (this milestone *consumes* the
brand book, it does not edit it). No new product features / capabilities / routes
beyond the dev-only component gallery. No core/inbound *functional* code changes.
**Release posture: prepare-only** — the ceremony was staged but no Hex release was cut.

**Critical path:** 94 → 95 → 96 → 97 → {98, 99, 100 parallel} → {101, 102 parallel} → 103

## Milestone Summary

**Key Decisions:**

- **D-27** (PROJECT.md): v1.11 re-baselines `mailglass_admin` onto the canonical fable brand tokens and runs a fractal (component → group → page), idempotent, research-grounded uplift of all three admin surfaces — an adopter-visible-quality investment under D-23, not feature growth.
- Token re-baseline: `app.css` daisyUI theme vars reference `var(--mg-*)` with no duplicate hex literals; a fail-closed ExUnit token-parity test breaks the build on brand-token drift.
- Tighten-then-re-baseline: Phase 94 landed the tightened conformance + motion grep gates FIRST so the token swap could not regress silently.
- Idempotent ratchet: schema-2 `{prior, current}` score baseline with a meet-or-beat comparator and an anti-vacuity guard; one carried-forward `GAP-NN` register with a sev≥3 citation gate.
- The "Storybook lens" is a thin dev-only LiveView gallery (`/dev/mail/gallery`) — zero-Node hard rule forbids a real Node Storybook.
- No pixel-diff visual regression (D-07 banned): structural Playwright assertions gate CI; LLM scores gate the milestone.
- Release prepare-only (v1.7 precedent): no Hex release cut; one PENDING ceremony action (inbound exact-pin re-pin, D-13) deliberately deferred.
