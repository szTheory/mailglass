<objective>
Swap the trigger on publish-hex.yml and post-publish-smoke.yml from the
broken `on: workflow_run` (with dead `head_branch` gate) to
`on: release: types: [published]`, and add a `mix hex.info` pre-check inside
the publish job that exits 0 (skip) when the version is already on Hex.
This is the steady-state fix for REL-01 — the v0.1.2 trigger could not
detect tag creation, and a workflow rerun would double-publish.

Purpose: Make Hex publish event-correct (release publication, not workflow
completion) and idempotent (rerun-safe).

Output: Two updated workflow files. No code changes elsewhere.
</objective>

    Replace the `on:` block at the top of `.github/workflows/publish-hex.yml`. New trigger:

    ```yaml
    on:
      release:
        types: [published]
      workflow_dispatch:
        inputs:
          tag:
            description: "Tag to publish (e.g. mailglass-v0.2.0)"
            required: true
    ```

    DO NOT use `on: push: tags:` — that fires on workflow rerun and would double-publish (PITFALLS.md §REL-01).

    Remove the `workflow_run`-derived `if:` gate at the existing lines 38-43 (the `head_branch` comparison). With `on: release: types: [published]`, GitHub guarantees the workflow only fires once per release publication; the `head_branch` gate is dead code now.

    Inside the publish job (before `mix hex.publish`), add an idempotency guard step. Use exactly this shape (matching CONTEXT.md REL-01 + PATTERNS.md §publish-hex.yml):

    ```yaml
    - name: Skip if version already on Hex
      env:
        PACKAGE: ${{ matrix.package }}   # or hard-coded if no matrix
        VERSION: ${{ steps.resolve_version.outputs.version }}
      run: |
        if mix hex.info "$PACKAGE" "$VERSION" 2>/dev/null | grep -q "Released:"; then
          echo "Version $VERSION of $PACKAGE already on Hex — skipping publish (idempotency guard)."
          echo "skip=true" >> "$GITHUB_OUTPUT"
          exit 0
        fi
      id: idempotency
    ```

    Then gate the actual `mix hex.publish` step on `if: steps.idempotency.outputs.skip != 'true'`.

    Brand voice: any error/info messages use specific, composed language ("skipping publish (idempotency guard)" — never "Oops!").

    Per D-13 (no Node toolchain anywhere) and CLAUDE.md "All third-party GitHub Actions pinned to commit SHA" — do not unpin or change any existing `uses:` SHAs in this plan; that is REL-09's concern in 08-04.
