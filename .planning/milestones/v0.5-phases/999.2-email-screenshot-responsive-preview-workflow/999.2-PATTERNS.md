Source analog (`mailglass_admin/lib/mailglass_admin/operator_live.ex`):

```elixir
def handle_params(params, uri, socket) do
  filter_params = normalize_filter_params(params)

  {:noreply,
   socket
   |> assign(:base_path, URI.parse(uri).path || "/operator")
   |> assign(:filter_params, filter_params)}
end

defp parse_positive_integer(value) when is_binary(value) do
  case Integer.parse(value) do
    {integer, ""} when integer > 0 -> integer
    _ -> nil
  end
end
```

## Project Constraints To Carry Into Planning/Execution

- Workflow must stay in admin/tooling surfaces (mix task + CI path), not a new `mailglass` core runtime API.
- Render truth must remain `PreviewLive`/`Mailglass.Renderer.render/1`; no alternate rendering engine in this phase.
- Claims must be bounded: Chromium screenshot artifacts prove preview-pipeline regression confidence only, not email-client parity.
- Determinism is mandatory: stable matrix dimensions, stable ordering, explicit manifest schema/metadata, and repeatable CI environment.
- Keep no-surprise package conventions: boundary classification, strict CLI errors, and `--no-optional-deps` compatibility.
