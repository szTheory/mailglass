**Researched:** 2024-05-01

**Confidence:** HIGH

## Summary

This phase implements a code generator to scaffold new Mailglass mailables and their corresponding HEEx templates. The generator will use `Igniter.Mix.Task`, which fits seamlessly into the project's existing adoption of Igniter for code generation and upgrades.

The task will parse the requested module name, optionally prefix it with the application's base namespace and `.Mail.` if omitted, and then generate both the Elixir mailable module and a matching `.html.heex` template file. To avoid naming collisions between the generated Mailable's builder function (e.g., `def notification(assigns)`) and the template function generated by `embed_templates` (e.g., `notification/1`), the HEEx file will be suffixed appropriately (e.g., `notification_template.html.heex`).

**Primary recommendation:** Use `Igniter.Mix.Task` to generate `lib/my_app/mail/<name>.ex` and `lib/my_app/mail/<name>/<name>_template.html.heex`, configuring `embed_templates` to bridge them.

## Architecture Patterns

### Pattern 1: Igniter Mix Task

**What:** Implementing an `Igniter.Mix.Task` to handle the `mix mailglass.gen.mailable` command.
**When to use:** Whenever creating a code generator that modifies or adds files to an Elixir project.
**Example:**
```elixir
# Source: Igniter Official Docs & Hexdocs

  use Igniter.Mix.Task

  @impl Igniter.Mix.Task
  def info(_argv, _composing_task) do
    %Igniter.Mix.Task.Info{
      example: "mix mailglass.gen.mailable Notification",
      positional: [{:mailable, optional: false}]
    }
  end

  @impl Igniter.Mix.Task
  def igniter(igniter) do
    name = igniter.args.positional.mailable
    # Resolve module name (e.g., MyApp.Mail.Notification)
    # Generate module file using Igniter.Project.Module.create_module
    # Generate HEEx file using Igniter.create_new_file
  end
end
```

### Pattern 2: Co-located HEEx Templates

**What:** Using `embed_templates "<directory>/*"` to compile external `.html.heex` files into functions on the Mailable module.
**When to use:** When scaffolding Mailables that require substantial HTML, keeping the Elixir file clean.
**Example:**
```elixir
defmodule MyApp.Mail.Notification do
  use Mailglass.Mailable, stream: :transactional
  import Phoenix.Component

  # Compiles `notification/notification_template.html.heex` to `notification_template/1`
  embed_templates "notification/*"

  def notification(assigns \\ %{}) do
    new()
    |> subject("New Notification")
    |> html_body(fn _ -> notification_template(assigns) end)
    |> Mailglass.Message.put_function(:notification)
  end
end
```

## Common Pitfalls

### Pitfall 1: Function Name Collisions
**What goes wrong:** The mailable builder function (e.g., `def welcome(...)`) conflicts with the generated template function.
**Why it happens:** `embed_templates "foo/*"` compiles `foo/welcome.html.heex` into `def welcome(assigns)`, causing an Arity-1 conflict.
**How to avoid:** Ensure the generated template file is named distinctively, such as `welcome_template.html.heex`, so it generates `welcome_template/1` while the builder is `welcome/1`.

### Pitfall 2: Module Namespace Resolution
**What goes wrong:** The generated mailable is placed in the root namespace (`MyApp.Notification`) instead of the conventional mail directory (`MyApp.Mail.Notification`).
**Why it happens:** The user runs `mix mailglass.gen.mailable Notification` and the generator blindly uses that as the full module name.
**How to avoid:** In the Igniter task, inspect the provided name. If it lacks a `.Mail.` prefix, explicitly prepend the application module name and `.Mail.` before creating the module.
