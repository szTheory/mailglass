## Milestone Summary

### Key Accomplishments

- Added first-party Resend webhook verification and normalization, including raw-body preservation for Svix validation.
- Added Mailgun webhook support with replay protection, runtime wiring, and installer/docs surface updates.
- Added SES SNS verification, certificate caching, control-plane handling, normalization, and runtime integration.
- Shipped `mailglass` and `mailglass_admin` to Hex as `0.3.2` after a disciplined Release Please patch-recovery flow.
- Closed the old SES ingest blocker with a `:ses`-aware ingest seam and plug-level end-to-end regression coverage.
- Closed v0.3 traceability gaps by refreshing config/installer parity and formalizing the SES-02 D-07 override.

### Key Decisions

- D-22: Webhook signature failures raise `Mailglass.SignatureError` with no recovery path for forged webhooks.
- D-23: SES certificate fetching stays behind an ETS-backed cache owner to avoid synchronous network fetches per webhook.
- D-24: Resend verification uses `CachingBodyReader` so Svix validation sees the original raw body.
- D-25: Mailgun replay handling remains a provider-boundary concern via `:ok | {:ok, :replay}`.
- D-32: Release tags are immutable; CI recovery happens by landing `fix:` commits and letting Release Please cut the next patch.

### Issues Resolved During Milestone

- Resend provider wiring and plug-level verification were completed and verified.
- Mailgun replay defense and normalized ingest were added end to end.
- SES Notification ingest no longer dies at the core ingest seam.
- Config validation and installer examples now include both `:ses` and `:resend`.
- The v0.3 requirements ledger now reflects the actual SES closure state.
