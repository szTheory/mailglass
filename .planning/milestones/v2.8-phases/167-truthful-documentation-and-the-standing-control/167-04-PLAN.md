Create `scripts/check_state_md_pr_refs.sh` following the repo's existing bash script conventions:
`#!/usr/bin/env bash`, `set -euo pipefail`, a leading usage comment block, and support for

Behavior:

1. Extract every `#NNN` reference from the target file. Strip references that occur inside a URL —
   match on a word boundary preceded by whitespace, `(`, or start-of-line, and explicitly exclude any
   `#NNN` immediately preceded by `/` or appearing after `github.com` on the same token. Deduplicate
   while **preserving first-appearance order**, so the output ordering is deterministic across runs.
2. If zero references are found, emit a zero-check result and exit 0. This is the empty-input
   contract — an empty reference set is a pass, not an error and not a cannot-check.
3. For each reference, resolve it against live GitHub. Try `gh pr view NNN --repo szTheory/mailglass
   --json state,title` first; if that fails, try `gh issue view NNN --repo szTheory/mailglass --json
   state,title`. Record one check per reference as a JSON object with the keys `name`, `status`,
   `message`, `details` — the same shape `mailglass.repo.hygiene` uses, so the outputs are
   interchangeable for a future consumer.
4. Classify each check three ways, per D-34 — a non-verdict must never be indistinguishable from a
   confirmed pass:
   - `pass` — the reference resolved, and STATE.md's prose within the same line does not describe it
     with a word contradicting its live state.
   - `blocked` — the reference resolved and STATE.md's line describes it as `open` while GitHub
     reports `CLOSED` or `MERGED`, or describes it as `closed`/`merged` while GitHub reports `OPEN`.
   - `cannot_check` — `gh` is not on `PATH`, `gh auth status` fails, the command errors, or the JSON
     response cannot be parsed by `jq`.
5. Aggregate with the same precedence as the analog: any `cannot_check` → overall `cannot_check`;
   else any `blocked` → overall `blocked`; else `pass`.
6. Exit `0` on pass, `2` on `cannot_check`, `1` on `blocked`. The distinct `2` is mandatory — an
   unobservable control that exits 0 is a permanent false green.
7. `--format json` emits the aggregate object (`status`, `generated_at` as an ISO-8601 UTC timestamp,
   `target`, `checks`) via `jq`; `--format text` emits one line per check prefixed by the external
   status string, rendering `cannot_check` as `cannot-check`.

Make the script executable (`chmod +x`). Document it in its own usage block only — do NOT add a
GitHub Actions workflow, a cron entry, or an entry in `.github/scheduled-controls.json`. Record in
the SUMMARY that this is a human/dispatch-invokable audit rather than a registered control, and why
(the alert budget; see this plan's execution preamble).

of `gh` → expect 2.
