## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| GitHub REST API → `proposal-discovery` shell body | untrusted PR metadata crosses into a bash step | `number`, `headRefOid`, `baseRefOid` (attacker-influencable strings) |
| `workflow_dispatch` input `candidate_digest` → step `if:` gating | a trigger-supplied input selects between the proposal path and the protected, PAT-backed release path | release-path selector (privilege-bearing) |
| `secrets.GITHUB_TOKEN` → step `env:` | credential exposure surface, evaluated per step | repo-scoped token |
| `release-proposal-control-result.json` → `scheduled_control_evidence.sh` and human reviewers | a control verdict is consumed downstream as a release-readiness signal | `status` / `reason` verdict pair |
| `.planning/REQUIREMENTS.md` → milestone auditors and release reviewers | requirement prose is read as the acceptance contract for a release-authorization control | `*Accept:*` clauses, checkbox state |
| harvest document → a future `/gsd-verify-work` or milestone audit | an observation slot is read as evidence that a fail-closed control was proven in production | post-merge observation slots |
