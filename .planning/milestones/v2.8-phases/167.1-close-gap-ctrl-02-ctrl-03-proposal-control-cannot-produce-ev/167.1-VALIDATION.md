**Harness note.** `test/scripts/release_trigger_recovery_test.exs` extracts each named workflow step's
literal `run: |` body (`extract_step_block!/2` → `proposal_result_script/1`) and executes it under
`bash` against fixture `gh`/`git` shims (`with_idle_schedule_fixture/3`). This is the only pre-merge
proxy for behavior that is otherwise observable only in a live Actions run. Do **not** build a parallel
harness — it would drift from the real file the moment either changes.

**Correction to `167.1-RESEARCH.md`:** `with_fake_gh/3` cannot host these tests. It is preflight-only;
its fake `gh` answers only `api:`/`pr:` queries and its env map lacks `FAKE_DISCOVERY`, `RUNNER_TEMP`,
`EVENT_NAME` and `COMMAND_LOG`, so the discovery/writer/gate bodies die under `set -u`. The correct host
is `with_idle_schedule_fixture/3`, extended with a `should_run` axis (Wave 0, Plan 01 Task 1).

**Baseline.** Zero failures (core 2182 / admin 510 / inbound 460 under `--seed 0`). No task may excuse
a failure as pre-existing.
