<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mail sender config -> unsubscribe service | Endpoint, host, mount path, redirect, and secret rotation settings cross from adopter config into signed-token generation |
| Untrusted token -> verification | Browser and mailbox-provider requests present attacker-controlled token strings to the verifier |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Spoofing | `Mailglass.Compliance.Unsubscribe` | mitigate | Verify with Phoenix.Token HMAC using current endpoint first, then explicitly iterate configured previous raw secrets only |
| T-11-02 | Tampering | `unsubscribe_url/2` | mitigate | Reject overlong URLs before they reach header injection, keeping RFC 5322 line-length failures out of outbound delivery |
| T-11-03 | Elevation of Privilege | config access | mitigate | Centralize compile-time/runtime config access in `Mailglass.Config` so new modules do not bypass repo security rules with ad hoc compile_env usage |
</threat_model>
