## Grounded implementation choice

The current `Operator.Mount.on_mount/4` already owns normalized success handling and `deny/4` (host `details[:to]`/`:message`, configured `:unauthorized_path`, and reason-specific defaults). Both LiveViews are router-mounted in that operator live_session. Install a `:handle_params` lifecycle hook there so the gate executes before `TenantSelector`, provider-option queries, subscriptions and collection/detail reads, without duplicating authorization in the two LiveViews.

Local pinned LiveView sources confirm that `attach_hook/4` supports `:handle_params` and that `put_private/3` exists in both admin 1.2.13 and demo 1.1.33. Keep captured mount options/session in the server-side hook closure; keep only the last approved tenant parameter key in a namespaced socket private entry. Use the current arrival context policy: `actor: Auth.session_actor(session)`, plus incoming `params`, captured `session`, and current `socket`. This gives the host the actor source it would receive on a fresh arrival, while successful normalized results update the socket for later actions.

Treat parameter absence distinctly from a present value, including a blank value. Initialize the approved key from the exact initial params after the mount grant; unchanged incoming tenant keys skip another call. A changed key is remembered only after a new grant. This preserves callback timing for ordinary filter/selection patches and checks canonicalization or explicit Account clearing when they change the parameter.
