# Phase 176 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope and source locks

Locked by `176-CONTEXT.md` (D-01..D-32) and not re-opened here: reuse of form → `push_patch` → `handle_params` → synchronous read; `phx-debounce="300"` on search only; no hidden submit button; history policy; server-held Account on commits; separate draft/committed state; stale-vs-error read rule; Inbound address rules (D-17..D-23); Raw provider source card structure (D-24..D-27).

This spec adds only what CONTEXT left to the UI layer: exact layout after Apply is removed, exact microcopy, token/size/spacing/colour use, state coverage, and machine-checkable acceptance. It adds no design system, no dependency, no new icon, no new colour, no new type size, and no new spacing token. Out of scope and not specified: custom date ranges, async reads, widening the `mailglass_inbound` list projection, IDNA/punycode display, unmasking routing diagnostics (matcher expected/actual, subject masking in the trace).

Surfaces touched (all existing, production components): `MailglassAdmin.Operator.FiltersForm` + Deliveries filter `<.form>` in `operator_live.ex`; `MailglassAdmin.Inbound.FiltersForm` + Inbound filter `<.form>` in `inbound_live.ex`; `Operator.DeliveriesList` / `Inbound.RecordsList` read-state panels; `Components.collection_header`, `Components.message_identity`; `Inbound.DetailHeader`; `Inbound.QuickView` (recipient label only); `Inbound.EvidenceCard`.

## Layout and interaction contract

### Filter bar (Deliveries and Inbound — identical behaviour)

1. **No Apply button.** Delete the `type="submit"` button and its `phx-disable-with`. No hidden submit button either (D-03). Visible controls: Search, Time window, Latest recorded event / Mailbox outcome, Provider, and a single "Clear filters" button.
2. **Layout.** Fields stay in the existing `filter_section compact` grid (1 col <640px, 2 col `sm`, 4 col `xl` for Deliveries; Inbound keeps its existing column count). "Clear filters" sits in the existing trailing auto column at `xl` and wraps under the fields below `xl`, left-aligned, `btn btn-ghost min-h-11 px-md`; remove Deliveries' `w-40`. It is always rendered and always enabled (a no-op when nothing is applied) so layout never shifts and Clear works during a pending debounce.
3. **Search input.** Existing `filter_field` text input with `phx-debounce="300"`, `autocomplete="off"`, `enterkeyhint="search"`, `placeholder="Subject or recipient"`, `data-committed={committed search}` and `phx-hook` for the Back/Forward value sync (D-10). Never `disabled`, never `readonly`, never wrapped in a loading state, never re-keyed (D-05). Selects have no debounce and commit on change. Enter commits immediately through form submit (implicit submission, D-03).
4. **Mobile.** Below `md` the existing "Filters" toggle opens the panel. Both toggles carry `aria-controls` and `aria-expanded` (Deliveries currently lacks them; match Inbound's pattern). Because filters now apply without a visible confirmation, the toggle label shows the applied count when >0: "Filters (2 applied)" in body weight 400 for the parenthetical. Zero applied shows "Filters". Target stays 44px.
5. **Hidden tenant input.** Recommended: delete `filters_tenant_id` from both forms; commits take `tenant_id` only from `socket.assigns.selected_tenant_id` (D-09). If retained for any reason it is ignored. Either way a tampered `tenant_id` in a change/submit payload must not change the Account (contract-tested).
6. **Results region stability.** While a commit is processing, keep prior rows and focus in place; no skeleton, spinner, dimming, or opacity transition on the results container (reads are synchronous; motion is not needed). Do not animate layout dimensions.
7. **History (user-visible contract of D-06/D-07).** One Back step per settled intent: a search edit session = 1 entry; each select change, Enter, Clear and pagination = 1 entry each; tenant canonicalization and reconnect recovery add none. Back/Forward restores the committed filters and, with focus in Search, the input text (hook syncs only when a history navigation is pending and `data-committed !== value`).
8. **Selection and page.** Any filter commit closes the Quick view/full detail (drops `delivery_id`/`inbound_id`/`full`) and returns to page 1. Pagination patches preserve current committed filters.

### Inbound contact display (INUX-05)

Full-detail header `<dl>` (replaces the single From cell; keep the surrounding `grid min-w-0 gap-md sm:grid-cols-2 lg:grid-cols-3 [&>div]:min-w-0 [&_dd]:[overflow-wrap:anywhere]`). Contact rows lead, then Provider, Received, Mailbox, Account (existing). Order and visibility:

| `dt` (label 14/700) | `dd` content | Present when |
|---------------------|--------------|--------------|
| From | address list | always |
| Reply-To | address list | non-empty only |
| To | address list (header `to`) | always |
| Cc | address list | non-empty only |
| Delivered to | envelope recipient + hint | always |

Bcc is not rendered. No Return-Path is invented.

- **Address row** (`<li>` inside `<ul role="list" class="space-y-sm">` within the `dd`): optional display name as plain 16px/400 text, then the addr-spec via `Components.copy_value` (label "From address" / "To address" / etc.). Display name is dropped when blank or equal to the address. Both are HEEx-escaped spans; no `raw`. Visual form: `Ada Lovelace` then `ada@example.com` (mono, copyable) on one wrapping line.
- **Spoof cue**: when the display name contains `@` and that address differs from the addr-spec, show the name, the real address, and a text-label line "Display name contains a different address." in `text-warning`. No icon added; text carries the meaning.
- **Multiple addresses**: all, in header order, one per line; exact duplicates inside one field collapsed (domain case-insensitive, local part case-sensitive). More than 5: first 5 plus native `<details>` whose `<summary>` reads "Show {N} more" (`mg-focus-ring min-h-11 content-center text-label font-bold text-secondary`, matching `technical_details` summary) containing the rest. No JS.
- **Delivered to** `dd`: the envelope recipient (copyable), then `<p class="mt-xs text-label text-secondary">SMTP envelope recipient (RCPT TO), used for routing.</p>`. Never labelled "To". "To" is only ever the header `to`.
- **Quick view** (`Inbound.QuickView` via `message_identity`): label "Delivered to" bound to `envelope_recipient`; no To/Cc (projection not widened). Operator Quick view/detail keep "To".
- **Missing/unparseable** (never a bare "—"): From "No From header"; To "No To header"; Delivered to "Not recorded by provider"; unparseable "Unparseable address" followed by the escaped original in mono. Missing text is `text-label text-secondary`.
- **Long/Unicode**: UTF-8 shown as received (no punycode); wrap anywhere; no truncation, ellipsis or line-clamp in detail; list-row truncation unchanged.
- **Masking**: From is no longer masked. Routing trace expected/actual, matcher diagnostics, and subject masking are unchanged and still masked. Telemetry metadata on reveal/detail stays `tenant_id`/`record_id`/`outcome` only.
