<objective>
Prove the UXF-10 return seam on one real path, then harden its validator and the one open-redirect-shaped sanitizer in scope.

Purpose: tracer-first. Health -> Preview -> Back to Health for a real, non-hard-coded Account, through every layer (Operator.Shell minting, PreviewLive validation, SurfaceNav rendering, host-owned arrival auth), before plan 177-03 threads the context through the remaining Preview builders and plan 177-06 rebuilds the nav into the scope group.
Output: `MailglassAdmin.Preview.ReturnContext`, minting in `Operator.Shell`, Back link in `SurfaceNav`, index-redirect threading in `PreviewLive`, ThemeController segment-boundary fix, unit + connected + browser proof.

Orchestrator decisions recorded here (rationale, CLAUDE.md Decision Policy):
- Param names stay `return_surface` / `return_tenant_id` (CONTEXT discretion): no clash found with any existing Preview or Operator param (`width`, `frame`, `theme`, `tenant_id`, `view`, filter keys).
- A3: minting is skipped when `preview_path` is not a local absolute path (RETURN-DESTINATION §2.2 recommendation). Reversible; a cross-origin Preview host keeps working, it just gets no Back link.
- A2: the sanitizer also rejects `.`/`..` and `%2e` segments. Same-origin only, low severity either way; browsers normalise dot segments out of the mount, so rejecting them removes a confusion vector at no cost.
- The Back link label lives in `ReturnContext.back_label/1` (closed map), so no caller can interpolate user text into it.
- Bundle ownership: this plan uses only utilities already in the committed `priv/static/app.css` (verify with `grep -c` before relying on a class); it never stages `priv/static/app.css`. The operator-browser script rebuilds the bundle, so every browser run is wrapped in the clean-before / restore-after guard. Plan 177-04 is the first plan that commits a rebuilt bundle.
- Zero owner UAT (D-52): every check is automated.
- Scope (revision W8): the browser tracer spec stays in this plan. It is the only real-browser proof that the plain-href Back link crosses the live_session boundary and that Browser Back returns to Preview (D-04, D-20). Moving it to a later plan would leave the tracer without its end-to-end verify, so the plan keeps it. Per-task verifies stay under the 60s budget by running `operator_live_test.exs` with `--only phase177` only.
- File count (revision W-9): 11 files in `files_modified`, deliberately not split. A tracer must be end to end, so minting (`shell.ex`), validation (`return_context.ex`, `preview_live.ex`), rendering (`surface_nav.ex`), the sanitizer and their connected and browser proofs land in this one plan.
- Browser budget (revision W-4): browser per-task verifies run in the advisory Playwright lane and pay a Tailwind build plus webServer boot, so their budget is about 180s cold, not the 60s ExUnit budget (177-VALIDATION.md). Task 1's browser verify is the first in the phase; its measured cold wall-clock time is recorded in the SUMMARY.
</objective>
