# Phase 173.1: Code Review Report

**Depth:** standard. No blockers. The requested focus areas were traced and `complete_release!/3` is sound.

## Summary

`complete_release!/3` cannot clobber another test's shared owner. It only writes `:manual` when the pool names this release's own owner, and `stop_owner/1` has already stopped that owner. Shared mode is process-global, and `guard_shared_checkout_from_async!` forbids concurrent async use. A late `:DOWN` from the old proxy is ref-keyed in `unshare/2` (`deps/db_connection/.../manager.ex:241`), so it cannot unshare a later owner. The probe-to-write window is therefore not exploitable in the intended usage.

The evidence checkpoint classifies Playwright statuses correctly. The JSON reporter's `status` is `expected|unexpected|flaky|skipped`, and unknown or undefined values count as `unexpected`. The remaining issues are weaker guards, not wrong results.

## Warnings

### WR-01: Contract test scan misses non-literal and piped call sites, so it can go partly vacuous

**File:** `mailglass_admin/test/mailglass_admin/auth_actions_contract_test.exs:28`
**Issue:** `@call_site` only matches `Auth.authorize(<arg>, :literal_atom`.
- `adapter |> Auth.authorize(:x, ctx)` is not matched.
- `Auth.authorize(adapter, action, ctx)` with a variable action is not matched.
- A different alias is not matched.
- `[^,]+` also spans newlines and nested commas (`Auth.authorize(f(a, b), :x)` mis-parses).

The "scan finds call sites" test asserts equality with `@known_actions`, but a new action added through any of these shapes would never show up. The same blind spot applies to the demo-grants and docs tests, because both iterate `called_actions()`.

**Fix:** Add a sanity count that fails when the scan and a looser grep disagree. For example, count the occurrences of `Auth.authorize(` (excluding `def`) and assert they equal the matched call sites. Or assert that every `authorize(` occurrence outside `auth.ex` is matched.

### WR-02: `String.to_existing_atom/1` makes a genuinely new action fail with an opaque `ArgumentError`

**File:** `mailglass_admin/test/mailglass_admin/auth_actions_contract_test.exs:48`
**Issue:** The atom for a new library action usually does not exist yet, because `mix test` loads modules lazily. The test then raises `ArgumentError` instead of reaching the intended message ("expected #{@known_actions}"). It still fails, but the failure does not explain what to update. This undermines the test's stated purpose, which is to force a deliberate update.

**Fix:** Keep the names as strings and compare against `Enum.map(@known_actions, &Atom.to_string/1)`. Or rescue and report the unknown name.

### WR-03: `sandbox_ownership_test` depends on private APIs and internal state shape

**File:** `test/mailglass/test_support/sandbox_ownership_test.exs:645-675`
**Issue:**
- `ExUnit.OnExitHandler.register/1` and `run/2` are `@moduledoc false` internals. Their arity or semantics can change on an Elixir upgrade, and the repo pins to 1.18.
- `owner_proxy!/1` pattern-matches `:sys.get_state(manager).checkouts[owner] == {:owner, ref, proxy}`, which is a `db_connection` private struct.
- If either internal changes, the test fails with a `MatchError` or `FunctionClauseError` that does not point at the cause.

**Fix:** Add a comment pinning the tested versions. Better, make `owner_proxy!` raise a descriptive message on mismatch instead of a bare match.

### WR-04: Outbound replay e2e baseline count can be taken before the timeline is populated

**File:** `reference/demo_app/assets/e2e/outbound-replay.spec.js:42-45`
**Issue:** `before = await succeeded.count()` is read immediately after `operator-detail-header` becomes visible. `count()` does not auto-wait. If the timeline hydrates after the header, `before` can undercount (0 where the real count is higher). The final `toHaveCount(before + 1)` can then never be satisfied, so the test hangs until timeout. The seed may also already contain a completed audit row for this delivery, which makes the test depend on seed content.

**Fix:** Assert the timeline container is visible, or wait for a known seeded event row, before counting. Alternatively, assert on a delta computed after the modal closes, or use `expect.poll`.

## Info

### IN-01: Checkpoint records `test_outcomes` but never gates on them

**File:** `reference/demo_app/assets/scripts/check-demo-browser-evidence.cjs:316`
**Issue:** A run with unexpected or flaky tests outside the pinned titles still writes a checkpoint. `collectTests` is also keyed by title (`outcomes` Map, lines ~170-186), so duplicate titles across projects overwrite each other, which is pre-existing. The `"passed"` to `"expected"` mapping at line 94 is dead for JSON reporter output, which uses `status`.
**Fix:** Decide explicitly whether `counts.unexpected > 0` should fail the checkpoint, and document the choice. Optionally drop the unreachable `"passed"` branch.

### IN-02: `Code.require_file` of the demo adapter in an async test

**File:** `mailglass_admin/test/mailglass_admin/auth_actions_contract_test.exs:35-39`
**Issue:** The demo module is compiled into the test VM and left loaded. The `ensure_loaded?` guard prevents redefinition warnings, but another async test that compiles the same module concurrently could race. The test also never asserts that an unknown action is denied, so the "deny by default" catch-all the moduledoc relies on is untested.
**Fix:** Add `assert {:error, _, _} = mod.authorize(:bogus, ctx)` to the demo test.
