## Color

Use theme semantic tokens. The proportions describe visual emphasis, not fixed element counts. For this evidence/documentation phase, existing product surfaces retain their established theme treatment.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Light `#F8FBFD` (Paper); dark `#0D1B2A` (Ink) | Page ground and primary work surface |
| Secondary (30%) | Light `#FFFFFF`; dark `#152538` | Raised surfaces, grouped panels, cards, menus, dialogs |
| Accent (10%) | Light `#277B96` (Glass); dark `#A6EAF2` (Ice) | Existing primary emphasis and focus only |
| Destructive | Light `#B42318`; dark `#E29089` | Destructive actions and their explicit error state only |

Accent reserved for: selected-row edge, primary CTA, active navigation/timeline cue, and keyboard-focus emphasis. Keep ordinary borders/surfaces neutral and flat. Status uses the existing semantic success, warning, error, and info roles plus text/icon labels; never rely on color alone. Do not introduce a visual treatment for evidence that suggests verification beyond what its source proves.

## Copywriting Contract

This is maintainer-facing guidance, not a new end-user flow. Use Mailglass's plain, exact voice. Keep browser-rendered email preview evidence distinct from delivered email-client evidence, and label historical screenshots/scores as historical.

| Element | Copy |
|---------|------|
| Primary CTA | `Open feedback preview` (walkthrough link or documented command; no new app CTA) |
| Empty state heading | `No current captures for this candidate` |
| Empty state body | `Run the focused evidence command for this candidate to create current captures.` Never present an older capture as current. |
| Error state | `Preview is not available. Check the documented start command and candidate source, then try again.` |
| Destructive confirmation | None added. Evidence cleanup removes only resources created by that evidence run; preserve the retained feedback preview and unrelated services. |

Evidence descriptions identify candidate revision and dirty-tree state when applicable, route, synthetic scenario/fixture, theme, viewport, interaction/adverse state, browser, before/after relation, capture path/hash, and relevant source/build/served asset identity. State browser, email-client, and historical-score limits explicitly. Do not retain real recipient or message data in evidence artifacts.
