<objective>
Make the two Core Full Suite job names distinguishable at runtime and at parse time, and record the
advisory-matrix lanes in the registry and in `MAINTAINING.md` as a third, disjoint classification axis.

The rename is not cosmetics. Verified live across three event types: on a `push` run all four legs report
distinct, fully-interpolated, suffix-free names; on a `pull_request` run the 1.19 job collapses to a single
`skipped` entry carrying the **literal uninterpolated template**, which is byte-identical to the 1.18 job's
declared name; and `CIYaml.job_names/1` collapses the two identical templates to one entry. So exact-equality
matching is already safe on the gate's own path — but any registry-versus-YAML set-equality test would claim
four-leg coverage while proving two, and on a pull-request run a skipped job reports a string identical to
the gating job's declared name.

This plan lands **decoupled from gating**. It is independently valuable — it fixes the declared-name
collision so the drift tests can be honest — and it is safe without any change to `gate-ci-green`.

Purpose: HARNESS-04 needs a registry that can name the two gating legs unambiguously before the gate is
written.
Output: a runtime-name parser, a third registry axis, two renamed jobs, a new `MAINTAINING.md` section, and
drift assertions binding all three together.
</objective>
