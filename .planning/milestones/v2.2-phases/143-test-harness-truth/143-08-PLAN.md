<objective>
Add the prevention half of the two-layer recurrence guard: a custom Credo check that bans raw
`Ecto.Adapters.SQL.Sandbox` ownership calls under `test/` outside the sanctioned door.

Detection (the formatter) names a leak the day it happens. Prevention (this check) stops the pattern being
re-typed at all. Neither substitutes for the other: a formatter cannot stop the fifteenth file from
hand-rolling an acquire/release pair, and a lint rule cannot see a leak that arises from a raise between two
correctly-written statements.

This is fill-in-the-blanks work. `credo_checks/no_raw_swoosh_send_in_lib.ex` is a structural twin — the only
one of the twenty existing checks that walks AST for a forbidden call on a specific external module, with
alias resolution and a path-prefix filter. The one genuine adaptation is four-segment alias resolution for
`Ecto.Adapters.SQL.Sandbox` where the analog resolves a two-segment `Swoosh.Mailer`.

Purpose: SEED-007's Definition of Done #3 — the pattern must not be re-typable.
Output: the check, its `.credo.exs` entry, its unit test, its integration-test entry, and a recorded proof
that `mix credo --strict` actually reaches the files the check claims to cover.
</objective>

call, and record this decision in a comment on the alias-collection function so a future reader does not
