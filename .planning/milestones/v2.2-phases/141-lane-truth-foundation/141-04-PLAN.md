<objective>
Give every `ci.yml` job a named classification in one authoritative Elixir registry, and make
`gate-ci-green` read that same classification instead of inferring it from a naming convention — with
the two bound together by set-equality assertions in the same commit train.

Purpose: today five registries disagree, and the largest bucket is not a bucket at all — 14 of 23
`ci.yml` jobs are recognized by neither `ci_green.needs` nor `gate-ci-green`'s advisory matcher, so they
block a Hex publish when red by pure fall-through. That tier is undocumented, unnamed, and grows every
time a job is added. This plan names it, enumerates it, and binds the Elixir and JS copies with a test
that fails on drift.

Output: three new classification attributes plus four accessors on `Mailglass.CILanes`, a rewritten
`gate-ci-green` classification step, and four set-equality assertions binding them.

**Decisions implemented here:** D-01 (`Mailglass.CILanes` is the single authoritative registry; the JS
arrays are verified against it, not maintained independently) · D-02 (the classification becomes three
named gating buckets, with `publish_gating_lanes/0` alongside `required_lanes/0` and `advisory_lanes/0`,
so today's effective publish posture is preserved byte-for-byte — plus the fourth `structural` bucket
taken under CONTEXT.md's discretion) · D-04 (delete the `/ Advisory \(/` convention regex;
`gate-ci-green` enumerates every set explicitly instead) · D-09 (the two jobs produced by plan 141-03's
`credo_strict` split are placed in the publish-gating bucket here; neither becomes merge-gating) ·
D-03 (the requirement text amended in plan 141-02 describes exactly the model landed here).
</objective>

## Decisions recorded here (never made by omission)

Per `.planning/research/v2.2/PITFALLS.md:488-494` and CONTEXT.md `<specifics>`, these choices are stated
rather than left implicit:

1. **Prefix matching is KEPT for advisory / publish-gating / structural; exact equality is KEPT for
   required.** D-04's *intent* — delete the naming-convention matcher and enumerate every set explicitly
   — is fully honored. Its natural literal reading (switch everything to `===`) is **not**, because
   RESEARCH.md **F1** proved with two live API job lists that GitHub appends matrix values to a matrix
   job's explicit `name:` at runtime: `Dialyzer (Elixir 1.18 / OTP 27)` reports as
   `Dialyzer (Elixir 1.18 / OTP 27) (1.18, 27)`, and `Operator Browser Gate` / `Preview Capture Advisory`
   gain ` (22)`. Unifying on exact equality would drop two advisory lanes into the publish-blocking tier,
   so a red browser gate would block a Hex publish. This is invisible from the YAML — the suffix does not
   exist there — which is exactly why it must be written down and machine-enforced, not merely commented.

2. **Every array holds FULL display names, not today's short prefixes.** `ADVISORY_LANES` today holds
   `'Operator Browser Gate'` and `'Demo Browser Evidence'`. Using full names is strictly more precise,
   still prefix-matches the runtime suffix, and makes the JS arrays *string-identical* to the Elixir
   registry — which is what reduces the drift test to four trivial set-equality assertions.

3. **`gate-ci-green` WARNS on unclassified-but-green and FAILS on unclassified-but-red.** Failing on
   green-but-unclassified would be stronger, but it is a real posture change and a foot-gun at release
   time. D-02 requires today's publish posture preserved byte-for-byte. The **hard failure lives in the
   meta-test** (plan 141-05), which runs on the PR that *adds* the lane — the correct place and time.
   Criterion 2's "no job can silently sit in neither" is satisfied by making it impossible to land an
   unclassified lane, not by surprising a release.
