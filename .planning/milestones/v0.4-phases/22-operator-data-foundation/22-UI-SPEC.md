# Phase 22 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Phoenix LiveView + vendored daisyUI atoms/patterns (source: `mailglass_admin/mix.exs`, `mailglass_admin/assets/css/app.css`) |
| Icon library | Heroicons via vendored Tailwind plugin (source: `mailglass_admin/assets/vendor/heroicons.js`, `mailglass_admin/lib/mailglass_admin/components.ex`) |
| Font | Inter for UI/body, Inter Tight for headings, IBM Plex Mono for ledger/meta text (source: `mailglass_admin/assets/css/app.css`) |

This phase extends the existing `mailglass_admin` design language. Do not introduce shadcn, React-only patterns, custom JS widgets, or a second token system. Registry safety is not applicable because this stack is Phoenix LiveView, not shadcn.

---

## Screen Contract

- Use a two-pane operator layout on desktop: a recent-deliveries list on the left and the selected delivery detail on the right.
- Collapse to a stacked flow on mobile: filters first, list second, selected delivery detail below the active row.
- Keep the existing flat visual language: bordered cards, `rounded-box`, no shadows, no bevels, no glassmorphism.
- Surface three data areas only in this phase: recent deliveries, delivery event timeline, suppression visibility/removability state.
- Do not render authentication prompts, replay actions, or suppression mutation controls in this phase. Reserve those entry points for later phases.
- On first load, the recent-deliveries list is the primary visual anchor. After a row is selected, the delivery detail header and event timeline become the primary focus.
- Visual priority after selection is fixed: `1.` selected delivery summary, `2.` event timeline, `3.` suppression state card.

---

## Component Inventory

- Filter bar: tenant-aware filters above the list. Use compact inputs/selects at `min-h-11` and keep filtering scoped to query primitives, not advanced rule builders.
- Deliveries list: timestamp, recipient or delivery target summary, provider, latest event summary, and tenant context in a dense but scannable row.
- Delivery row state: selected row gets the existing active treatment pattern, adapted from preview sidebar selection. Use accent border plus elevated background, not a filled accent block.
- Delivery detail header: delivery identifier, message/mailable context if available, provider, tenant, and a compact summary badge for current state.
- Event timeline: chronological vertical list with timestamp, event name, provider/source metadata, and any rejection/bounce reason shown inline.
- Suppression state card: one compact card in the detail pane showing suppression reason, scope, and reversibility state. If immutable, render it as a read-only status, not a disabled destructive control.
- Empty-state card: reuse the centered card pattern already used in preview, with one icon, one heading, and one explanatory sentence.
- Inline status badges: use semantic badge treatments for delivered/sent, deferred/warn, failed/error, and suppression immutability.

---

## Interaction Contract

- Primary interaction is row selection, not navigation to a separate full page.
- Persist selected delivery and active filters in the URL so refresh/back preserves operator context.
- Filters submit through standard LiveView events and should feel immediate, but not per-keystroke on long free-text inputs. Use explicit submit or debounced change where text search exists.
- Expanding a delivery should not remount the entire screen. Update the detail pane in place.
- Event timeline is read-only in this phase. No inline replay buttons, destructive confirmations, or editable suppression controls.
- Suppression reversibility must be communicated as state text:
  `Reversible in a later phase` for removables and `Immutable by policy` for non-removables.
- Loading states should use skeleton rows/cards or muted placeholder blocks, not spinners as the primary layout.
- Flash/toast usage should stay limited to transient fetch/system feedback, following the existing `Components.flash/1` pattern.

---

## Accessibility Contract

- Preserve existing minimum touch target behavior: `min-h-11` (44px) for list rows, buttons, segmented controls, and filter inputs.
- Use semantic table/list markup for the deliveries collection; do not fake tables with anonymous `div` grids when row scanning is the main task.
- Selected delivery row must expose selected state via `aria-current` or equivalent stateful semantics, not color alone.
- Timeline items must remain readable in DOM order from oldest to newest or newest to oldest, but the chosen order must match the visible order exactly. For this phase, use newest delivery event at top only if the chronology label clearly states that ordering; otherwise default to oldest-to-newest.
- Status feedback follows the current contract: polite live region for transient flash, explicit heading/body copy for blocking errors.

| Token | Value | Usage |

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 700 | 1.5 |
| Heading | 20px | 700 | 1.2 |

Weight contract is exactly `400` and `700` because those are the self-hosted weights already loaded in `mailglass_admin/assets/css/app.css`. Use IBM Plex Mono at `12px` or `14px` for delivery ids, timestamps, event payload snippets, and provider metadata.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Paper `#F8FBFD` in light theme / Ink `#0D1B2A` in dark theme | App background, main surfaces, detail pane base |
| Secondary (30%) | Mist `#EAF6FB` in light theme / Ink elevated `#152538` in dark theme | Sidebar/list pane, cards, filter bar, timeline container |
| Accent (10%) | Glass `#277B96` in light theme / Ice `#A6EAF2` in dark theme | Selected delivery border, active filter chip, active timeline marker, primary CTA only |
| Destructive | Error Crimson `#B42318` in light theme / `#D47368` in dark theme | Blocking errors and immutable/failed status semantics only; no destructive CTA in this phase |

Accent reserved for: selected delivery row border, the `Open delivery` CTA, applied filter pills, active timeline node, and keyboard/focus emphasis. Do not use accent as the default color for every badge, border, or row.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Open delivery |
| Empty state heading | No recent deliveries |
| Empty state body | No recent deliveries match these filters. Clear the filters or wait for the next send. |
| Error state | Delivery data could not be loaded. Refresh the page or adjust the filters, then try again. |
| Destructive confirmation | None in Phase 22. Suppression removals and replay actions are out of scope until later phases. |

Additional required copy:

- No delivery selected: `Select a delivery to inspect its event timeline and suppression state.`
- No timeline events: `No delivery events have been recorded for this item yet.`
- Suppression removable: `This suppression is reversible in a later phase.`
- Suppression immutable: `This suppression is immutable by policy.`

All copy must keep the existing mailglass voice: clear, exact, confident, warm, technical. Do not use vague error language such as `Something went wrong` or playful phrasing.

## Implementation Notes

- Reuse current admin primitives and classes where practical: `card`, `badge`, `btn`, `join`, `rounded-box`, `bg-base-*`, `text-secondary`, and existing toast semantics.
- Favor server-rendered LiveView updates over custom client state. This phase must work without adding a custom JS build pipeline.
- Delivery timeline visuals should use simple borders, dots, and spacing. Do not introduce charting libraries or animated timeline packages.
- Suppression state is informational in this phase. If a future action is unavailable, show explanatory copy instead of a disabled destructive button.
