<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin LiveView → core operator query modules | Operator-controlled filter params cross into backend query code |
| Core operator query modules → mailglass schemas | Read-only queries cross from UI-driven state into tenant-scoped delivery, event, and suppression data |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Information Disclosure | recent-deliveries query | mitigate | Require explicit tenant-aware filter inputs and backend tests proving foreign-tenant rows are excluded. |
| T-22-02 | Information Disclosure | event timeline query | mitigate | Query timeline rows from `Mailglass.Events.Event` scoped by tenant and `delivery_id`; test cross-tenant exclusion explicitly. |
| T-22-03 | Tampering / Authorization Drift | suppression projection | mitigate | Keep the module read-only and expose only visibility/reversibility state, not mutation helpers. |
| T-22-04 | Denial of Service | operator queries | mitigate | Keep filters compact and bounded (for example recent-limit/default ordering) rather than exposing unbounded full-table scans. |
</threat_model>
