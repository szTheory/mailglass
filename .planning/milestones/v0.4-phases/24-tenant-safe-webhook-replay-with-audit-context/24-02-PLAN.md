<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator-triggered replay command -> core replay execution | Sensitive operator actions cross from UI context into tenant-scoped side effects |
| Stored webhook payload -> provider normalization | Persisted payloads are reused as already-verified evidence, not re-verified raw bytes |
| Replay execution -> append-only audit ledger | Outcome facts must remain durable and tamper-resistant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-05 | Elevation of Privilege | replay command lookup | mitigate | Require `tenant_id` and `webhook_event_id`, scope lookup before any audit append or replay execution. |
| T-24-06 | Repudiation | replay outcomes | mitigate | Append explicit requested/succeeded/failed ledger rows with actor and target metadata. |
| T-24-07 | Integrity | replay semantics | mitigate | Reuse existing normalization/projector/idempotency machinery and return explicit no-op outcomes instead of pretending duplicate work succeeded. |
| T-24-08 | Information Disclosure | replay metadata | mitigate | Keep audit metadata to actor ids, tenant ids, webhook ids, provider ids, and outcome atoms; never store payload excerpts or recipient content. |
</threat_model>
