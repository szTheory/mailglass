<objective>
Fix a live correctness bug: the shipped Postgres migration dispatcher (`Mailglass.Migration.up()`, `@current_version 4`) creates `mailglass_deliveries` WITHOUT the `idempotency_key` / `status` / `last_error` columns and the deliveries idempotency partial unique index that the runtime (`delivery.ex:112-122`, `outbound.ex` upsert) requires. CI is green only because the internal TestRepo applies a standalone `priv/repo/migrations/00000000000002_*.exs` migration that adds those columns — a path adopters never run. A fresh adopter gets a table the runtime fails against.

This is a reproduce-first patch (RED → GREEN → reconcile). Ship version 1.10.2 is NOT cut here — versions are bumped by Release Please at release ceremony, not by hand (see Task 3 rationale).

Purpose: Converge the shipped adopter migration path and the internal TestRepo path onto a single source of truth so the bug cannot silently recur.
Output: A failing-then-passing adopter-path migration test, a new `v05.ex`, `@current_version` 4→5, and a reconciled TestRepo path.
</objective>
