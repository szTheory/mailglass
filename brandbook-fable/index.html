mailglass
brand book

Email, made visible. Mail you can see through.

mailglass is a Phoenix-native framework for composing, previewing, delivering, and observing email. This book is the brand system itself: the voice, the tokens, the type, the mark — every claim demonstrated on this page, in both themes, with nothing fetched from anywhere. The mark above is drawn from the live tokens; flip the theme and watch the whole book follow.

01

Orientation & Essence

mailglass brings structure and visibility to transactional email in Phoenix applications: typed mailables, component templates, previews, delivery records, normalized events, and suppression handling. The brand carries the same promise as the library — clarity you can verify. Glass is the metaphor: panes, preview surfaces, light passing through structure. Never frosted blur, never gloss, never literal broken glass.

The voice is a thoughtful maintainer's. The composition is a well-lit workbench: left-aligned, documentation-like, generous whitespace around exact content. Every section of this book ends in something you can use — a table, a CSS block, a rendered specimen.

The rules, up front

  • Assets are outlined paths only.

    No live text and no font dependencies inside any SVG. The wordmark renders identically on every OS and inside font-less image sandboxes.

  • Dark mode is demonstrated, not asserted.

    The toggle in the header re-skins every specimen on this page. A dark value no specimen renders does not exist.

  • Every contrast claim is computed.

    The matrix in section 05 is calculated from the live token values when the page loads, and recalculated when the theme flips. No ratio on this page is typed in by hand.

  • Flat color first; transparency carries meaning.

    Translucency appears only where it expresses layered visibility — a pane you can see through to something real beneath. It is never atmosphere. Gradients come nowhere near the identity.

  • No glassmorphism.

    No frosted blur, no transparency stacks, no lens flares — doubly tempting given the name, and banned for exactly that reason. Crisp first, glassy second.

  • No background plate behind the mark.

    The mark sits directly on its surface. The single documented exception is the inherently square social avatar.

  • This page asks the network for nothing.

    No webfonts, no scripts from elsewhere, no remote images. Open it from disk and it is complete.

02

Voice

mailglass speaks like a thoughtful maintainer: plain English, exact nouns, strong verbs, short sentences. Clear, exact, confident without being cocky, warm without being cute, modern without being trendy, technical without being intimidating.

Four principles

  • Clear first. Prefer the direct word over the clever one.
  • Explain, don't hype. Confident understatement beats inflation.
  • Calm under failure. Errors are specific and composed.
  • Generous with context. Copy helps the reader recover quickly.

Say this, not that

SayNotWhy
previewexperience the full rendering lifecycleThe direct word respects the reader's time.
provider-normalized eventsrevolutionary observabilityExplain what it is; never market-speak.
Delivery blocked: recipient is on the suppression listOops! Something went wrongErrors name the cause and stay composed.
This message was skipped because the recipient previously unsubscribedSuppressedOne extra clause saves the reader a search.
Render a real message before you send itBeautifully effortless email magicUtility with taste; no enterprise theater.

The seven domain nouns the copy is built on: Mailable (source-level definition), Message (rendered email), Delivery (per-recipient send record), Event (observed fact, past tense), InboundMessage (received email), Mailbox (inbound handler), Suppression (policy record blocking future sends). Dispatch is not delivery: dispatched means handed to the provider; delivered means the destination accepted it.

Typography

Three faces, three jobs: Inter Tight for display, Inter for UI and body, IBM Plex Mono for code and exact values.

An honest note about rendering: Inter is preinstalled on no major operating system, and this brand ships no font files and loads none from the network. Usage rules

  • Display size appears once per page. Headings step down without skipping levels.
  • Mono carries every exact value: hexes, sizes, tokens, module names, headers.

  • Letter-spacing tightens slightly at display sizes (−0.015em) and never spreads.

Every ratio below is computed from the live token values the moment this page loads, and recomputed when the theme flips — the table can never drift from the tokens, because it is read out of them. The math is WCAG 2.x relative luminance; verdicts use the normal-text thresholds (AA at 4.5, AAA at 7.0).

Logo System

The mark is the back of an envelope drawn entirely in light: a landscape pane, a lit fold descending from the top edge, and a round seal straddling the bottom edge. The envelope is never outlined — light does all the drawing. Every opening is a void in the path, so whatever sits behind the mark shows through; that transparency is the brand's one literal use of glass.

Minimum size and clear space

The full mark holds down to 24px; below that, use the favicon redraw. Lockups hold down to 20px of wordmark height. Clear space on every side is the height of the seal's visible half (one quarter of the mark's height) — give it room or give it the favicon.

Do
  • Use the light expression on Paper, Mist, white, and other light grounds.
  • Use the monochrome lockup or the dark expression on Ink and dark grounds.
  • Let the background show through the fold and the seal — the voids are the point.
  • Use logo-with-tagline.svg when the subtitle must appear; it is the only asset that carries it.
Don't
  • Never place the light-expression primary on a dark ground — the Ink pane vanishes.
  • Never add a background plate behind the mark; the square social avatars are the sole exception.
  • Never outline the envelope — light does the drawing.
  • Nothing may read as broken, severed, or fractured. Voids always read as light passing through.

Usage & Export Policy

The brand ships as text. Everything committed is reviewable in a diff: SVG, Markdown, JSON, CSS, HTML. Anything rasterized is generated locally, used where needed, and never committed.

CategoryWhatPolicy
CommittedSVG assets, tokens.json, tokens.css, this page, brand-book.md, README.mdText artifacts only — every change reads in review
Generated locallyPNG exports of the social card (1200×630) and avatars at platform sizes; .ico if a host demands oneProduce when a launch surface needs them; regenerate from the SVG sources at will
Never shipsBinaries, font files, rasters, screenshotsIf it can't be diffed, it doesn't belong in the folder

One trap worth naming twice: the social-card SVG is a template. Link-preview crawlers do not render SVG, so the published preview image is always a local PNG export of it — the SVG itself is never wired up as the page's preview image.

Fonts follow the same logic. Inter and IBM Plex Mono are the brand faces when installed; nothing here embeds or downloads them. The wordmark — the one place type may never fall back — is already outlined inside every asset.
